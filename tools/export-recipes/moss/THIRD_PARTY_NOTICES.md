# Third-party notices — MOSS-Image

Provenance record for the pre-release review (ADR 0065 stage 6) of this recipe directory and of
the distribution `karume-moss-image` it builds (`distribution.py`, `card.py`). **It is not a
license determination.**

This directory (`tools/export-recipes/moss/`) is repo-only: it is never published to PyPI and none
of it enters the `karume` wheel (ADR 0065 decision 1). Upstream-derived code lives next to the
recipe that needs it so its provenance travels with the code. The text tower and the tokenizer are
written by the `qwen3_5` recipe (`qwen3_5/export.py`, `qwen3_5/tokenizer.py`), whose only source
is this checkpoint's `text_encoder` and `tokenizer` folders (`qwen3_5/checkpoint.py` `SOURCES`);
that directory copies no upstream code, so its provenance is recorded here.

`Unverified` marks a field nobody has checked against the upstream revision actually used.
Checking license compatibility per revision is a review scheduled before release (ADR 0065
decision 7; the per-publication check of `docs/release-runbook.md` §1). A field that says
"Checked … on <date>" records a check against the pinned revision on that date; "reviewed by the
maintainer on <date>" records that the maintainer's human review of that check was completed on
that date.

## Upstream sources

- **Weights and pipeline code** —
  [OpenMOSS-Team/MOSS-Image-SFT](https://huggingface.co/OpenMOSS-Team/MOSS-Image-SFT),
  pinned in `sources.py` (`SOURCE`, with the SHA-256 of `pipeline_moss_image.py`). The DiT
  (`transformer`) is converted and redistributed in `karume-moss-image` (the graphs `dit_text`,
  `dit`, `dit_skip22`); the scheduler config supplies the shift of the manifest's
  `pipelineConfig`. The `pipeline_moss_image.py` file (`trust_remote_code` code) is imported after
  its SHA-256 is checked. The `text_encoder` (Qwen3.5) and `tokenizer` are run locally to produce
  the references' precomputed text embeddings (`text_embeds.py`, not distributed), and are
  converted and redistributed in `karume-moss-image` (the text tower as `text_encoder`, the
  tokenizer as the asset `tokenizer`).
- **Text encoder and tokenizer** — bundled in the same repository (`text_encoder/`,
  `tokenizer/`), but not MOSS's own: they are those of
  [Qwen/Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B) (`sources.py`
  `TEXT_ENCODER_ORIGIN`) — see the Qwen3.5 block below.
- **VAE** — bundled in the same repository (`vae/`), but not MOSS's own: it is the FLUX.2 VAE with
  the FLUX.2 small decoder. `sources.py --vae-origin` (`VAE_ORIGINS`) compares it tensor by tensor
  with its two origins — see the VAE block below. Only its decode path (the decoder,
  `post_quant_conv` and the latent BatchNorm statistics) is redistributed.
- **Model implementation** — `diffusers` (`DiffusionPipeline`,
  `FlowMatchEulerDiscreteScheduler`, `AutoencoderKLFlux2`) and `transformers`
  (`Qwen3_5Model`, `Qwen2Tokenizer`), pinned `diffusers==0.39.0` /
  `transformers==5.14.1`, imported only.
- **Adapted code** — short functions transcribed from upstream code, each under
  a "Third-party code notice" comment: `pipeline_ref.py` (`denormalize`,
  `unpatchify`), `reference.py` (`head`, and `cfg` — the CFG line of
  `MOSSImagePipeline.__call__`) and `dit_patch.py` (`MossDit.forward` and
  `MossDitText.forward` — `MOSSImageTransformer.forward` / `_TextProjection.forward`
  for a batch of one with the host-side steps moved out — and the `RopePair`
  branch of the patched `_rotate`) from `pipeline_moss_image.py`; `reference.py`
  (`euler` — the update line of `FlowMatchEulerDiscreteScheduler.step`) and
  `vae_patch.py` (`upsample_2d` — `Upsample2D.forward` with the nearest ×2 written
  as a repetition — and the three decoder graphs' `forward` — the statements of
  `AutoencoderKLFlux2._decode`, `Decoder.forward`, `UNetMidBlock2D.forward`,
  `UpDecoderBlock2D.forward` and `AttnProcessor2_0.__call__` split across them)
  from diffusers. `cfg` and `euler` are one-line formulas, listed here all the same
  so the inventory does not depend on a judgement of how short a copy may be.
- **Fixed prompts** — `prompts.py` quotes three prompt texts verbatim from the
  HF model card and the upstream user guide; the fourth (the negative) is the
  empty string.
