# Third-party notices — Gemma 4 (E2B / E4B / 12B / 26B A4B)

Skeleton for the pre-release provenance review (ADR 0065 stage 6). It records what this recipe
directory is known to derive from. **It is not a license determination.**

This directory (`tools/export-recipes/gemma4/`) is repo-only: it is never published to PyPI and
none of it enters the `karume` wheel (ADR 0065 decision 1). Upstream-derived code lives next to
the recipe that needs it so its provenance travels with the code.

`Unverified` marks a field nobody has checked against the upstream revision actually used.
Checking license compatibility per revision is a human review scheduled before release
(ADR 0065 decision 7); filling this table in _is_ that review, and this file only lays out the
questions it has to answer.

## Upstream sources

- **Weights** — `google/gemma-4-E2B-it` and `google/gemma-4-E4B-it` on Hugging Face
  (<https://huggingface.co/google/gemma-4-E2B-it>, <https://huggingface.co/google/gemma-4-E4B-it>),
  downloaded into `inputs/gemma4/gemma-4-E{2,4}B-it/`. Only the **text decoder** keys are read;
  the vision and audio towers are never loaded. They make the regular line, `karume-gemma4`.
- **q4_0 QAT weights (E2B / E4B)** — `google/gemma-4-E2B-it-qat-q4_0-unquantized` and
  `google/gemma-4-E4B-it-qat-q4_0-unquantized` on Hugging Face, Google's quantization-aware-trained
  checkpoints of the two `-it` models, read from the HF cache at the commits `sources.py` pins
  (`QAT_PINS`). Only the text decoder keys are read; its 4-bit grid is stored as is
  (`export_product_qat.py`). Their tokenizer files are not read: the tokenizer, the chat template and
  the generation defaults come from the `-it` repositories above. They make the q4_0 QAT line,
  `karume-gemma4-qat`, with 12B below.
- **12B weights** — `google/gemma-4-12B-it-qat-q4_0-unquantized` on Hugging Face
  (<https://huggingface.co/google/gemma-4-12B-it-qat-q4_0-unquantized>), Google's
  quantization-aware-trained checkpoint of `google/gemma-4-12B-it`, read from the HF cache at the
  commit `sources.py` pins. The text decoder keys are read and its 4-bit grid is stored as is
  (`export_unified.py`); the encoder-free vision embedder's keys are read and stored as their bf16
  values (`export_vision.py`). The audio embedder's are never read.
- **12B tokenizer, chat template and generation defaults** — `google/gemma-4-12B-it` on Hugging
  Face (<https://huggingface.co/google/gemma-4-12B-it>), read from the HF cache at the commit
  `sources.py` pins. Its weights are no longer read: the QAT repository above ships the
  `tokenizer.json` every Gemma 4 repository had before Google's glitch-token fixes (its other
  tokenizer files are byte-identical to 12B-it's), so the tokenizer comes from the base model. The
  image goldens also read its `processor_config.json`, and the distribution its image token budget.
- **26B A4B weights** — `google/gemma-4-26B-A4B-it-qat-q4_0-unquantized` on Hugging Face
  (<https://huggingface.co/google/gemma-4-26B-A4B-it-qat-q4_0-unquantized>), Google's
  quantization-aware-trained checkpoint of `google/gemma-4-26B-A4B-it` (two shards and their index),
  read from the HF cache at the commit `sources.py` pins. Only the text decoder keys are read and
  its 4-bit grid is stored as is, the routed experts' steps as f16 (`export_moe.py`); the vision
  tower and its embedder are never read.
- **26B A4B tokenizer, chat template and generation defaults** — `google/gemma-4-26B-A4B-it` on
  Hugging Face (<https://huggingface.co/google/gemma-4-26B-A4B-it>), read from the HF cache at the
  commit `sources.py` pins, as 12B's come from 12B-it. Its weights are not read.
- **MTP drafter weights** — `google/gemma-4-E2B-it-assistant` on Hugging Face
  (<https://huggingface.co/google/gemma-4-E2B-it-assistant>), loaded from the HF cache by
  `export_drafter.py` and re-distributed as `e2b/drafter/` of `karume-gemma4`.
- **q4_0 QAT MTP drafter weights** — `google/gemma-4-E2B-it-qat-q4_0-unquantized-assistant`,
  `google/gemma-4-E4B-it-qat-q4_0-unquantized-assistant` and
  `google/gemma-4-12B-it-qat-q4_0-unquantized-assistant` on Hugging Face, loaded from the HF cache at
  the commits `sources.py` pins (`QAT_DRAFTER_PINS`) by `export_drafter_qat.py` and re-distributed
  as `<model>/drafter/` of `karume-gemma4-qat`. Their tokenizer files are not read.
- **Model implementation** — the `transformers` package (`Gemma4ForCausalLM`), added ad hoc with
  `uv run --with 'transformers==5.14.1'`. Nothing is monkeypatched and nothing is copied: the
  recipe renames the text keys onto the text-only class and exports through `torch.export`.
- **Tokenizer** — read verbatim at run time from the checkpoint's `tokenizer.json` and compiled
  into a Karume tokenizer asset (`tokenizer.py`), one per model; the golden prompts are this
  repository's own text. E2B's and E4B's tokenizer files are `google/gemma-4-E2B-it` at
  `4adf15748de9e1a0097b6274cee9c15836c41c37` and `google/gemma-4-E4B-it` at
  `4ecc2ba63bcac23ba4a767fc87025b1450f84c9c` (fetched 2026-11-04 into `inputs/gemma4/`; also the
  tokenizer pins of the q4_0 and mobile QAT lines, `sources.REGULAR_TOKENIZER_PINS`): Google's
  glitch-token fixes of 2026-11-03, which change `tokenizer.json` alone (E2B drops 267 BPE merges
  and renames id 249788, E4B drops 253). The README front matter at both commits is unchanged
  (`license: apache-2.0`, not gated — HF API, 2026-11-04).

NOTE: this recipe **does** have two distribution seats (`distribution.py` / `card.py` →
`models/karume-gemma4`, the regular line, and `models/karume-gemma4-qat`, the q4_0 QAT line). The
verbatim Apache 2.0 text is vendored once for every family that
needs it as `../_shared/licenses/apache_license_2_0.txt` and shipped as each distribution's
`LICENSE.md`, alongside a `NOTICE.md` that lists the modifications required by Apache 2.0 §4(b).
