## Active pitfalls

- Low bit widths are **not a reason for speed**. Decode on the RTX 3080 Ti (Chrome, 2026-09-19) is not bandwidth-bound (measured bandwidth utilisation 11.5 / 25.5% — recomputed from the table's columns, 12.1 / 27.5%; the B570 (the development machine before the swap) and the M2 are unmeasured. [ADR 0108](../docs/decisions/0108-container-format.md) addendum 7), so what a low-bit codec trims is the side that is not the bottleneck. What it helps is **memory**, and its execution premise is packed int8 activations ([ADR 0105](../docs/decisions/0105-packed-static-quantize-activations.md)). To claim speed, measure that first ([ADR 0108](../docs/decisions/0108-container-format.md) decision 15).
- The real assets' i2 is **not ternary**. In gemma4-qat E2B's I2 tensors `q = −2` appears in 5.8–7.4%, so reading i2 assets as ternary turns around 6% of all elements into other values. Ternary has the same packing and restoration formula as i2 and needs 0 added runtime lines, but **it is declared as a separately named codec** (so that assets can be told apart — [ADR 0108](../docs/decisions/0108-container-format.md) decision 13).
- sha256 reference values are **rows per environment**, not constants ([ADR 0106](../docs/decisions/0106-device-keyed-references.md)). A machine without rows gets an explicit SKIP + a red reference guard, so create the rows with `KARUME_REFERENCE=write`. Do not re-record other environments' rows. Turning them into tolerances is forbidden.
- Wan2.1 resolves to the **practical preset** `f16+dit8-a8-attn8-s16` when `quant` is omitted (since 2026-10-04). The existing sha rows, bands and case ids are values of the `f16` preset, and the tests keep them by stating the preset explicitly in every case (omission is stopped by the type). When adding rows, state the preset explicitly too ([ADR 0120 addendum 2026-10-04](../docs/decisions/0120-wan-dit-w8a8-seat.md)).
- The golden's second stage (WGSL specification band; `OUTPUT_TOLERANCE` in `e2e_golden_test.ts`) is also **rows per environment key**; on a machine without a row the second stage does not exist at all, and the case goes red on the first stage, Karume's own criterion, alone ([ADR 0106 addendum](../docs/decisions/0106-device-keyed-references.md)). Rows are added only under the key of the machine that measured them, never widened to all machines.
- `measurements` in `results.json` is **a record not used for decisions** and holds no derived values such as ratios to the band (deriving them is the job of `tools/verify-diff`). When moving a band after reading this field, write the grounds for loosening from the relevant section of the specification and the measured values.
- Input-caused failures (the request itself cannot be accepted) are thrown as `ModelInputError`. Misspellings (model / quant / sampler names), call-order violations (disposed, double generation), asset mismatches and broken internal premises **stay plain `Error`** and are not mixed into this type ([ADR 0107](../docs/decisions/0107-model-input-error.md) decisions 2 / 3).
- Running a lane alone does not run the three all-SKIP guards (`gpu_gate` / `assets_gate` / `distribution_gate`) (they exist only in core). Do not treat a green lane as meaning the same as a green full verify. Only the reference guard is bundled with each series' e2e.
- Deno does not convert timestamp-query values to ns (they stay wgpu's raw ticks). The B570's `timestampPeriod` is 52.0833 ns, so the breakdown of `lastRunTiming` / `--diagnostics` is ×52 too small (the RTX 3080 Ti measured a period of 1 ns on 2026-10-06 and has a row in `TIMESTAMP_UNIT_NS`; Chrome converts — [known-issues](../docs/known-issues.md)).
- On Deno, by the time a `GPUOutOfMemoryError` is caught by an errorScope, the device may already be dead. The only survivable OOMs are those of `createBuffer` / `createTexture`; OOMs in `queue.writeBuffer` staging, submit and bind group creation make wgpu lose the device, and `device.lost` does not resolve until the next call that passes validation. Do not build any new design that "frees and retries after hitting OOM" — measure the free space first with `fitsHeadroom` (the 97% section of [limitations](../docs/limitations.md); [ADR 0112 addendum](../docs/decisions/0112-anima-transformer-residency.md)).
- CPU f32 changes the last bit depending on the offset of the weight's address from a 64-byte boundary (MKL behaviour; f64 unchanged). When an f32 golden splits, do not loosen the check; re-record it in that environment. A synthetic random text context amplifies the difference between f32 and f64 in Wan2.2 5B, so goldens and contexts used for decisions use real prompt embeddings ([ADR 0121 addenda "stage 0 results" / "stage 1 results"](../docs/decisions/0121-wan22-ti2v-5b.md)).
- Isolate whole-verify failures with the logs and standalone runs of the failing files. Do not conclude that it is VRAM pressure.
  For the reproduction where the fixed repo/revision of a fake HF URL and port reuse pick up an old manifest, see [known-issues](../docs/known-issues.md). Do not delete the cache without permission and treat that as a pass.
- Device loss from diagnostic runs on Metal and per-GPU low-bit differences are recorded in [known-issues](../docs/known-issues.md) and [limitations](../docs/limitations.md).
  Do not treat the maintainer's M2 generation results and the RTX automated verification as the same measurement.
- Keep the switch expansion of `storeBTransposed` for Metal's threadgroup vec4 writes. Do not casually remove the RoPE / SiLU rounding barriers or the integer barrier of RMS fusion either.
  Spell the multiply-adds of the parallel GEMV family with explicit `fma()` (Metal changes how it contracts per expression form, and two kernels with the same formula diverge — [ADR 0105 addendum 4](../docs/decisions/0105-packed-static-quantize-activations.md)).
  `linearCompute: "a8"` has different contracts for the i8 full-K and the i4 group reductions ([ADR 0076](../docs/decisions/0076-w4a8-linear-execution.md)).
- Fusion depends on shape, consumers, published values and adjacency conditions. Confirm that it applies with diagnostics and the `e2e_*_fusion_counts_test.ts` files (`packages/e2e/tests/`).
  When decomposed attention loses its row-block, it can fall back to a huge intermediate ([ADR 0067](../docs/decisions/0067-autoregressive-attention-vocabulary.md)).
- Keep the submit after the Session's weight transfer, flush-before-destroy, the release order borrower → lender, and the run/batch reservations.
  Do not confuse rejecting dispose during a batch reservation with a dispose that waits after normal runs stop being accepted.
- Prefill shapes and multiple capacities consume the resident budget of PreparedPlan / backing. Do not apply fine buckets uniformly to every chunk.
  See [ADR 0095](../docs/decisions/0095-plan-backing-budget.md) and the [bucket verification](../docs/research/2026-09-13-prefill-buckets.md).
- Judge performance by repetitions under the same conditions. Do not tie absolute values of separate standalone runs, GPU passes split for diagnostics, or CPU sampling wait time directly to the speed of normal generation.
  Compare GPTQ quality on the same weights and the same evaluation inputs too ([measured quantization quality](../docs/research/2026-08-24-gptq-expansion-quality.md)).

## Entry points to the stable contracts

- Zero module side effects, Web standard APIs, TS/WGSL and the public barrel boundary are in [CLAUDE.md](../CLAUDE.md).
- The public names of `@karume/models`: the subpaths export bare names (`Pipeline`, `SOURCES`), the barrel the shared surface plus one namespace per family (`sbv2.Pipeline`) — [ADR 0136](../docs/decisions/0136-models-public-naming.md).
- Op tolerances are in `packages/runtime/tests/helpers/op-tolerance.ts`; WGSL for the same codegen key is byte-identical. Do not update reference goldens to match the speed-up defaults.
- The manifest is `karume/5` ([ADR 0109](../docs/decisions/0109-manifest-v5-container.md)); the distribution is the container `krm` (block ≤ 32 MiB, part ≤ 1024 MiB; [container-v1](../docs/container-v1.md)). The old shards (256 MiB cap, tensor pieces — [ADR 0090](../docs/decisions/0090-shard-spec-v3-tensor-pieces.md)) are retired.
  Memory fit is checked against the device's absolute limits, without guessing the physical free VRAM ([ADR 0089](../docs/decisions/0089-memory-limits-preflight.md)).
- The source of truth for the published revisions is each family's `SOURCES` table. Do not duplicate changes into docs; source resolution follows [ADR 0086](../docs/decisions/0086-distribution-source.md).
  For the sole owner of the RoPE inputs and the state length with variable capacity, see [ADR 0091](../docs/decisions/0091-gemma4-host-rope-variable-capacity.md).
- Assets and experiments: [assets-layout](../docs/assets-layout.md); the publishing procedure: [release-runbook](../docs/release-runbook.md).
  The real-image corpus is the frozen copy in `outputs/misc/corpus/`. Use a new directory for each experiment.
  The boundary between the exporter core and the model-specific recipes, and their licences, are in [ADR 0065](../docs/decisions/0065-exporter-core-recipe-split.md).
