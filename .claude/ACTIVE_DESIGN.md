## Current focus

- **The move to maintained specs — [ADR 0152](../docs/decisions/0152-maintained-specs-and-declared-numeric-requirements.md) accepted 2026-11-15; items 1–5 of 7 landed, item 6 started.** The work items, what each has landed and what is left from it are the first entry of the [backlog](../docs/backlog.md)'s `later` section.
  - **Documents.** `docs/spec/` holds what the system does now and is the source of truth (so far [spec/numerics.md](../docs/spec/numerics.md), [spec/verification.md](../docs/spec/verification.md), [spec/workbench.md](../docs/spec/workbench.md) and [spec/geometry-profiles.md](../docs/spec/geometry-profiles.md)); an ADR keeps a decision and its reasons and is not edited to follow the rules. Code points at a rule with `SPEC: docs/spec/<file>.md#<heading>`. Error messages do not cite ADR numbers.
  - **Numerics.** A preset declares a requirement level per model and per op kind — `exact` (the reference kernel's bits on this device), `reorder` (another summation order inside the op band) or approximations listed by name. The runtime's omitted value stays `exact`; reference kernels are frozen and better kernels are added beside them.
  - **Verification.** Every preset keeps sha256 rows stored with the fingerprint of the kernels the case compiled; the runtime checks its own strategies on a regression corpus; a verification cache re-runs a model's e2e only when its own code, its weights or the WGSL it compiles change.
  - **Built**: `SessionOptions.numerics` (`{ level?, ops? }`; the manifest's `session.numerics`; Gemma 4's pipeline options), one derivation shared by Session construction and the estimate, the three bit-identical fusions always applied, the verification cache's recording stage, the regression corpus with seven entries (two Gemma 4 QAT graphs, the Irodori and Wan2.2 DiTs, two VAE decoders and a text encoder; `packages/runtime/tests/corpus/`). The seven options that named a reduction form or a fusion are gone from the public surface.
  - **The workbench** (`apps/workbench`; ADR 0152 calls it the harness): one file is one entry without UI code, run by the browser shell and by `node apps/workbench/run.ts <entry>` alike; each run leaves a `karume-workbench/1` record under `outputs/workbench/<host>-<adapter name>/` (the dev server writes a browser run's). Its entries are `kernel-check`, `geometry-sweep` and `attention-bench`, whose pages left the Playground. The Playground's other measurement pages (they read a distribution) move later.
  - **Pitfall**: not built — the corpus's other entries, the applicability check derived from the graph (the `FamilySessionPolicy` tables still decide), making the cache's reuse the default (`KARUME_VERIFY_CACHE=reuse` is opt-in; the runtime's sources stay in its key). The subgroup GEMV, the subgroup RMS reduction and the byte-plane GEMV are selected by no Session (private key `REORDER_STRATEGIES`). The published `gemma4-qat` / `gemma4-qat-mobile` manifests use the old `session` keys and the hub now rejects them: the local mirrors are regenerated, the re-upload and the pins wait for the maintainer's go-ahead.
- **The numerics and kernel adoption rules — [ADR 0147](../docs/decisions/0147-numerics-and-kernel-adoption.md) accepted 2026-11-10** (supersedes ADR 0058 and 0110; rules index [kernel-rules](../docs/kernel-rules.md)). What a change has to meet now:
  - **Two axes.** A level says what a path is for (reference / practical / opt-in / preset — decision 1); a contract class E / C / R / Q says the form of its evidence (decision 2; class Q has a member, `attentionScoreStorage: "none"`). A practical preset (non-empty `session`) is a row class, not the practical level.
  - **Who decides.** A kernel or numerics path becomes a runtime option on machine checks only (its class checks, the four-point check for R / Q, the census, the reference rows unchanged). Making a configuration a preset is the maintainer's, after a human quality review of every preset (the default preset's never skipped; another's only on prior approval, with a machine evaluation instead); the maintainer picks the default; publication waits for an explicit OK (decision 3).
  - **Fusions bit-identical to the unfused plan always apply** (built): `fuseRmsNormAdd` / `fuseLinearStaticQuantize` / `fuseGeluMulStaticQuantize` left `SessionOptions` and the manifest vocabulary, and the test-only key `DISABLED_FUSION_RULES` gives the unfused plan. The Session canary that checks each fusion per device is not built (decisions 5, 9). `packedStaticQuantize` stays opt-in (NaN saturates).
  - **Acceptance is derived from the graph** at admission, before any weight is fetched; the per-family `FamilySessionPolicy` tables and MOSS-Image's knob gate go, a public query API answers which values have a place (decision 7). A missing device feature warns once and switches toward the reference instead of throwing (decision 8).
  - **Per-GPU evidence**: the workbench's `kernel-check` entry before every release, MUST on Dawn / Vulkan RTX 3080 Ti and Chrome / D3D12 RTX 5070 Ti, recorded per vendor / architecture / backend / browser (decision 9). The tiled VAE decode is a declared approximation of the reference level (decision 10).
  - **Pitfall**: until the remaining code changes filed in the backlog land, the code still has the acceptance tables and the throws on missing features — those rules are decided, not built. Do not add a boolean fusion key or a new acceptance-table entry in the meantime.

## Active pitfalls

- Low bit widths are **not a reason for speed**. Decode on the RTX 3080 Ti (Chrome, 2026-09-19) is not bandwidth-bound (measured bandwidth utilisation 11.5 / 25.5% — recomputed from the table's columns, 12.1 / 27.5%; the B570 (the development machine before the swap) and the M2 are unmeasured. [ADR 0108](../docs/decisions/0108-container-format.md) addendum 7), so what a low-bit codec trims is the side that is not the bottleneck. What it helps is **memory**, and its execution premise is packed int8 activations ([ADR 0105](../docs/decisions/0105-packed-static-quantize-activations.md)). To claim speed, measure that first ([ADR 0108](../docs/decisions/0108-container-format.md) decision 15).
- The real assets' i2 is **not ternary**. In gemma4-qat E2B's I2 tensors `q = −2` appears in 5.8–7.4%, so reading i2 assets as ternary turns around 6% of all elements into other values. Ternary has the same packing and restoration formula as i2 and needs 0 added runtime lines, but **it is declared as a separately named codec** (so that assets can be told apart — [ADR 0108](../docs/decisions/0108-container-format.md) decision 13).
- sha256 reference values are **rows per environment**, not constants ([ADR 0106](../docs/decisions/0106-device-keyed-references.md)). A machine without rows gets an explicit SKIP + a red reference guard, so create the rows with `KARUME_REFERENCE=write`. Do not re-record other environments' rows. Turning them into tolerances is forbidden.
- Wan2.1 resolves to the **practical preset** `f16+dit8-a8-attn8-s16` when `quant` is omitted (since 2026-10-04). The existing sha rows, bands and case ids are values of the `f16` preset, and the tests keep them by stating the preset explicitly in every case (omission is stopped by the type). When adding rows, state the preset explicitly too ([ADR 0120 addendum 2026-10-04](../docs/decisions/0120-wan-dit-w8a8-seat.md)).
- The golden's second stage (WGSL specification band; `OUTPUT_TOLERANCE` in `e2e_golden_test.ts`) is also **rows per environment key**; on a machine without a row the second stage does not exist at all, and the case goes red on the first stage, Karume's own criterion, alone ([ADR 0106 addendum](../docs/decisions/0106-device-keyed-references.md)). Rows are added only under the key of the machine that measured them, never widened to all machines.
- `measurements` in `results.json` is **a record not used for decisions** and holds no derived values such as ratios to the band (deriving them is the job of `tools/verify-diff`). When moving a band after reading this field, write the grounds for loosening from the relevant section of the specification and the measured values.
- Input-caused failures (the request itself cannot be accepted) are thrown as `ModelInputError`. Misspellings (model / quant / sampler names), call-order violations (disposed, double generation), asset mismatches and broken internal premises **stay plain `Error`** and are not mixed into this type ([ADR 0107](../docs/decisions/0107-model-input-error.md) decisions 2 / 3).
- Running a lane alone does not run the three all-SKIP guards (`gpu_gate` / `assets_gate` / `distribution_gate`) (they exist only in core). Do not treat a green lane as meaning the same as a green full verify. Only the reference guard is bundled with each series' e2e.
- Deno does not convert timestamp-query values to ns (they stay wgpu's raw ticks). The B570's `timestampPeriod` is 52.0833 ns, so the breakdown of `lastRunTiming` / `--diagnostics` is ×52 too small (the RTX 3080 Ti measured a period of 1 ns on 2026-10-06 and has a row in `TIMESTAMP_UNIT_NS`; Chrome converts — [known-issues](../docs/known-issues.md)).
- On Deno, by the time a `GPUOutOfMemoryError` is caught by an errorScope, the device may already be dead. The only survivable OOMs are those of `createBuffer` / `createTexture`; OOMs in `queue.writeBuffer` staging, submit and bind group creation make wgpu lose the device, and `device.lost` does not resolve until the next call that passes validation. Do not build any new design that "frees and retries after hitting OOM" — measure the free space first with `fitsHeadroom` (the 97% section of [limitations](../docs/limitations.md); [ADR 0112 addendum](../docs/decisions/0112-anima-transformer-residency.md)).
- CPU f32 changes the last bit depending on the offset of the weight's address from a 64-byte boundary (MKL behaviour; f64 unchanged). When an f32 golden splits, do not loosen the check; re-record it in that environment. A synthetic random text context amplifies the difference between f32 and f64 in Wan2.2 5B, so goldens and contexts used for decisions use real prompt embeddings ([ADR 0121 addenda "stage 0 results" / "stage 1 results"](../docs/decisions/0121-wan22-ti2v-5b.md)).
- Isolate whole-verify failures with the logs and standalone runs of the failing files. Do not conclude that it is VRAM pressure.
  For the reproduction where the fixed repo/revision of a fake HF URL and port reuse pick up an old manifest, see [known-issues](../docs/known-issues.md). Do not delete the cache without permission and treat that as a pass.
- Device loss from diagnostic runs on Metal and per-GPU low-bit differences are recorded in [known-issues](../docs/known-issues.md) and [limitations](../docs/limitations.md).
  Do not treat the maintainer's M2 generation results and the RTX automated verification as the same measurement.
- Keep the switch expansion of `storeBTransposed` for Metal's threadgroup vec4 writes. Do not casually remove the RoPE / SiLU rounding barriers or the integer barrier of RMS fusion either.
  Spell the multiply-adds of the parallel GEMV family with explicit `fma()` (Metal changes how it contracts per expression form, and two kernels with the same formula diverge — [ADR 0105 addendum 4](../docs/decisions/0105-packed-static-quantize-activations.md)).
  `linearCompute: "a8"` has different contracts for the i8 full-K and the i4 group reductions ([ADR 0076](../docs/decisions/0076-w4a8-linear-execution.md)).
- Fusion depends on shape, consumers, published values and adjacency conditions. Confirm that it applies with diagnostics and the `e2e_*_fusion_counts_test.ts` files (`packages/e2e/tests/`).
  When decomposed attention loses its row-block, it can fall back to a huge intermediate ([ADR 0067](../docs/decisions/0067-autoregressive-attention-vocabulary.md)).
- Keep the submit after the Session's weight transfer, flush-before-destroy, the release order borrower → lender, and the run/batch reservations.
  Do not confuse rejecting dispose during a batch reservation with a dispose that waits after normal runs stop being accepted.
- Prefill shapes and multiple capacities consume the resident budget of PreparedPlan / backing. Do not apply fine buckets uniformly to every chunk.
  See [ADR 0095](../docs/decisions/0095-plan-backing-budget.md) and the [bucket verification](../docs/research/2026-09-13-prefill-buckets.md).
- Judge performance by repetitions under the same conditions. Do not tie absolute values of separate standalone runs, GPU passes split for diagnostics, or CPU sampling wait time directly to the speed of normal generation.
  Compare GPTQ quality on the same weights and the same evaluation inputs too ([measured quantization quality](../docs/research/2026-08-24-gptq-expansion-quality.md)).

### Carried over from finished work

Pitfalls that sat inside this file's records of finished work. They stay here until a spec or a README next to the code takes them.

- **Node 24 + Dawn.** Dawn does not return a destroyed allocation until the next submit completes / `GPUAdapterInfo.description` is the driver version (the environment key uses the `device` field) / Node has no CacheStorage (pass `@karume/hub/node`'s `nodeCacheStorage(dir)` as `caches` to the hub's HTTP source — 2026-10-17) / `fs.readFile` rejects more than 2 GiB (test-support's fs reads 1 GiB at a time) / the sha rows of PNGs are the sha of the pixels (2026-10-17 — PNG bytes depend on the zlib implementation and differ between Deno and Node) / bf16 storage runs on the same skeleton as f16 (ADR 0131; upstream Anima is BF16 in all four components; the files of the base preset `bf16` are under `anima-v1.0/`; bf16 rounding leaves out non-persistent buffers (RoPE's inv_freq)) / Qwen3's text encoder pins packed-sequence detection before export (out-of-vocabulary ops since `a5427e6b`) / Node's ICU is Unicode 17.0 (splits with the NFKC table at U+A7F1; pinned).
- **Containers ([ADR 0108](../docs/decisions/0108-container-format.md)).** Do not upload a local mirror made by the migration CLI as is (the card reports `karume/4` and the safetensors dialect); always pass a declaration assembled on the host through `parseIrDeclarationValue` (the in-memory container applies no sha256 and checks neither non-finite numbers nor nesting depth — on the `krm` path, `openContainer` checks those); iterate `WeightBatch.items` only once, to the end, before pulling the next batch (iterating twice can silently yield 0 items; there is no run-time detection); the host RAM peak of the scan type grows with the part length (the measured external maximum = the held frame + buffers waiting for GC + items totals about 1.5–4.4 times the largest part), so do not estimate it with the seek type's numbers; the match between krm and the in-memory container in `gpu_memory_container_test.ts` is not an external ground truth (the two paths share everything from the merge layer to construction — ADR 0108 addendum 4), so the external ground truth is the cross-check with the CPU reference chain in the same file; the full-surface `assetComponentOpener` opens every component first (before admission); `ModelComponent.asset(name)` returns a new reader on each call, and with an unverified source it holds the block for its lifetime (do not hold it longer than one read); component replacement only for components whose graph description has the same sha256; `IrGraph.initializers[*]` has no `tensor` (the name is the key); a shared declaration is only `{shared:true}` and has no storage (the expected storage is derived from the lender's codec at construction).
- **Geometry profiles ([ADR 0115](../docs/decisions/0115-geometry-profiles.md) / [0117](../docs/decisions/0117-app-geometry-tuning.md)).** `runGeometrySweep` calls requestAdapter twice to see the timestamp-query enumeration (the callback form of step 5 can make it once); on an unexpected exception it returns no partial record (per-row failures, aborts and device lost are kept in the record).
  - Classes that contain new cases are re-run in **full**. The generator takes as candidates only geometries measured on every case of the column, so adding cases only in quick makes geometries adopted only on the full grid drop out as "not measured".
  - Registering a profile in `BUILTIN_GEOMETRY_PROFILES` automatically runs the per-profile GPU test (`gpu_geometry_profile_test.ts` — Uint32 match with the default + the geometry discriminator appears in the executed key).
  - The dp4a canary fires with the i8a8 attention geometry of the profile the Session chose (ADR 0115 decision 7). Reverting it to the default geometry makes the canary's WGSL and the executed WGSL differ on machines with a profile.
  - Deno reports an empty architecture, so today every machine falls back to the default profile (Chrome's spellings: M2 = `apple` / `metal-3`; RTX 5070 Ti = `nvidia` / `blackwell`).
  - Do not hand-edit the generated files (`src/kernels/geometry-profiles/<id>.ts`): regenerate with `node tools/geometry-profiles/generate.ts <id> --records=<workbench sweep records>` (the registered table as base plus new records; `--dry-run` shows what would change — [spec/geometry-profiles.md](../docs/spec/geometry-profiles.md)). The three tables' headers predate the generator and still name the untracked scripts under `outputs/diag/` that wrote them; each is replaced when its table is regenerated. `apple-metal-3` cites only records of the old sweep format and cannot be regenerated until M2 is swept again.
  - The fill value variables of the i8a8 kernels are fixed as `bv<number>` (building them from a prefix + number shadows the function-scope `k4` and silently gives wrong values). `codegen_i8a8_shadowing_test.ts` checks for overlapping declaration names over every candidate geometry.
  - Adding sweep cases of one op family moves only that family's keys (`caseSet` and `kernels` are per op family since ADR 0117 addendum 2026-11-12): every embedded table's entry of that family must be re-swept or re-derived in the same change (a derivation with the table as `base` carries the other families over), and a table re-derived from records without cases of a family has no entry for it, with its fields at the default by absence (ADR 0115 addendum decision 11).
- **Wan2.1 ([ADR 0118](../docs/decisions/0118-wan21-video-generation.md)).** Frames are 5–81 (unlocked in step 8; default 33); umT5 is bf16; 50 steps are opt-in via KARUME_WAN_FULL_PIPELINE=1; adaLN does not take part in fusion (0 reshapes); VAE zeroing is a host write (staging 0.58 GiB is on the VRAM side); wan's pytest is `uv run --group wan --inexact`.
- **Wan2.2 ([ADR 0121](../docs/decisions/0121-wan22-ti2v-5b.md)).** Put into the descriptor only values that differ by generation and cannot be derived from the graph declaration; channel counts, spatial compression and overlap are derived from the declaration and px (not held as constants); a commit that touches the 2.1 path (`src`) runs the 2.1 lanes for real and matches all of the development machine's rows (decision 10; after the swap, the RTX 3080 Ti rows — ADR 0121 addendum "the development machine changed"); when you change the shared test helper `wan-vae-chunk-loop.ts`, run both `vp test --project models:wan` and `vp test --project models:wan-ti2v`; stage 5's tile references (832×480×81 / 480×832×9) and stage 2's r check (S = 8,190 / 7,920) include sizes outside the accepted ones but are used as they are, as numeric checks unrelated to the accepted sizes; GPU checks may be run on a frozen copy of the target commit (`git archive <commit>` + symbolic links to the assets) to separate them from edits in the working tree; the NVIDIA driver does not expose `drm-total-*` in DRM fdinfo, so the tests' VRAM observation is `n/a` (not a check; watch from outside with `nvidia-smi`).
- **Irodori `dit_context` / `dit` ([ADR 0114](../docs/decisions/0114-irodori-dit-context-split.md)).** Pass the same `ditSessionOptions` to `dit_context` and `dit` (different options move the numbers); close the `dit_context` Session before opening `dit` (stacking them in the same batch doubles VRAM by the output slots).
- **Gemma 4 26B A4B ([ADR 0145](../docs/decisions/0145-gemma4-26b-moe-resident.md)).** This machine (12 GB) checks only the 12-layer cut (`KARUME_SERIES=1` `e2e_gemma4_26b_cut_test.ts`); the router has many near-ties (8th / 9th probabilities within 1e-4 on about 7% of rows); `storage_dtypes` counts an i4f16 step as part of its layout, not as f16.
- **Gemma 4 12B images ([ADR 0144](../docs/decisions/0144-gemma4-12b-vision.md)).** The masks are upstream's path A (transformers' plain `forward` takes B, so a golden harvested from it encodes B); each image gets its own prefill chunk; the lengths uniform is 16 bytes now; the goldens of `gemma4-12b-vision` are in the test-asset dataset.
- **f16 full-layer KV ([ADR 0143](../docs/decisions/0143-f16-full-state-storage.md)).** The self-tuning speculation gate is refused under it, and **`pack2x16float` rounds toward zero on D3D12**, so the append rounds in integers (the kernel check's first run in Chrome failed on this). S (`attentionScoreStorage: "f16"`) keeps `pack2x16float`, so its rounding differs between backends: integers cost 3–5% of the attention route there, and the difference is recorded and accepted (ADR [0031](../docs/decisions/0031-attention-score-f16-storage.md) addendum).
- **Integer GEMV ([ADR 0140](../docs/decisions/0140-integer-gemv.md)).** The epilogue's rounding barrier must not be spelled `rounded(0.0 + rounded(t))` (Metal reassociates — ADR 0140 decision 5).
- **Byte-plane GEMV ([ADR 0141](../docs/decisions/0141-byte-plane-gemv.md)).** The decode stays exact only while the compiler keeps its two constants apart (folding them into one `fma` decodes code 2 as about 1.2e-7 — ADR 0141 decision 2).
- **Decode run-ahead ([ADR 0142](../docs/decisions/0142-decode-run-ahead.md)).** A chained run's position is reserved at issue, never read in the body (the pending commit grows only at settlement — ADR 0142 decision 1); the M2 bench drops into a slow state after about six visits, so A/Bs there compare only the visits before it (research 2026-11-03 §11).
- **Held rows.** Rows can be added to the held rows (`HELD_SERIES` in `e2e_birefnet_test.ts`) only for families that bring down the whole process when run on that machine (families whose numbers do not match stay red and get fixed). The B570's 2048² row goes away by splitting `deform_conv2d` or by speeding it up (perf-ledger K-63).

## Entry points to the stable contracts

- Zero module side effects, Web standard APIs, TS/WGSL and the public barrel boundary are in [CLAUDE.md](../CLAUDE.md).
- The public names of `@karume/models`: the subpaths export bare names (`Pipeline`, `SOURCES`), the barrel the shared surface plus one namespace per family (`sbv2.Pipeline`) — [ADR 0136](../docs/decisions/0136-models-public-naming.md).
- Op tolerances are in `packages/runtime/src/reference/op-tolerance.ts`; WGSL for the same codegen key is byte-identical. Do not update reference goldens to match the speed-up defaults.
- The manifest is `karume/5` ([ADR 0109](../docs/decisions/0109-manifest-v5-container.md)); the distribution is the container `krm` (block ≤ 32 MiB, part ≤ 1024 MiB; [container-v1](../docs/container-v1.md)). The old shards (256 MiB cap, tensor pieces — [ADR 0090](../docs/decisions/0090-shard-spec-v3-tensor-pieces.md)) are retired.
  Memory fit is checked against the device's absolute limits, without guessing the physical free VRAM ([ADR 0089](../docs/decisions/0089-memory-limits-preflight.md)).
- The source of truth for the published revisions is each family's `SOURCES` table. Do not duplicate changes into docs; source resolution follows [ADR 0086](../docs/decisions/0086-distribution-source.md).
  For the sole owner of the RoPE inputs and the state length with variable capacity, see [ADR 0091](../docs/decisions/0091-gemma4-host-rope-variable-capacity.md).
- Assets and experiments: [assets-layout](../docs/assets-layout.md); the publishing procedure: [release-runbook](../docs/release-runbook.md).
  The real-image corpus is the frozen copy in `outputs/misc/corpus/`. Use a new directory for each experiment.
  The boundary between the exporter core and the model-specific recipes, and their licences, are in [ADR 0065](../docs/decisions/0065-exporter-core-recipe-split.md).
