## 実施順（2026-08-13 裁定 — 波順）

> **ビット同一門の位置づけ（ユーザー方針 2026-08-13）: 実装が正しいことの指標であって、
> それ自体が目的ではない。** 数値を変える最適化は **opt-in 席**で許容する — 既定 =
> 参照経路（sha256 門はそこで凍結・指標として温存）・opt-in 側は参照経路との A/B 帯門 +
> census・既定へ昇格させる時だけ品質裁定（w8a8 既定化が前例）。**品質管理の分担（同日
> 補足）: 実装の正しさ・非破壊はビット同一で機械検証し、ビット同一が保証されない部分は
> 人間レビュー（聴感・視認）で品質を管理する** — 数値が大幅に悪化していても生成結果が
> 崩壊していないことは多く、数値指標より人間評価を正とする（w8a8 既定化の「LSD 5.64 より
> 聴感が正」が前例）。旧「代替品質門の設計が先行条件」はこの方針で置換。2026-08-12 裁定の
> 第 1 段（前提ゼロ）は消化済み。

1. **波①（conv ビット一致）— 済（2026-08-13）**: K-4a = conv1d implicit GEMM
   （[ADR 0053](decisions/0053-conv1d-implicit-gemm.md)・`7a725d7`・conv1d 16.0 倍・
   irodori 全 GPU −27%・ビット同一）。K-7 の利得実測も相乗りで完了
   （[restats](research/2026-08-13-op-timing-restats.md) §7 — **採否裁定は波② H-2 の後**）。
2. **波②（ホスト境界）**: H-2 分解計測 → H-5 の API 設計案を先出し（裁定）→ H-5 + H-1
   実装（同根の固定費 — セットで実測）→ 残余で H-3。H-4 はタスク #7 と同体（別裁定）。
3. **波③（数値契約を割る群）**: numerics opt-in の ADR 起草（**案 a = 個別 named
   option** — `linearCompute`/`attentionCompute` と同型。「opt-in の高速化を全て使う」
   一括フラグは将来課題として ADR に記す — ユーザー要望 2026-08-13）→ K-5
   （portability 兼）→ K-2。K-4b（i8a8 化）は H-4 後。
4. **以降**: ⑤ 小粒・exporter 整備（帯 3 残 3 点 + L-5 の (rel_path,size) 前置フィルタ）→
   ⑥ モデル拡充（BiRefNet_HR → Gemma 4 E2B）→ ④ リリース準備波（P0-4 最小 gate ほか）。
   リリースはしばらく先（ユーザー 2026-08-13）— ④ はモデル拡充の後。
