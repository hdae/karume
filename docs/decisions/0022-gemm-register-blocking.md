# 0022: Register-blocked 4×4 + vec4 kernels for the three GEMM ops

- Status: accepted (2026-08-03, including six rulings approved by the maintainer); partly
  superseded by [0115](0115-geometry-profiles.md) (the one backend-common default geometry became
  per-adapter geometry profiles, 2026-09-27; refined by [0116](0116-geometry-profile-row-buckets.md)
  and [0117](0117-app-geometry-tuning.md)) and by [0058](0058-numerics-opt-in-contract.md) /
  [0110](0110-practical-tier-numerics-contract.md) decision 2 (how a variant that changes the
  reduction order is admitted, decision 3). The skeleton numbers of decision 1 were replaced by the
  parameterised geometry of the 2026-08-10 addenda.
- Date: 2026-08-03
- Scope: `matmul` / `bmm` / `linear` (`packages/runtime/src/kernels/gemm.ts` plus the thin
  `matmul.ts` / `bmm.ts` / `linear.ts`)
- Related: [0018](0018-f16-weight-execution.md) / [0019](0019-i8-weight-execution.md) (weight
  storage) / [0021](0021-gpu-timing-diagnostics.md) (the timing that measured the demand)

## Context

The GPU time breakdown of the Anima DiT (ADR 0021) was linear 89% (512 px, f16 weights) / 75%
(1024 px, i8 weights) and bmm 9% / 23%. The prototype measured 3.07× for a register-blocked kernel
([research/2026-08-03-demo-w8-perf-recon.md](../research/2026-08-03-demo-w8-perf-recon.md)). Design:
[research/2026-08-03-gemm-design.md](../research/2026-08-03-gemm-design.md).

## Decision

1. **One shared skeleton.** A single template in `packages/runtime/src/kernels/gemm.ts` with five
   insertion fragments serves all three ops. As decided on 2026-08-03 it was a 64×64 output tile,
   16×16 = 256 threads, 4×4 outputs per thread, K tile 16 and 8 KB shared memory; the geometry is
   now parameterised and the default is `M128N128 r8×8 wg16×16` with 16 KB shared memory (addenda
   of 2026-08-10). The earlier "do not share code" MUST was dropped because its purpose (protecting
   existing generated bytes) disappeared when all three ops were replaced at once. **A single
   inner-product loop mechanically keeps the reduction order identical across the three ops.**
2. **The key carries a shape-derived v4 flag** (`gemmUsesVec4(k, n) = k % 4 == 0 && n % 4 == 0`).
   Other shapes take a scalar variant with the same register structure. A key that depends on the
   shape follows the same vocabulary as `r${rank}` in `elementwiseKey`, so determinism (same key ⇔
   same bytes) holds. Padding was rejected because it touches three invariants (full write,
   aliasing, pool sizes); keeping a 16×16 kernel was rejected because the scalar variant covers it.
3. **The reduction order is exactly that of the old kernel** (K ascending, tile width 16, outer `t`
   and inner `kk` both ascending). MUST: this is the base of the numeric contract; a future variant
   that changes the reduction order (DP4a, shader-f16 and so on) enters only together with a
   re-derived tolerance. **(superseded by ADR 0058 and ADR 0110 decision 2 on 2026-09-26: such a
   variant is a separate named option off the reference path, and the evidence it needs is defined
   by the contract class it declares. The core — changing the order requires new evidence —
   remains.)**
4. **Quad reads of stored weights are an opt-in extension of `weight-storage.ts`** (`dequant4` /
   `weightRead4`). It defaults to off, so the other weight-reading ops (conv1d, conv2d,
   conv_transpose1d, embedding) generate the same bytes; snapshots check this. i8 dequantisation is
   `vec4<f32>(unpack4xI8(w)) * s`, a per-component f32 multiply with the same rounding as the
   scalar path, so ADR 0019 ("scale applied per element") holds under vec4 and needs no change. f16
   reads 4 elements from 2 u32 words; this relies on the flat index being a multiple of 4, which is
   a different trap from the parity issue of ADR 0018.
5. **The bmm uniform is 3 words `{m, n, k}`.** The batch comes from `wid.z`; the old 4th word
   `batch` was never read by the WGSL.

## Consequences

- Measured on 2026-08-03: the demo PNG sha256 matched before and after for 512 px / f16 weights and
  1024 px / i8 weights; no tolerance changed; DiT GPU time per step improved 3.95× (512 px) and
  3.65× (1024 px).
- Detection limits found by fault injection (10 cases), kept as operating knowledge: (1) dropping
  the zero fill of the K remainder on one of A / B is not detected, because the other side's zero
  cancels the product; (2) a K-remainder regression in `matmul` alone is not caught by the current
  cases; (3) swapping the i8 scale axis is detected only by cases with two or more row tiles.
- Full-write checks with poison values cover the three ops × v4 / scalar
  (`packages/runtime/tests/gpu_full_write_test.ts`). The grid-stride degeneration harness does not
  apply to tiled kernels; their safety net is the fail-loud `tiledWorkgroups` plus these checks.
- Coverage gap: no real model has a `matmul` node, and the scalar variants of `matmul` and of
  f32 / f16 `linear` are exercised only by unit tests.
- Dynamic indexing of `acc` depended on the driver's unrolling; the 2026-08-10 addenda confirmed
  the risk and moved to static unrolling.

## Addendum (2026-08-10) — i8a8 geometry and static unrolling

Dynamic indexing spilled to local memory on NVIDIA as well. The i8a8 kernels moved to codegen-time
unrolling (linear `4b15ec2`, attention `3f417dc`, ×1.35–1.45 each) and got their own parameterised
geometry (`packages/runtime/src/kernels/i8a8-geometry.ts`; linear / QK `M128N64 r8×8 wg8×16`, PV
`M64N128`). Integer reduction is order-independent, so the geometry does not change output bits
([research/2026-08-10-kernel-variant-sweep.md](../research/2026-08-10-kernel-variant-sweep.md)).

## Addendum (2026-08-10, later) — f32 / f16 geometry parameterised

The f32 / f16 skeleton also takes a parameterised geometry (`packages/runtime/src/kernels/gemm-geometry.ts`),
carried in the pipeline key. Decision 3 still holds: geometry changes only the assignment of work;
the per-output K order and the multiply-add expression stay the same. Unlike i8a8, f32 has no
theoretical guarantee of order independence across geometries; bit identity is an empirical claim
(three geometries, all PNG / WAV checks, zero sha256 mismatches —
[research/2026-08-10-f32-geometry-probe.md](../research/2026-08-10-f32-geometry-probe.md)).

- MUST: a change of the default geometry goes together with re-running the sha256 checks.
- MUST NOT: geometry that changes at run time (autotuning) for f32 / f16. Reaffirmed by ADR 0115
  decision 8 and ADR 0117.

Static unrolling of the accumulator was applied to every op (f16 at 1024 px ×1.15 on its own).

## Addendum (2026-08-10, tile sweep) — default `M128N128 r8×8 wg16×16`

Tile edges became part of the geometry (`tileM = regM·wgY`, `tileN = regN·wgX`; dispatch and key
resolve through the same point as generation). The sweep set the default to
`M128N128 r8×8 wg16×16` (f16 at 1024 px 23.7 → 20.2 s, w8a8 neutral, all PNG / WAV checks
bit-identical; research above, section on the tile sweep). conv2d keeps its 64 / 32-row m-tile
heuristic. The best tile shape differs from i8a8's, so default geometries are chosen per path
from measurements only. Apple M2 showed no regression and identical output sha256.

The rule "one default for every backend; per-backend static defaults only after a clear measured
regression" **(superseded by ADR 0115 on 2026-09-27: the M2 sweep reversed the winning geometry
between GPUs, which met this rule's own condition; selection is now a static per-adapter table, a
geometry profile)**. The ban on run-time autotuning is unchanged.

## Addendum (2026-08-11) — row-count buckets

Geometry is chosen from a static table on the row count M (`gemmGeometryForRows`;
`GEMM_ROWS_BUCKETS` in `gemm-geometry.ts`), because `M128N128` leaves one row tile for small M and
becomes occupancy-bound (EmbeddingGemma at T=4). The first version used only M ≤ 64; the same day
the middle bucket was adopted (`a81cc083`) after the Anima / SBV2 end-to-end A/B showed no
regression and every sha256 matched
([research/2026-08-11-skinny-m-geometry.md](../research/2026-08-11-skinny-m-geometry.md) §4):

| M          | Geometry               |
| ---------- | ---------------------- |
| ≤ 64       | `M16N16 r1×4 wg4×16`   |
| 65 – 512   | `M64N32 r4×4 wg8×16`   |
| ≥ 513      | default `M128N128`     |

Boundaries are the measured ones; M ≥ 513 is outside the measured points and is not
interpolated. The choice is a pure function of the plan-time shape and the key carries the
geometry. The table serves linear / bmm / matmul, the row-block decomposed attention (ADR 0060 —
QK / PV are bmm) and the tiled GEMM paths ①ₜ QK / ③ₜ PV of states-shaped attention (ADR 0067
addendum 2026-09-06, perf-ledger K-13). Fused attention ① / ③ (ADR 0023), conv2d and i8a8 do not
use it. Since ADR 0115 the Session reads it through the adapter's profile
(`gemmRowsGeometry` in `packages/runtime/src/kernels/geometry-profile.ts`); the default profile
holds this table as is.
