# 0003 — IR v1（プロトタイプ IR（v0）の非互換改訂）

- Status: accepted（2026-08-01、ユーザー裁定: v0 互換は保たない）
- 根拠資料: recon §2/§7

## 決定

先行実験プロジェクト（以下プロトタイプ）の IR（v0）の構造を土台に、**非互換の v1** として
改訂する。

### 継承するもの（プロトタイプで実証済み）

- 配布形は **単一 safetensors + `__metadata__` へのグラフ JSON 埋め込み**
  （HF 配布・Range 取得と相性が良い）。
- **制御フローを持たない静的 DAG**。ループ・データ依存 shape・RNG はホスト外出し。
- ノードは SSA `{op, ins, outs, attrs}`（各値の定義はちょうど 1 箇所。outs は 1 個以上 —
  詳細は docs/ir-v1.md）。全値の `{dtype, shape}` を宣言し、実行時に毎ノード照合。
  JSON は `allow_nan=False`（受理集合をブラウザ JSON.parse に揃える）。
- 次元言語は **`coeff·sym+offset` の一次式・1 次元 1 シンボル・シンボル名は
  エクスポート呼び出し側が正本**（プロトタイプ決定 0007→0010 の到達点から開始）。
  入力 shape に現れないシンボルは拒否。
- op 語彙は allowlist 凍結。融合ノードは IR 語彙の外（optimizer/executor 間の内部語彙）。

### v0 から変えるもの

1. **格納メタの明示フィールド化**: `<prefix>.scale.<key>` / `<prefix>.folded.<hash>` 型の
   companion 命名規約による暗黙結合を廃止し、initializer 単位の `storage` 記述
   （格納 dtype / scale 参照 / group_size 等）を JSON 側に持つ。
   意味論 dtype（常に f32）とは分離したままにする。
2. **bf16 を格納 dtype 語彙に最初から含める**（v0 の DTYPE_NAMES には無い。
   PyTorch 主流 dtype のため境界での扱いを仕様化する）。
3. **バージョニングと capability**: バージョン欄が整数 1 個ではなく、フォーマット
   バージョン + グラフが要求する op 語彙集合を宣言できる欄を持つ（ランタイムはロード時に
   非対応 op を列挙して fail loudly できる）。
4. **次元文法の実装 1 正本化**: v0 は 4 実装（emit / verify / parse / resolve）を人間の
   規律で同期していた。v1 は文法定義を共有テーブル + 適合テスト（TS/Python 双方が同一
   ケース表で検証）に集約する。
5. メタデータキー等の識別子は Karume 名義に改める。

## 帰結

- プロトタイプの既存モデルファイルはそのままでは動かない（exporter を新設するため許容 —
  ユーザー裁定）。
- 未リリースの間は v1 内でも breaking 変更可（グローバル規約: 未リリースは移行 shim 禁止・
  fail loudly）。
