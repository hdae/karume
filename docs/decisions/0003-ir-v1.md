# 0003: IR v1 (an incompatible revision of the prototype's IR v0)

- Status: accepted (2026-08-01, the maintainer's ruling: no compatibility with v0); partly
  superseded by [0009](0009-dtype-i32-bool.md) (semantic dtypes are f32 / i32 / bool, 2026-08-02)
  and [0108](0108-container-format.md) (the container convention and the `storage` description of
  change 1, in effect 2026-09-24). The static DAG, SSA, dimension language, `allow_nan=False` and op
  allowlist hold in IR v2.
- Date: 2026-08-01
- Related: recon §2 / §7

## Decision

Starting from the structure of the prototype's IR (v0), Karume defines an **incompatible v1**.

### Kept from v0 (proven in the prototype)

- The distribution form is **one safetensors file with the graph JSON embedded in
  `__metadata__`** (suits Hugging Face distribution and range requests) *(superseded by ADR 0108
  on 2026-09-24 — see the addendum)*.
- **A static DAG without control flow.** Loops, data-dependent shapes and RNG stay on the host.
- Nodes are SSA `{op, ins, outs, attrs}` (each value is defined exactly once; `outs` has one or more
  entries — details in [IR v2](../ir-v2.md)). Every value declares `{dtype, shape}`, checked per
  node at run time. The JSON is written with `allow_nan=False` (the accepted set equals the
  browser's `JSON.parse`).
- The dimension language is **a linear expression `coeff·sym+offset`, one symbol per dimension,
  with symbol names owned by the export call site** (starting from where the prototype's decisions
  0007 → 0010 ended). A symbol that does not appear in an input shape is rejected.
- The op vocabulary is a frozen allowlist. Fused nodes are outside the IR vocabulary (an internal
  vocabulary between optimizer and executor). *Later fact: ADRs [0012](0012-attrs-and-fused-ops.md)
  and [0023](0023-fused-attention.md) added composite ops that the exporter keeps undecomposed
  (`linear`, `rms_norm`, `attention`, … — [op vocabulary](../op-vocabulary.md)) to the IR; what stays
  outside it is the runtime fusion pass (`packages/runtime/src/runtime/fusion.ts`).*

### Changed from v0

1. **Storage metadata becomes explicit fields.** The implicit binding by companion names
   (`<prefix>.scale.<key>`, `<prefix>.folded.<hash>`) is dropped; each initializer carries a
   `storage` description (storage dtype, scale reference, group size, …) in the JSON, kept separate
   from the semantic dtype (then always f32 — ADR 0009 allowed i32 / bool on 2026-08-02; the
   separation stands). *(Superseded by ADR 0108 decision 17 on 2026-09-24 — see the addendum.)*
2. **bf16 is in the storage-dtype vocabulary from the start** (v0's `DTYPE_NAMES` lacks it; it is a
   mainstream PyTorch dtype, so its handling at the boundary is specified).
3. **Versioning and capabilities.** Instead of one integer, the version field holds the format
   version plus the op vocabulary the graph requires, so the runtime can list unsupported ops at
   load time and fail loudly.
4. **One source for the dimension grammar.** v0 kept four implementations (emit / verify / parse /
   resolve) in sync by discipline; v1 puts the grammar in one shared case table with conformance
   tests that TypeScript and Python both run (`packages/runtime/tests/fixtures/dim-grammar.json`).
5. Metadata keys and other identifiers are renamed to Karume's.

## Consequences

- The prototype's model files do not load as they are (accepted because the exporter is new — the
  maintainer's ruling).
- Withdrawn 2026-10-18: "breaking changes inside v1 are allowed while unreleased (no migration
  shims)". Karume is released, and old distribution forms are read by the migration CLI
  (`karume migrate`, `tools/exporter/src/karume/cli.py`).

## Addendum (2026-09-22, in effect 2026-09-24) — ADR 0108 replaces the container convention

The container of [0108](0108-container-format.md) (`krm` / `krg`, two-document descriptor, blocks
and parts) replaced the single-safetensors convention; the old readers left runtime, hub and models
in `9e905d9f`. Canonical now: 0108, [container-v1](../container-v1.md) and [IR v2](../ir-v2.md).

## Addendum (2026-09-24) — the `storage` description of change 1 moved to the binding table

ADR 0108 decision 17 (IR v2 = IR v1 − `storage`) moved it from the graph JSON to the `encoding` of the
container's binding table ([container-v1](../container-v1.md) §5, §6). Change 1's intent — explicit
fields instead of companion names, storage separate from the semantic dtype — is unchanged.
