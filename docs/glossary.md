# 用語集（glossary）

> 用語 → 意味の要約 → 会話と docs で使う日本語 → 正本へのポインタ。
> **意味の正本は各行の参照先**で、この表は索引に徹する（定義を 2 か所で持たない）。
> 要約と正本が食い違ったら正本が勝ち、この表を直す。
> docs に新しい用語を持ち込むときはここへ 1 行足す。
> 量子化方式そのものの全数と状態は [quantization](quantization.md) が索引を持つ。

## 量子化 — 格納と名前

| 用語                       | 意味（要約）                                                                                                                                        | 使う日本語                                                         | 正本                                                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 格納型（storage dtype）    | 資産ファイルに焼く重みの形。`f32` / `f16` / `i8` / `i4` / `i2` / `i32`（`bf16` は宣言のみ）。意味論は `i32` を除いて全て f32 で、格納だけを圧縮する | 格納型                                                             | [ir-v1 §格納 dtype](ir-v1.md)・`packages/runtime/src/format/ir.ts` の `STORAGE_DTYPES`・ADR [0006](decisions/0006-quantization.md)                      |
| dtype ラベル               | 配布 manifest の `quants[].weights` に書く綴り。格納型と同じ語彙を使い、混成資産では「適格な重みの格納型」を代表として書く                          | dtype ラベル                                                       | ADR [0074](decisions/0074-quant-seat-naming.md) 決定 2                                                                                                  |
| 系列（series）             | exporter が書く中間成果物のディレクトリ単位（`outputs/series/<系列名>/`）。配布形の 1 つ手前                                                        | 系列                                                               | [assets-layout](assets-layout.md)                                                                                                                       |
| quant 席（quant seat）     | 配布形が「格納型 + 実行ノブ」を束ねて付けた名前（`i4` / `i4-gemvpar` / `i4-fast` など）。hub は不透明キーとしてしか扱わない                         | quant 席（会話では「quant の選択肢」でもよい）                     | ADR [0074](decisions/0074-quant-seat-naming.md)・表示名は [0075](decisions/0075-quant-presentation.md)                                                  |
| packed                     | 1 語 / 1 byte に複数の整数要素を詰めた格納。`i4` は 1 byte 2 要素（`u = q + 8`）、`i2` は 1 byte 4 要素（`u = q + 2`）                              | packed                                                             | ADR [0069](decisions/0069-packed-w4-storage.md) 決定 2・[0097 追記 1](decisions/0097-gemma4-qat-integration.md#追記-1--int2-格納と実行の契約2026-09-11) |
| group_size                 | `i4` で 1 個の scale が担当する K 方向の連続要素数。2 冪かつ 16 以上で、行長を割り切ること                                                          | group_size（「group 量子化」で統一・「グループ量子化」と混ぜない） | ADR [0069](decisions/0069-packed-w4-storage.md) 決定 2                                                                                                  |
| scale companion            | 量子化重みの復元係数を持つ別テンソル。`i8` は `[出力チャネル]`、`i4` は `[N, groups]`、`i2` は `[N,1]`                                              | scale companion                                                    | [ir-v1 §格納 dtype](ir-v1.md)・ADR [0019](decisions/0019-i8-weight-execution.md)                                                                        |
| PLE（Per-Layer Embedding） | 層ごとに 1 本ずつ足し込まれる補助 embedding。グラフの外の sidecar としてホストが行を読む                                                            | PLE                                                                | ADR [0085](decisions/0085-ple-host-gather.md)・packed 版は [0097 追記 4](decisions/0097-gemma4-qat-integration.md#追記-4--packed-ple-sidecar2026-09-11) |

## 量子化 — 活性と実行

| 用語                                               | 意味（要約）                                                                                                                                                                          | 使う日本語                             | 正本                                                                                                                                                                                            |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実行ノブ                                           | `SessionOptions` の数値・方式系オプション（`linearCompute` / `linearGemvReduce` / 融合フラグなど）。格納型とは直交する                                                                | 実行ノブ                               | `packages/runtime/src/runtime/session-types.ts` の `SessionOptions`・保存可否は `packages/hub/src/manifest.ts` の `SESSION_KEYS`・契約は ADR [0058](decisions/0058-numerics-opt-in-contract.md) |
| SRQ（Static Range Quantization・静的レンジ量子化） | 学習時に決めた固定 scale で活性値を int8 の格子へ丸め、同じ scale を掛け戻す処理。計算は f32 のままで「丸めるだけ」。`scale = 0` は恒等（未較正の印）                                 | SRQ                                    | ADR [0097 追記 2](decisions/0097-gemma4-qat-integration.md#追記-2--固定-srq-op-の契約2026-09-11)・op は [op-vocabulary](op-vocabulary.md) の `static_quantize`                                  |
| w8a8                                               | 重み i8 格納 × 活性 per-token i8 の**整数内積**経路（`linearCompute: "a8"`）。初出では展開する                                                                                        | w8a8（重み 8bit × 活性 8bit 整数内積） | ADR [0025](decisions/0025-w8a8-linear-execution.md)                                                                                                                                             |
| w4a8                                               | 重み i4 常駐 × 活性 per-token i8 の整数内積経路。group 部分縮約なので数値契約は w8a8 と別                                                                                             | w4a8                                   | ADR [0076](decisions/0076-w4a8-linear-execution.md)                                                                                                                                             |
| 整数内積                                           | 量子化した整数同士を int32 累算で掛け合わせる実行形。縮約順に依らず結果が一意になる。karume が持つのは w8a8 / w4a8 で、QAT の SRQ 経路は float 縮約                                   | 整数内積                               | ADR [0025](decisions/0025-w8a8-linear-execution.md)・[0076](decisions/0076-w4a8-linear-execution.md)                                                                                            |
| packed int8 活性                                   | 固定 SRQ が出す int8 コード 4 個を u32 1 語に詰めて並列 GEMV へ渡す受け渡し形。GEMV 側は `f32(code) × scale` で戻して現行の f32 積和に流すので現行とビット同一（-0.0 / NaN だけ例外） | packed 活性                            | ADR [0105](decisions/0105-packed-static-quantize-activations.md)                                                                                                                                |
| fake-quant                                         | 重みを量子化格子へ丸めてから f32 のまま保持する処理。exporter が焼く前の丸め段を指す                                                                                                  | fake-quant                             | `tools/exporter/src/karume/quantize.py`                                                                                                                                                         |
| RTN（Round To Nearest）                            | 校正なしの最近接丸め。i8 は per-channel 対称、i4 は K 方向 group                                                                                                                      | RTN                                    | ADR [0019](decisions/0019-i8-weight-execution.md)・[0069](decisions/0069-packed-w4-storage.md)                                                                                                  |
| GPTQ                                               | 校正データで丸めを補正する方式。karume が出荷するのは格子が RTN と厳密に同じ `grid="rtn"` 版なので、格納形は i4 席そのもの                                                            | GPTQ                                   | [perf-ledger](perf-ledger.md) Q-6・`tools/exporter/src/karume/quant_calib.py`                                                                                                                   |
| 固定量子化（QAT の持ち込み）                       | 上流 checkpoint の整数と scale を再量子化せずそのまま焼く経路。自動量子化（fake-quant → 格納）とは入口が別                                                                            | 固定量子化                             | ADR [0097 追記 3](decisions/0097-gemma4-qat-integration.md#追記-3--固定量子化-writer-の入口2026-09-11)                                                                                          |

## 生成と文脈

| 用語                                | 意味（要約）                                                                                                                                                              | 使う日本語                                           | 正本                                                                                                                                                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| capacity（容量）                    | 1 会話が確保する KV cache の論理位置の数 = その会話が使える最大の文脈長                                                                                                   | capacity                                             | ADR [0066](decisions/0066-generation-context-state-slots.md)・可変容量の RoPE 入力は [0091](decisions/0091-gemma4-host-rope-variable-capacity.md)・実行時ノブとしての性質は [limitations](limitations.md) |
| chunkLength                         | prefill（prompt をまとめて食わせる段）1 回に流す行数                                                                                                                      | chunkLength                                          | ADR [0066](decisions/0066-generation-context-state-slots.md) 決定 4                                                                                                                                       |
| maxChunkLength                      | `chunkLength` の上限。export 時に焼いた記号 `M` の trace 上限を配布形が宣言したもの                                                                                       | maxChunkLength（「trace 上限」と言い換えない）       | ADR [0066](decisions/0066-generation-context-state-slots.md)・宣言は各 `distribution.py`                                                                                                                  |
| chunkBuckets（prefill バケット）    | chunk ごとに「`queryLength` 以上の最小バケット」の物理行数で走らせるための宣言集合                                                                                        | prefill バケット                                     | [limitations](limitations.md) の「prefill バケット」節                                                                                                                                                    |
| KV cache                            | 過去 token の key / value を保持する領域。karume では generation context の state スロット                                                                                | KV cache                                             | ADR [0066](decisions/0066-generation-context-state-slots.md)                                                                                                                                              |
| sliding 層 / full 層                | 直近 `window` 位置だけを見る attention の層 / 会話の先頭から全部を見る層。KV の伸び方が違う                                                                               | sliding 層 / full 層                                 | ADR [0066](decisions/0066-generation-context-state-slots.md)・[0067](decisions/0067-autoregressive-attention-vocabulary.md)                                                                               |
| ring                                | sliding 層の KV を物理行へ巡回配置する環状バッファ。法は `window` ではなく `capacity`                                                                                     | ring                                                 | ADR [0067](decisions/0067-autoregressive-attention-vocabulary.md) の 2026-09-08 追記                                                                                                                      |
| slack                               | ring の行数が窓より多い余り。投機デコードの棄却行の置き場                                                                                                                 | slack                                                | ADR [0096](decisions/0096-speculative-decoding.md)                                                                                                                                                        |
| MTP（Multi-Token Prediction）       | 公式 drafter が複数 token をまとめて提案する仕組み。karume では投機デコードの提案側                                                                                       | MTP                                                  | ADR [0096](decisions/0096-speculative-decoding.md)                                                                                                                                                        |
| 投機デコード                        | drafter が出した k token を本体が 1 run で検証し、一致した分だけ確定する実行形                                                                                            | 投機デコード（「speculative」と混ぜない）            | ADR [0096](decisions/0096-speculative-decoding.md)                                                                                                                                                        |
| 融合（fusion）                      | 隣接する複数 op を 1 回の GPU 起動へまとめる変換。形・消費・公開値・隣接条件が揃ったときだけ適用する                                                                      | 融合                                                 | ADR [0040](decisions/0040-fusion-pass.md)                                                                                                                                                                 |
| 先行投入（decode の）               | 次 token を GPU 内で決めて埋め込みへ渡し、読み戻しを待たずに深さ d の run を同一 context へ先に発行する実行形。フェンス待ちを d 本で償却する                              | 先行投入                                             | [research 2026-09-19](research/2026-09-19-qat-speed-recon.md) §9 クラスタ B・契約は ADR [0066](decisions/0066-generation-context-state-slots.md)                                                          |
| フェンス床（Deno の）               | Deno の WebGPU 実装がフェンス 1 本（`mapAsync` / `onSubmittedWorkDone`）につき GPU 完了後に必ず 10 ms 寝る定数。decode は 1 token = 1 フェンスなので壁に 10 ms/token 乗る | Deno のフェンス床                                    | [research 2026-09-19](research/2026-09-19-qat-speed-recon.md) §3.2・[limitations](limitations.md)                                                                                                         |
| 入力起因エラー（`ModelInputError`） | 渡した要求そのものが受理できない失敗 = 入力を直せば通る（HTTP なら 400）。内部不変条件の破れ・資産の齟齬・GPU 容量（= 500）は素の `Error` のまま                          | 入力起因エラー（「バリデーションエラー」と混ぜない） | ADR [0107](decisions/0107-model-input-error.md)                                                                                                                                                           |

## 検証

| 用語                             | 意味（要約）                                                                                                                                                             | 使う日本語                                                | 正本                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| レーン（テストレーン）           | フル verify を分けた実行単位。`deno.json` の `test:core` と `test:models:<系列>` が定義で、core ∪ 全レーンがリポの全テストを覆う（被覆は `verify_lanes_test.ts` が見る） | レーン（「シャード」「グループ」と言い換えない）          | ADR [0005](decisions/0005-verification.md) の 2026-09-20 追記                                                 |
| 環境キー                         | 参照値と検証結果を機ごとに分ける ID。`<ランタイム>-<アダプタ名 slug>`（例 `deno-intel-graphics-bmg-g21`）。GPU アダプタが取れない環境は持たない                          | 環境キー（「デバイス ID」と言い換えない）                 | ADR [0106](decisions/0106-device-keyed-references.md) 決定 2・`packages/runtime/tests/helpers/environment.ts` |
| 参照値（環境別の行）             | e2e 出力（PNG / WAV）の sha256 の期待値。`packages/models/tests/fixtures/references/<系列>.json` にケース ID × 環境キーの行として持つ（追跡下）                          | 参照値（「ゴールデン」は torch 由来の golden と混ぜない） | ADR [0106](decisions/0106-device-keyed-references.md) 決定 1                                                  |
| 作るモード（`KARUME_REFERENCE`） | 参照値の行を実測から作る指定。未設定 = 比較だけ、`write` = 無い行を足す（既存は触らない）、`rewrite` = 現環境の行だけ上書き                                              | 作るモード                                                | ADR [0106](decisions/0106-device-keyed-references.md) 決定 3                                                  |
| 結果の席（`outputs/verify/`）    | 走行ごとの決着 `results.json` と実物の置き場（`<環境キー>/<日付>_<系列>/`・git 追跡外・消して安全）                                                                      | 結果の席                                                  | ADR [0106](decisions/0106-device-keyed-references.md) 決定 5・[assets-layout](assets-layout.md)               |
