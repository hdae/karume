# Glossary

> Term → meaning summary → pointer to the canonical source. The Japanese used in conversation is in
> [GLOSSARY.ja.md](GLOSSARY.ja.md).
> **The canonical meaning is the source each row points to**; this table is only an index (a
> definition is not kept in two places).
> When a summary and its source disagree, the source wins and this table is fixed.
> When a new term enters the docs, add one row here.
> The full list and status of the quantization methods themselves are indexed by
> [quantization](quantization.md).

## Quantization — activations and execution

| Term                                 | Meaning (summary)                                                                                                                                                                                                                                                                                                                                                         | Source                                                                                                                                                                                                            |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Option / knob                        | The numeric and method options of `SessionOptions` (`linearCompute` / `linearGemvReduce` / fusion flags and so on). Orthogonal to the storage dtype                                                                                                                                                                                                                       | `SessionOptions` in `packages/runtime/src/runtime/session-types.ts`, whether it can be stored: `SESSION_KEYS` in `packages/hub/src/manifest.ts`, contract: ADR [0058](decisions/0058-numerics-opt-in-contract.md) |
| SRQ (Static Range Quantization)      | Rounds activations to an int8 grid with a fixed scale decided at training time and multiplies the same scale back. The computation stays f32 and "only rounds". `scale = 0` is the identity (the mark of an uncalibrated scale)                                                                                                                                           | ADR [0097 addendum 2](decisions/0097-gemma4-qat-integration.md#addendum-2-2026-09-11--fixed-srq-op-contract), op: `static_quantize` in [op-vocabulary](op-vocabulary.md)                                          |
| w8a8                                 | The **integer dot product** path of i8-stored weights × per-token i8 activations (`linearCompute: "a8"`). Spelled out at first use                                                                                                                                                                                                                                        | ADR [0025](decisions/0025-w8a8-linear-execution.md)                                                                                                                                                               |
| `vaeTile` (Wan2.2)                   | The edge of the Wan2.2 VAE decoder's latent tile a request chooses (`wan.GenerateRequest.vaeTile`: 16 by default, 32 opt-in). 32 runs a second chunk-graph pair that holds no weight bytes and borrows the 16-tile pair's resident weights (shared initializers); it decodes 1280×704 in 2×3 tiles instead of 4×7, at about four times the decoder stage's memory. Never chosen automatically | ADR [0134](decisions/0134-wan22-vae-tile32-shared.md) |
| conv3d w8a8 / `conv8`                | The integer dot-product path of conv3d: int8-resident weights × activations quantised to int8 **once per input pixel over its channels**, one exact i32 sum per tap folded into f32 by one `fma` per tap (`convCompute: "a8"`; preset token `conv8`). The weight is reordered to tap-major on the host at Session construction                                                                                        | ADR [0133](decisions/0133-conv3d-w8a8.md)                                                                                                                                                                         |
| Channel-major quantiser (per-pixel quantiser of conv3d w8a8) | The activation quantiser of conv3d w8a8: one dispatch that reads the conv input `x[Cin, P]` as stored (consecutive threads take consecutive pixels; a workgroup is 16 pixels × 16 channel lanes), folds each pixel's amax over its channels and writes the same `xq[P][Cin/4]` words and `xs[P]` scales as the row form of `quantize_rows`, bit-identical. It replaced the transposed f32 copy + `quantize_rows` on 2026-10-26 (perf-ledger V-6) | ADR [0133](decisions/0133-conv3d-w8a8.md) addendum 2026-10-26 (channel-major quantiser), `quantizeRowsChannelMajorWgsl` (`packages/runtime/src/kernels/quantize-rows.ts`) |
| w4a8                                 | The integer dot product path of resident i4 weights × per-token i8 activations. A partial reduction per group, so its numerics contract differs from w8a8                                                                                                                                                                                                                 | ADR [0076](decisions/0076-w4a8-linear-execution.md)                                                                                                                                                               |
| Integer dot product                  | The execution form that multiplies quantized integers with int32 accumulation. The result is unique regardless of the reduction order. Karume has w8a8 / w4a8; the QAT SRQ path reduces in float                                                                                                                                                                          | ADR [0025](decisions/0025-w8a8-linear-execution.md), [0076](decisions/0076-w4a8-linear-execution.md)                                                                                                              |
| Packed int8 activations              | The hand-off form that packs 4 int8 codes from fixed SRQ into one u32 word for the parallel GEMV. The GEMV side restores `f32(code) × scale` and feeds the existing f32 multiply-accumulate, so it is bit-identical to the existing path (only -0.0 / NaN excepted)                                                                                                       | ADR [0105](decisions/0105-packed-static-quantize-activations.md)                                                                                                                                                  |
| fake-quant                           | Rounding weights to the quantization grid and keeping them as f32. Refers to the rounding step before the exporter writes them                                                                                                                                                                                                                                            | `tools/exporter/src/karume/quantize.py`                                                                                                                                                                           |
| Quality measurement (`quality.json`) | The record left in the series: the difference (quantization error) between the f32 output before rounding and the output of the rounded weights, measured with torch on CPU at export. Zero when the storage dtype is the same as upstream's; for a lossy one, a mean absolute difference of α < 0.5 LSB (provisional threshold) is the check before publication          | ADR [0113](decisions/0113-birefnet-weight-series.md) decisions 4, 5                                                                                                                                               |
| Preset derivation rule (BiRefNet)    | The rule that derives the presets of each checkpoint from the storage type of the upstream checkpoint. No preset wider than the upstream storage is shipped, and the default preset is the one whose type equals the storage (BiRefNet_HR = `f16` only; Lucida = `f32` default + `f16`). Distribution assembly and export call the same function (`birefnet_seat_dtypes`) | ADR [0113](decisions/0113-birefnet-weight-series.md) addendum 2026-10-11                                                                                                                                          |
| RTN (Round To Nearest)               | Round-to-nearest without calibration. i8 is per-channel symmetric, i4 is grouped along K                                                                                                                                                                                                                                                                                  | ADR [0019](decisions/0019-i8-weight-execution.md), [0069](decisions/0069-packed-w4-storage.md)                                                                                                                    |
| GPTQ                                 | A method that corrects the rounding with calibration data. What Karume ships is the `grid="rtn"` variant, whose grid is exactly the RTN grid, so its stored form is the i4 preset itself                                                                                                                                                                                  | [perf-ledger](perf-ledger.md) Q-6, `tools/exporter/src/karume/quant_calib.py`                                                                                                                                     |
| Fixed quantization (importing QAT)   | The path that writes the upstream checkpoint's integers and scales as they are, without requantizing. Its entry is separate from automatic quantization (fake-quant → storage)                                                                                                                                                                                            | ADR [0097 addendum 3](decisions/0097-gemma4-qat-integration.md#addendum-3-2026-09-11--fixed-quantization-writer-entry)                                                                                            |

## Op vocabulary

| Term                     | Meaning (summary)                                                                                                                                                                                                                                                                                                                                                                                                                                    | Source                                                                                                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entry door               | The single test that decides whether adding an op to the IR vocabulary needs an ADR: Core ATen membership, measured as `torch.Tag.core in op.tags`. Core ops and their attr variants enter with a ledger NOTE only; everything else (non-core aten, torchvision, Karume's own names) needs an ADR. ADR 0064 adds two axes: the semantic scope is stated, and an addition that breaks an execution-model invariant needs an ADR even inside Core ATen | ADR [0059](decisions/0059-op-vocabulary-entry-doors.md) decisions 1, 2, [0064](decisions/0064-entry-door-generality-axes.md), procedure: [op-vocabulary](op-vocabulary.md) |
| Export-eliminated layer  | Ops that never reach the runtime: values that are export-time constants are folded (`FOLDABLE_OPS`), and exact compositions of existing primitives are decomposed by the normalize / convert passes (old layer 0). No procedure; the cheapest way out                                                                                                                                                                                                | ADR [0059](decisions/0059-op-vocabulary-entry-doors.md) decision 1, [op-vocabulary](op-vocabulary.md)                                                                      |
| Extended atomic layer    | Non-core ops in the IR vocabulary that **cannot** be written as an exact equivalent from other ops of the vocabulary (old layer 1′). The ADR is the proof that the op cannot be avoided (`deform_conv2d`); the requester (IR mechanism or model) does not change the door                                                                                                                                                                            | ADR [0059](decisions/0059-op-vocabulary-entry-doors.md) decisions 1, 3, [0064](decisions/0064-entry-door-generality-axes.md)                                               |
| Extended composite layer | Non-core ops in the IR vocabulary that can be written from other ops but are kept for performance or meaning (the rest of old layer 2). The ADR gives the measured reason under at least one of entry conditions ① to ④ (`gru_scan`); the 9 non-core ops whose decomposition is forbidden belong here                                                                                                                                                                | ADR [0059](decisions/0059-op-vocabulary-entry-doors.md) decisions 1, 3, 5, [0064](decisions/0064-entry-door-generality-axes.md)                                            |
| Gated DeltaNet (GDN) | A linear-attention layer whose state is a dk × dv matrix per value head, updated per token by the gated delta rule: decay the state by `exp(g)`, then a rank-1 correction toward `v` with strength `beta`; the output reads the updated state with q. Used by Qwen3.5-class models (24 of the 32 layers of the MOSS-Image text encoder) | ADR [0135](decisions/0135-gated-delta-rule-scan.md) context |
| `gated_delta_scan` | The proposed extended composite op for the GDN recurrence: `(q, k, v, g, beta) → o`, arity 5, f32, empty attrs; q / k already l2-normalised, the head broadcast `⌊h/r⌋` and the `dk^-½` scale derived inside, zero initial state. Decode is its states form | ADR [0135](decisions/0135-gated-delta-rule-scan.md) decisions 1, 4 |
| Sequential scan (GDN) | The kernel form that walks the tokens one by one with the state in registers; in form (a2) one value column is split over 8 threads by key slices (the key split, part of the numerics), with one workgroup exchange per token. The op's kernel for every T | ADR [0135](decisions/0135-gated-delta-rule-scan.md) decision 3, [research 2026-10-27](research/2026-10-27-gdn-scan-spike.md) §2 |
| Blocked scan (GDN) | Form (a3): the sequential state in registers advanced 8 or 16 tokens at a time with the UT transform, plus a small prep dispatch. Faster at long T but rounds differently from the sequential scan; a performance candidate only | ADR [0135](decisions/0135-gated-delta-rule-scan.md) decision 3, [research 2026-10-27](research/2026-10-27-gdn-scan-spike.md) §2 |
| Chunked scan (WY / UT form) | Upstream's prefill algorithm: 64-token chunks, a triangular solve per chunk, a sequential pass over chunk states and an output pass (3 dispatches). Rejected on the RTX 3080 Ti (slower at every T, 320.5 MiB of scratch per layer at T = 4096) | ADR [0135](decisions/0135-gated-delta-rule-scan.md) decision 3, [research 2026-10-27](research/2026-10-27-gdn-scan-spike.md) §2 |
| Accurate exp | A range-reduced polynomial `exp` in WGSL (at most 1 ULP on the long-memory range, measured) used instead of the built-in `exp`, whose bias (mean −0.34 ULP on [−0.1, 0) on the RTX 3080 Ti) accumulates in a per-step product of decays. MUST in the GDN scan | ADR [0135](decisions/0135-gated-delta-rule-scan.md) decision 3, [research 2026-10-27](research/2026-10-27-gdn-scan-spike.md) §5.4 |

## Distribution container (`krm` / `krg`)

> [ADR 0108](decisions/0108-container-format.md) and [container-v1](container-v1.md) are **accepted**, and
> the container is the only distribution (the old distribution — one safetensors file / a shard list —
> is read only by the migration CLI).
> Words of the old distribution (shard, the spelling of piece keys) stay in their rows, marked "old".

| Term                                             | Meaning (summary)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Source                                                                                                                                                                                                                         |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Container                                        | Karume's own distribution that holds graphs, weights, scales and assets in one physical format. It replaced the old distribution (one safetensors file / a shard list + `__metadata__.karume_ir`)                                                                                                                                                                                                                                                                                                                                              | [container-v1](container-v1.md), ADR [0108](decisions/0108-container-format.md)                                                                                                                                                |
| `krm`                                            | A container with weight blocks (model) = graph + trained weights + scales + assets. Its magic is `KRMC`                                                                                                                                                                                                                                                                                                                                                                                                                                        | ADR [0108](decisions/0108-container-format.md) decision 1, [container-v1](container-v1.md) §1                                                                                                                                  |
| `krg`                                            | A container **without** weight blocks (graph). It is extracted from a `krm` by rewriting only the header and copying bytes, so identity can be decided by content hash (not by name, nor by "same architecture")                                                                                                                                                                                                                                                                                                                               | ADR [0108](decisions/0108-container-format.md) decisions 1 / 4, [container-v1](container-v1.md) §9                                                                                                                             |
| Descriptor (graph descriptor / model descriptor) | The two JSON documents at the start of the container. Graph descriptor = `graphs` (IR v2) + table of contents of the const region + `capabilities`; model descriptor = binding table + table of contents of blocks / parts + `provenance`. It holds no execution defaults (`session` / `requiredLimits` and so on)                                                                                                                                                                                                                             | ADR [0108](decisions/0108-container-format.md) decision 2, [container-v1](container-v1.md) §2                                                                                                                                  |
| Const region                                     | A dedicated section for weight-independent constants (results of constant folding, values from the config). **Owned by the graph descriptor**; block offsets are relative to the start of the region. In the split form, part 1 is this region                                                                                                                                                                                                                                                                                                 | ADR [0108](decisions/0108-container-format.md) decision 3, [container-v1](container-v1.md) §3                                                                                                                                  |
| Block                                            | **The unit of fetch, verification and release**. It does not cross parts; its length is at most 32 MiB and a multiple of 4, and the writer bakes the tail padding (the sha256 includes the padding)                                                                                                                                                                                                                                                                                                                                            | ADR [0108](decisions/0108-container-format.md) decisions 5 / 7, [container-v1](container-v1.md) §4                                                                                                                             |
| Part                                             | **The delivery granularity** (not the holder in host RAM — that is the block). Part 0 = header + descriptor, part 1 = const region, part 2 onward = weights / assets. The writer chooses its length from `{256, 512, 768, 1024} MiB` (default 256 MiB)                                                                                                                                                                                                                                                                                         | ADR [0108](decisions/0108-container-format.md) decision 6, [container-v1](container-v1.md) §4                                                                                                                                  |
| Binding table                                    | The map `(graph name, initializer name)` → supply of the weight. Held by the model descriptor. A `krg` has no weight binding table; only the const binding table, held by the graph descriptor                                                                                                                                                                                                                                                                                                                                                 | ADR [0108](decisions/0108-container-format.md) decision 1, [container-v1](container-v1.md) §5                                                                                                                                  |
| Supply form / shared declaration                 | A binding-table value has one form only, the supply form = `block` (or `pieces`) + `encoding`, with which this container supplies the data. Borrowing from another Session is held only by the `{ "shared": true }` declaration on the IR side and lies outside the set reconciled against the binding table (written into the binding table, it fails loudly as surplus)                                                                                                                                                                      | [container-v1](container-v1.md) §5, [ir-v2](ir-v2.md) "Shared initializers"                                                                                                                                                    |
| Codec                                            | A registered name that bundles a quantized storage's packing, value range, scale shape and dequantization formula (`int8-sym` / `int4-sym-g` / `int2-off` / `ternary`). It replaced the enumeration of the old `storage.dtype`                                                                                                                                                                                                                                                                                                                 | ADR [0108](decisions/0108-container-format.md) decisions 12 / 13, [container-v1](container-v1.md) §6                                                                                                                           |
| Codec ledger                                     | The **storage format** of the codecs (decode path, packing, whether a scale is needed, group granularity, accepted `rowAxis`) kept in one place as **immutable data in the repository** (no registration at import). It holds neither CPU decoding nor executability — ownership is split per axis: ② whether it can run = `RUNTIME_SUPPORT.storage`, ③ the ops that can keep it compressed and resident = the runtime's eligibility predicates                                                                                                | ADR [0108](decisions/0108-container-format.md) decision 12, addendum 12, [container-v1](container-v1.md) §6.2                                                                                                                  |
| `encoding`                                       | The supply description that each binding-table entry carries (`codec` / `packing` / `rowAxis` / `groupSize` / `scale` / `zeroPoint`)                                                                                                                                                                                                                                                                                                                                                                                                           | [container-v1](container-v1.md) §6                                                                                                                                                                                             |
| `packing`                                        | The element count `blockElements` and byte count `blockBytes` that one packing block carries, and the alignment of the payload start `alignBytes`. **The bit width is derived from these** and is not declared                                                                                                                                                                                                                                                                                                                                 | ADR [0108](decisions/0108-container-format.md) decision 10, [container-v1](container-v1.md) §6                                                                                                                                 |
| Layout (decode path)                             | The kind of the runtime's dequantization path, derived from the codec ledger's registered name (`f32` / `f16` / `bf16` / `i32` / `i8` / `i4` / `i2`). `ternary` uses the same `i2` path as `int2-off`. The public API `codecLayout(codec)` reads it                                                                                                                                                                                                                                                                                            | [codecs.ts](../packages/runtime/src/format/container/codecs.ts)                                                                                                                                                                |
| `rowAxis`                                        | The axis that is the scale's "row" (`0` or `1`). The field that brings the per-channel axis of i8 / i2 into the declaration; for GPU-resident presets it is checked against the axis derived from the consuming op (`weightChannelAxes`), and a mismatch fails before any weight is fetched (presets that decode to f32 dequantize with the declared axis). Only i8 of `conv_transpose1d` takes `1`                                                                                                                                            | ADR [0108](decisions/0108-container-format.md) decision 11, [container-v1](container-v1.md) §6                                                                                                                                 |
| `groupSize`                                      | The number of consecutive elements along a row that one scale covers. Equal to the row length = per-channel. The scale's shape is the rank 2 group shape `[shape[rowAxis], row length / groupSize]`                                                                                                                                                                                                                                                                                                                                            | ADR [0108](decisions/0108-container-format.md) decision 11, [container-v1](container-v1.md) §6                                                                                                                                 |
| Ternary                                          | A codec with the value range `{−1, 0, +1}`. Its packing and dequantization are **exactly identical** to `int2-off` and the runtime adds zero lines, but it is declared under its own name **to identify the asset** (the real i2 assets are **not** ternary — `q = −2` occurs 5.8–7.4 %)                                                                                                                                                                                                                                                       | ADR [0108](decisions/0108-container-format.md) decision 13, [container-v1](container-v1.md) §6                                                                                                                                 |
| Scale-ledger uniqueness                          | The rule that one weight has one scale ledger and, once it is fixed at rounding, it is not recomputed. Stored values are quantized with the fixed scale passed in. Ternary absmean is not idempotent (it has no fixed point), so this rule, not idempotency, forbids double rounding and recomputation                                                                                                                                                                                                                                         | ADR [0108](decisions/0108-container-format.md) addendum 9                                                                                                                                                                      |
| Bit-plane decomposition                          | A reserved scheme for odd bit widths (3 / 5 / 6 / 7). 32 elements are laid out as `bits` u32 words, one "plane" each (bit `j` of word `b` = bit `b` of element `j`). Only the ledger entry shape is reserved; implementation starts from the width that is first needed                                                                                                                                                                                                                                                                        | ADR [0108](decisions/0108-container-format.md) decision 14, [container-v1](container-v1.md) §6                                                                                                                                 |
| Single form / split form                         | All parts concatenated into one file / each part split into its own file. The byte order is the same; the only difference is "whether there are cuts". The official HF distribution uses the split form only                                                                                                                                                                                                                                                                                                                                   | ADR [0108](decisions/0108-container-format.md) decision 3, [container-v1](container-v1.md) §8                                                                                                                                  |
| Scan-type / seek-type sources                    | The two forms in which the hub's fetch surface reads blocks. Seek type = a positional read per block (local, the browser's Blob) / scan type = reads a whole part into the **holding slot** (one part) and cuts blocks as views of that buffer (Deno and Node via HF). Only the scan type's RAM peak scales with the part length                                                                                                                                                                                                             | ADR [0109](decisions/0109-manifest-v5-container.md) decision 7, [0108](decisions/0108-container-format.md) addendum 5, [container-v1](container-v1.md) §11                                                                     |
| Verified / unverified source                     | Whether the source has already verified the part's bytes (`BlockSource.verified`). Verified = paths where the fetch layer compared the whole file's sha256 with the record (HF cold / warm), and no block sha256 is computed / unverified = local directories, whole bytes and part lists, where every block read reads the whole block and computes its sha256                                                                                                                                                                                | ADR [0109](decisions/0109-manifest-v5-container.md) decision 7, [container-v1](container-v1.md) §7                                                                                                                             |
| Merged concurrent fetches (single-flight)        | The mechanism by which the fetch layer (`@hdae/fetch-cache`) merges concurrent whole-file fetches for the same content key within a process into one. Later callers receive the first caller's bytes, and their `caches`, auth headers and `fetch` are not used (a later caller re-verifies with its own sha256). Warming (prefetch) is not covered                                                                                                                                                                                            | ADR [0080](decisions/0080-hub-fetch-cache-050.md) addendum 2026-10-10, "hub: the cache is not isolated by credential" in `docs/limitations.md`                                                                                 |
