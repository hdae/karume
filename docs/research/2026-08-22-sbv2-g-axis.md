# SBV2 net_g の g 軸評価（波 J-3）

> 性格: **時点スナップショット**（2026-08-22 実測・聴感裁定込み）。裁定の正本は ADR
> [0069](../decisions/0069-packed-w4-storage.md) 追記 9。リグ = `sbv2/measure_quant.py`
> （`--w4-group-size` — `e813b8c` で g 引数化）。

## §1 何を決めるための実測か

波 I の方式スクリーニングは g=32 固定の裁定（ADR 0069 追記 5）で、方式確定後の g 軸再評価が
J-3。評価軸は「`w4` の f32 比〈テンション少し低め〉（波 J-5b 聴感）が g を細かくして縮むか」 —
net_g の conv は GPTQ 不適（H が linear の in 軸形）で、**g が唯一の品質ノブ**だった。掃引点は
g16 / g32 / g64 の 3 点。g128 は実験前に棄却（実資産走査の事前試算で適格要素が 55% に減り、
非適格の i8 残留でサイズも g32 比 +18% と自滅 — 品質・容量の両面で負け筋しかない）。

## §2 測定条件

- FN4 dump（`outputs/demo.old/sbv2-dump/dump.safetensors` — 波 I と同一・同一乱数列）。
  BERT は f32 固定（net_g の g 効果だけを分離）。丸めは RTN = sbv2 の出荷丸めと同一
  （sbv2 recipe に校正は無いので fake-quant がそのまま出荷等価）。
- 実行（`tools/export-recipes` で）:

  ```sh
  uv run --no-sync python -m sbv2.measure_quant --configs w4-rtn \
      --dump <dump> --reference-wav <reference.wav> \
      --w4-group-size {16,32,64} --out outputs/demo/quant-sim-j3-g{16,32,64}
  ```

- **リグ改修の無回帰**: g32 の `w4-rtn.wav` が波 I 産の現物（`outputs/demo.old/quant-sim/`）
  とバイト一致（sha256 `d991d9b0…`）。gates all green（f32 と `reference.wav` のバイト一致
  門込み）。
- **混成セル**（g16 格子 × g32 適格集合）はリグの公開関数の組み合わせで測定 —
  `census_w4_targets(root, roles, 32)` の include を `w4_methods(16)` の apply へ渡して
  `run_config` を駆動（リポ変更なし）。駆動検算 = この駆動の f32.wav が掃引の f32.wav と
  バイト一致。

## §3 結果（f32 波形比）

| セル                        | SNR (dB)  | LSD (dB) | 振幅比 (relRMS) |
| --------------------------- | --------- | -------- | --------------- |
| **g32（現行）**             | **−0.38** | **5.54** | **1.044**       |
| g16（素 — 適格 19 本増）    | −3.90     | 6.28     | 1.567           |
| g16 格子 × g32 集合（混成） | −3.88     | 5.74     | 1.563           |
| g64（適格 22 本減）         | −1.67     | 5.82     | 1.211           |

- **適格集合は g で変わる**（行長の g 整除が適格条件）: g16 では decoder 末尾（16ch
  resblock 12/13 と `dec.conv_post` — 受容野が 32 非整除・16 整除）の 19 本が voice 側で
  新規適格、g64 では 22 本が除外へ（front は 3 点とも 65 本で不変）。
- 混成セルが素の g16 とほぼ同値 → 「g16 悪化は新規適格の decoder 末尾のせい」仮説は**反証**。

## §4 重みレベルの忠実度（配管バグの排除）

適格集合を g32 に固定した relRMS(ΔW)/RMS(W):

| 対象            | g16        | g32    |
| --------------- | ---------- | ------ |
| front（65 本）  | **0.0894** | 0.1046 |
| voice（235 本） | **0.0925** | 0.1109 |

g16 ⊂ g32 の入れ子分割なので g16 ≤ g32 は数学的にも保証され、実測も約 −15% 良い —
波形指標の逆順は配管では説明できない。

## §5 読み取り

1. **波形の f32 同一性指標は g の順序を運ばない。** 重みが良くなっても（g16）波形指標は
   悪化し、悪くなっても（g64）g16 より良い。flow / decoder が微小な重み差をカオス的に増幅
   する。波 I の注記（SNR/LSD は位相・長さずれに弱く最終判定は聴感）の g 軸版の実証。
2. サイズは算術確定: bpw = 4 + 32/g → g16 = i4 部 **+20%**（5.0 → 6.0 bpw）・g64 = −10%
   （+ 適格減の i8 残留分だけ目減り）。

## §6 聴感裁定（2026-08-22 ユーザー）— g32 据え置きで確定

> g16 系は逆にテンション高くなってるね、一番差異が小さいのは現行という形になる。
> 実際現行のが違うというのも多分ブラインドテストで分からないレベルなので、維持でいい
> かもしれません。

- **裁定 = g32 据え置き・J-3（SBV2 側）クローズ**。g16 はテンションを**逆方向**（高い側）へ
  動かす — 振幅比 1.56 が方向まで含めて予告どおり（波 I の「振幅比は音量系劣化の予告指標」に
  整合）。3 点中 f32 に最も近いのは現行 g32 で、既定はこの軸で既に最適だった。
- 含意: net_g の「テンション少し低め」は **g 軸では縮まない**。conv は GPTQ 不適のままなので、
  残る経路は conv の校正付き丸め（im2col 級の別実装）だけ — 実需が出るまで寝かせる。
