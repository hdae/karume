## P-1 — `quantize_rows` の小 D 変種（採用・`3175161`）

- 実装: 行長から幾何を決める（パス② の quad 数以上の最小の 2 のべきをレーン幅・余りで別の行を
  同じ workgroup に並べて畳む）。1 行が 256 レーンを使い切る行長（linear の K）は従来形のまま
  （キー・WGSL 不変）。並べ畳む形はキー `:r<行数>w<幅>`。
- 方法: anima 1024²（turbo-v1.1・既定 quant・4 step・seed 1）を gpuTiming ON で回し、
  `onRunDiagnostics` の op 別 GPU ns をキー接頭辞 `quantize_rows` で集計。変種 off は
  `quantizeRowsGeometry` を常に幅 256 へ固定した写しで同じ台本（ABBA・各 2 回）。

|                                      |                      従来形（off） |                変種（on） |
| ------------------------------------ | ---------------------------------: | ------------------------: |
| quantize_rows 合計                   | 228.1 / 229.8 ms（2,488 dispatch） |          134.4 / 136.4 ms |
| うち linear（wg256・K ≥ 1024）       |                                  — | 104.7 / 106.1 ms（1,584） |
| うち短い行（r8w32 + r4w64 + r2w128） |                    ≈ 123 ms（904） |     29.5 / 30.3 ms（904） |
| 全 GPU（4 step）                     |                   4,676 / 4,713 ms |          4,506 / 4,665 ms |

短い行の部分は **×4.1**（kill 線 ×1.3）。全 GPU では −2%（起票の見込み −3% と同じ桁）。数値契約は
幾何 4 通り（r8w32 / r16w16 / r32w8 / r128w2）× 縮退経路で従来形と q / scale がビット同一
（`gpu_i8a8_test.ts`）。

## P-2 — `BatchScope.settle()`（採用 — 壁時計の利得は未証明・`e7b4489`）

- 実装: batch 区間の最初の 1 実行の後にフェンス 1 本を張り、そこまでの実測でチャンク推定を
  裏付ける（区間の間ずっと初期値 16 に据え置かれていた）。irodori の DiT ループで step 0 の
  最初の forward 後に 1 回。
- 方法: irodori v4-small / f32・`fromPretrained(denoDirectory)`・ウォームアップ 1 回の後に 1 生成を
  壁時計で計測（gpuTiming OFF・`onRunDiagnostics` で dit の `submit` 統計）。ABBA 5 対。

| 条件                                    | submit（off → on） | 壁 off（中央値） | 壁 on（中央値） |                                差 |
| --------------------------------------- | -----------------: | ---------------: | --------------: | --------------------------------: |
| voice-clone（参照 + caption・CFG 3 本） |        8,000 → 377 |        10,888 ms |       10,632 ms | −2.4%（平均 −1〜−4.7%・外れ値 1） |
| no-ref（参照なし・caption なし）        |        4,800 → 257 |         6,254 ms |        6,163 ms |               −1.5%（平均 −3.1%） |

submit は −95% だが、壁は両条件とも走間の揺れ（±3〜5%）の内側。この区間は GPU 律速で、ホストの
submit 費用（≈0.5 ms/回）は GPU 実行の裏に隠れる。kill 線「1/10 でも壁 ±1% 以内なら不採用」に
ほぼ該当するが、**ユーザー裁定（2026-09-03）= 無害（フェンス 1 本・fail loud のガード・テスト済み）
なので残す**。ホスト費用が露出する条件（ブラウザの Dawn 越し・低速 CPU）での追試は未実施
（irodori のブラウザ面が無い）。

## P-3 — anima VAE タイルの整除制約撤廃（採用・`9591783`）

- 実装: 本数 = `ceil(span / (tile − minOverlap)) + 1`・開始位置 = 丸め等間隔。本数が変わらない辺は
  配置も同一（1024² / 512² / 1344×768 系はバイト不変 — フルテストの PNG sha 門緑）。
- 方法: 1824×1248（turbo-v1.1 / f16・2 step・seed 42）を gpuTiming ON で回し、`vae_decoder` の
  run（= タイル）ごとの GPU ns を合計。旧コードは `9591783^` の `anima/{tiling,resolution,pipeline}.ts`
  を一時的に置いて同じ台本（ABBA・各 2 回）。

|                     |  旧規則（15 枚） |  新規則（12 枚） |
| ------------------- | ---------------: | ---------------: |
| VAE decode GPU 時間 | 2,322 / 2,615 ms | 1,778 / 2,078 ms |
| 壁（2 step 全体）   |    19.1 / 20.4 s |    18.6 / 20.6 s |

平均 **−22%**（kill 線 −10%・起票の見込み −20%）。視認裁定（2026-09-03・ユーザー）: 1824×1248 の
旧 / 新 × seed 42〜45 × プロンプト 2 種と、復帰した 8 解像度（1456 / 1488 / 1584 / 1648 / 1680 /
1776 / 1840 / 1936 × 1024）× seed 42・43 × 2 種で**継ぎ目なし・OK**。素材 =
`outputs/bench/karume-anima/2026-09-03_p3-tiles/{old,new}/` + `index.html`（git 追跡外）。
