## 0. 結論サマリ（先に読むところ）

1. **需要は実在する**。1024px turbo w8a8 では attention が DiT GPU の **46%（1,110ms/2,415ms）**
   で次の支配項（`examples/anima/README.md:144-151`）。本 recon で **qk / stats / pv の内訳を
   実測ファイルから初めて確定**した（既存 doc は「内訳は記録されていない」と書いていた —
   `docs/research/2026-08-03-shader-f16-recon.md:183-186`）:
   **qk 44.2% / stats 7.3% / pv 48.5%**（`models/anima-demo/out/turbo-i8-1024-seed42.json`）。
   → **dp4a 化の対象（qk + pv）は attention の 92.7%**。stats は対象外で正しい。
2. **QK 側は「ほぼ書き写し」で成立する**。q / k とも縮約軸 = D が最内連続なので、
   **既存 `quantize_rows` を 1 バイトも変えずに 2 回呼ぶだけ**で per-token i8 が得られ、
   GEMM は `linear-i8a8` の構造そのまま（`xs[row]·wscale[col]` → `qs[row]·ks[col]`）。
   **数値契約も linear と同じ atol=0 が立つ**（整数厳密縮約 + f32 演算 5 個）。
3. **PV 側が本設計の唯一の難所**。P̃ = exp(S−m) は**行内 max が構造的に 1.0** なので、
   per-token scale は **1/127 に縮退**する（amax を取っても同じ値になる = 適応の余地がゼロ）。
   したがって PV の量子化 SNR は **行の peak/rms がそのまま決める**:
   `relRMS ≈ (peak/rms)/(127·√12)`。attention が平坦な行なら 0.2%、鋭い行（有効幅 1 本）なら
   **14%** 程度まで悪化する【試算】。**ここが Q0 で測るべき唯一の本質**で、
   「PV は P が [0,1] なので量子化しやすい」（shader-f16 recon §7 隣接②）という前提は
   **半分しか正しくない**（値域は狭いが**行内ダイナミックレンジが広い**）。
4. **V の量子化軸は per-column（N 方向の amax）でなければならない**（per-token は縮約軸上で
   scale が変わり総和から括り出せない）。ただし**新カーネルは要らない** — 既存 `strided`
   （permute）で Vᵀ[B·H, D, N] を作り、その上で `quantize_rows` を呼べば「per-column 量子化 +
   dp4a が要求する N 連続パック」が同時に得られる。
5. **期待効果**【試算】: linear の 3.44×（1024px 実測換算）をそのまま外挿しない前提で、
   **2.0× 想定なら DiT GPU −20.4%（2,415 → 1,922ms/step）・壁時計 36.5 → 約 31.6s**。
   QK のみなら −9.6%。上界（linear 同等 3.44×）でも −29.3% で、**桁は変わらない**。
6. **適用範囲は Anima DiT のみ**。VAE decoder は融合 attention を持つが 1024px で 112ms/1,989ms
   （5.6%）と小さく、画質直撃なので対象外を推奨。**SBV2 / DeBERTa は融合 attention op を
   そもそも使っていない**（`export_*.py` が SDPA を分解する）ため、ADR 0025 決定⑤の
   「他モデル検証」に相当する受け皿が **attention a8 には存在しない**。
7. **プロトタイプに attention の int8 実装・実測は無い**（flash 型 f32 のみ）。
   今回は全面的に Karume 側の新規設計で、外挿できる先行実測は無い。

**推奨: 案 B（QK + PV）を「波 Q0 → 波 1（QK）→ 波 2（PV）」の段階で。Q0 で PV が落ちたら
QK のみ（案 A）へ縮退**。詳細は §5。

### 1.4 律速の読み（既存 recon の再確認）

`docs/research/2026-08-03-shader-f16-recon.md:194-237` の結論をそのまま引く:
attention は **ALU ピークの約 20%・DRAM ピークの約 10%** しか使っておらず、律速は
**内側ループの共有帯域 / 命令発行**。内側ループは共有ロード 5 回で 16 MAC = **2 B/MAC**
（`src/kernels/gemm.ts:611-640`）。dp4a はここを **1/4 バイト × 1 命令 4 MAC** に置き換える
（`src/kernels/linear-i8a8.ts:233-247`）ので、linear で 3.44× 出た機序が attention にも
そのまま効くと読める【推測・ただし linear の実測が直接の裏付け】。

**DRAM の床**【試算】: 1024px の attention DRAM は S 書き 1 + stats 読み 1 + PV 読み 1 の
3 パス換算で **101.5GB/step**（f16 recon §3.2 と同じ数え方）。912 GB/s で **111ms** が床。
現状 1,110ms はその 10 倍なので、**DRAM は 3〜4× の高速化を阻む位置には無い**（後述の
上界シナリオ 402ms でも床の 3.6 倍）。

## 2. 設計の核心 — 3 つの構造的事実

### 2.1 【QK】q / k は「縮約軸が最内連続」なので linear と完全に同型

`S[b,m,n] = Σ_d q[b,m,d]·k[b,n,d]`。q は `[B·H, M, D]`・k は `[B·H, N, D]` で、**縮約軸 D が
両方とも最内連続**。linear の `x[m,k]`（k 連続）× `w[n,k]`（k 連続）と**添字の形が一致する**。

- 量子化: `quantize_rows(q, rows = B·H·M, dim = D)` と `quantize_rows(k, rows = B·H·N, dim = D)`。
  **新カーネル 0 本**。
- 内積: `acc[i32] = Σ_d qq·kq`（`dot4I8Packed`）。`|acc| ≤ D·127² = 2,064,512`（D=128）で
  i32 上限の 0.1%。
- dequant: `S = f32(acc) · (qs'[row] · ks'[col])`。ここで
  **`qs' = qs·scale` / `ks' = ks·scale`**（半スケール契約をそのまま行/列ループ不変の
  2 回の乗算として畳む — `prologueA` / `prologueBLinear` と同じ位置）。
- **半スケールの畳み先の裁定**: i8 経路では「分解経路とのビット同一」という半スケール契約の
  _目的_ が消える（ADR 0023 決定 2 の (b) は f32 変種の性質）。したがって **attrs の契約は
  一切変えず**（`scale` は引き続き √scale）、i8 経路では
  **量子化の前ではなく dequant の側へ 2 回掛ける**のが正しい。
  量子化の前に掛ける形（`q·scale` を量子化）は **amax も同じ倍率で動くので整数値はほぼ同じだが
  f32 丸めが 1 段増えるだけの純損**で、しかも `quantize_rows` を無改変で使えなくなる。

### 2.2 【PV】P̃ の per-token scale は 1/127 に**構造的に縮退する**

`P̃_ij = exp(S_ij − m_i)` は `m_i = amax_j S_ij` なので **行内 max が厳密に 1.0**
（`exp(0) = 1` は f32 で厳密）。したがって:

- per-token（行）amax 量子化を掛けても **`s = 1/127` にしかならない**。
  「行ごとに適応する」という per-token 量子化の利点が**ゼロになる**唯一のテンソル。
- 量子化列は `q_P = round(127 · exp(S−m))`（clamp 上限 127 は構造的に到達不能・
  `quantize_rows` の clamp と同じ性質）。**除算が 1 つも要らない**（2.5ULP 問題の外）。
- `1/l`（= `row_inv`）は **dequant 側へ移せる**: `O = f32(acc) · ( (inv_i·(1/127)) · vs[d] )`。
  `inv_i·(1/127)` は行ループ不変なので prologue で 1 回。**linear の `xs·wscale` と同型**。
- **P は実体化しない**まま（A タイル充填で `exp → ×127 → round → pack4xI8`）。
  新しいバッファも新しい dispatch も要らない。ADR 0023 の「P 非実体化」がそのまま保たれる。

**品質上の帰結（本設計で最大のリスク）**: 量子化誤差の相対値は
`relRMS(P̃) ≈ (peak/rms)/(127·√12)`（ADR 0025 の層別誤差が中央値 1.8% で一致した理論式
`peak/(127·√12)` — `0025:22-25` — をそのまま行に適用したもの）。P̃ の peak は常に 1 なので、
`peak/rms = √(N / Σ_j P̃_ij²)` が**そのまま SNR を決める**。

| 行の attention 分布       | peak/rms | 予測 relRMS【試算】 |
| ------------------------- | -------: | ------------------: |
| ほぼ一様（P̃ ≈ 1 が N 本） |      1.0 |               0.23% |
| 有効幅 64 本（N=4096）    |      8.0 |                1.8% |
| 有効幅 16 本              |     16.0 |                3.6% |
| ほぼ 1 点集中             |     64.0 |           **14.5%** |

比較: linear の w8a8 は入力活性の `peak/rms` 実測が理論値 `peak/440` に中央値 1.8% で一致し、
**relRMS 中央値は 1e-2 級**（外れ値は modulation 後と GELU 後で peak 32〜56 = relRMS 7〜13% —
`0025:22-25`）。つまり **「有効幅 16 本」相当までなら既に受理された w8a8 と同じ土俵**で、
**1 点集中の行が多いと linear の外れ値層より悪くなる**。

→ **Q0 で測るべき第一の量は「DiT 全 56 attention の行ごとの P̃ peak/rms 分布」**。
これは GPU コード 0 行・DiT 1 forward で取れる（§4）。

### 2.3 【PV】V の量子化軸は per-column（N 方向）でなければならない — が新カーネルは要らない

`O[m,d] = Σ_n P[m,n]·V[n,d]`。縮約軸は **n**。
`f32(acc)·s` 形が成立する条件は **s が縮約軸 n に依存しないこと**なので、
V の scale は **d ごと（= 出力列ごと）に N 全体の amax** で作る必要がある。
per-token（= V の行 n ごと）にすると **scale が縮約軸上で変わり括り出せない**
（黙って使うと沈黙の誤値。linear で `wcol` を行に流用する誤りと同型の罠 — ADR 0024 の MUST④）。

さらに dp4a は **縮約軸方向に 4 要素をパック**するので、V^q は
**`[B·H, D, N]`（N 連続）= Vᵀ のレイアウト**でなければならない
（linear の重み `[n,k]`（k 連続）と同じ形 — `linear-i8a8.ts:204`）。

**新カーネルを作らない解**:

```
① strided（既存の permute カーネル）: v[B·H,N,D] → vT[B·H,D,N]   （f32・33.55MB/層）
② quantize_rows（既存・無改変）:      vT を rows = B·H·D, dim = N で量子化
                                       → vq[B·H,D,N/4 語] + vs[B·H·D]
```

②の「行」= `(b,h,d)` なので、**per-column(N) 量子化が自動的に得られる**。
`dim % 4 == 0` は `N % 4 == 0` に対応（実測形は全て満たす）。
コストは f32 33.55MB の読み書き 1 往復 + 2 パス量子化 = **1 層あたり約 130MB**【試算】。

> 代替（新カーネル 1 本を作る案）: 共有メモリ 64×64 タイル転置 + 列 amax + 量子化を 1 dispatch に
> 融合。dispatch が 56 本減り DRAM も 1 往復減るが、**grid-stride 縮退ハーネス / full-write /
> NaN 規律を 1 から作る**ことになる。**波 2 の後段の最適化として温存**を推奨（§7 実装波）。

**案 B は案 A を構造的に内包する**（同じノブ・同じ量子化基盤・波が分かれるだけ）ので、
「A か B か」は**排他の選択ではなく Q0 の結果で決まる終点**である。

**却下した案**（記録）:

- **P を i8 で実体化する案**: ②stats の後に「S と stats を読んで P^i8 を書く」dispatch を足す形。
  1024px self で 268MB の新バッファ + 56 dispatch を足して、DRAM は
  `S 読み 1.07GB + P 書き 0.27 + P 読み 0.54 = 1.88GB` と現状の `S 読み ×2 = 2.15GB` から
  13% しか減らない【試算】。**exp の再評価（D/64 = 2 回）を消せる**利点はあるが、
  ADR 0023 の「P 非実体化」を捨てる代償に見合わない。→ **タイル充填で丸める案（§2.2）を採る**。
- **V を per-tensor scale にする案**: 転置は結局必要（パック方向の要請）なので**簡略化にならず**、
  品質だけ落ちる。
- **PV の per-K-block scale（SageAttention 型）**: K タイル 16 列ごとに局所 amax を取り、
  タイルごとに f32 へ dequant して f32 累積する形。**§2.2 の縮退を回避できる唯一の構造**だが、
  ①タイル内の行 amax を 4 スレッド跨ぎで縮約する barrier が要る ②`f32(acc)·s` の 1 回 dequant
  という単純さが失われる ③縮約が f32 になり順序依存が復活する。
  → **Q0 で素の 1/127 格子が落ちたときの上位案として温存**（openQuestion ⑥）。
  なお「int8 attention は QK だけ整数・PV は半精度」という構成が外部実装で採られている、という
  記憶はあるが**本 recon では一次確認していない**（知識のみ・出典なし）。判断材料にはしない。

## 4. 数値契約（Q3 への回答）

### 4.1 QK 段 — **atol=0 が立つ**（linear i8a8 と同型）

出力 1 要素あたりの浮動小数演算は **5 個だけ**:
`qs = amax_q·(1/127)`（乗算）/ `ks = amax_k·(1/127)` / `qs' = qs·scale` / `ks' = ks·scale` /
`f32(acc)·(qs'·ks')`。全て round-to-nearest-even で決定的。整数縮約は厳密で順序非依存。
→ ADR 0025 決定 4 の論法（`0025:53-56`）がそのまま通る。

**唯一のほころびも linear と同じ**: 量子化の `x/s` は**除数がデータ依存の除算**で、
WGSL の f32 除算は 2.5 ULP まで許される（本機実測 200,000 中 55,605 件で 1 ULP 割れ —
`src/kernels/quantize-rows.ts:36-50`）。→ **丸め境界近傍の要素が ±1 段揺れうる**ので、
テストは `quantizeRowsTieMargin`（`src/reference/i8a8.ts:121-137`）と同型の余裕を実測して門にする。
q / k の 2 本ぶん測る。

**失われるもの**: 分解経路とのビット同一（`tests/gpu_attention_parity_test.ts`）は
**i8a8 変種では原理的に成立しない**。同テストは f32 / f16 変種専用の門として据え置き、
i8a8 では走らせない（キー別の変種選択なので構造的に混ざらない）。

### 4.2 PV 段 — **atol=0 は立たない。理由と代替の門**

**立たない理由**: A 側の量子化値が `round(127·exp(S−m))` で、**`exp` の実装が WGSL と JS で違う**
（WGSL 仕様の `exp` は数 ULP の許容を持ち、JS の `Math.exp` も正しい丸めではない
— **仕様値は記憶ベースで本 recon では一次確認していない**が、「両者がビット一致する保証は無い」
ことは確実）。`127·exp` の値は [0,127] に**密に分布する**ので、1024px 1 層 1 head の
16.7M 要素のうち丸め境界（半整数）の数 ULP 以内に落ちる要素が必ず存在する
（境界幅 ~2e-5 / 値域 127 → **1 層あたり数千件のオーダー**【試算】）。
→ 実モデル形状で「余裕を実測して atol=0 を主張する」型は**恒真化どころか常時赤になる**。

**代替の門（3 本）**:

1. **dp4a vs エミュ atol=0**（無条件に成立）。同一シェーダの同一 `exp` を通るので、
   整数が一致し縮約も厳密。ADR 0025 決定 5 の検出器（`LINEAR_I8A8_DOT` 型の強制ノブ）を
   attention 用に 1 本増やす。
2. **参照 API を「整数の手前」で割る**（本 recon の提案・**推奨**）:
   - `attentionPvI8Reference(qP: Int8Array, vq, prow, vs, …)` = **整数配列を受け取る純関数**。
     ここは `f32(acc)·(prow·vs)` の 3 演算だけなので **atol=0**。
   - `qP` の生成（`round(127·exp(S−m))`）は別の門にする: 小形状で GPU が書いた S を読み戻し、
     TS 側で `qP_ref` を作り、**「一致しない要素の割合」と「一致しない要素は必ず ±1 段」**を
     assert する（±2 段以上が 1 件でも出たら赤 = 実装バグ）。これは恒真化しない強い門で、
     実測分布そのものが記録になる。
3. **実モデル形状は tolerance**（既存の全カーネルと同じ流儀）。E2E は §5 の判別帯。

**整数側の安全性**: `|acc| ≤ N·127²`。N = 16,384（VAE 1024px）で 2.64e8 < 2^31。
既存の `LINEAR_I8A8_MAX_K = 131,072` をそのまま門として輸入すれば足りる（`linear-i8a8.ts:64-69`）。

### 4.3 stats 段の扱いと「分母を量子化後の総和にする」オプション

素直に作ると、分子は `Σ q_P/127`（量子化後）なのに分母 `l` は f32 の `Σ exp(S−m)`（量子化前）に
なる。**0.5/127 未満の要素は丸めで消える**ので、分子だけが系統的に小さくなり
**行ごとの倍率バイアス**（= head 全体に相関した誤差）になる。ゼロ平均の雑音より質が悪い。

**stats を i8a8 変種にして `l' = Σ round(127·exp(S−m))/127` を積めば、この偏りは構造的に消える**
（`Σ P = 1` が量子化後の世界で厳密に成立する）。追加コストは要素あたり `round` 1 個で、
stats は attention の 7.3% しかない。**推奨だが、効果の実測は Q0 が 1 行で出せる**ので
**openQuestion ②**として裁定に上げる。

> 注意: これをやると 3 カーネルが同時に切り替わる（S の格納形を共有する f16 変種と同じ構造 —
> `executor.ts:1574-1576`）。ノブ 1 つで 3 本が動くという既存の性質は保たれる。

## 6. 期待効果の試算（Q5）

### 6.1 前提と外挿の禁止事項

- 基準 = **1024px turbo w8a8**（DiT GPU **2,415ms/step**・attention **1,110ms**・
  linear 1,024ms・全体 36.5s / DiT 28.0s = 2,805ms/step 壁 — `examples/anima/README.md:144-151`）。
- attention 内訳は §1.2 の実測比で **qk 490 / stats 81 / pv 538**【試算】。
- **stats（81ms）は対象外**（本タスクの前提どおり）。
- **linear の 3.44× をそのまま外挿しない**理由（3 つ・いずれも機序ベース【推測】だが根拠付き）:
  1. **3.44× には dequant 除去分が含まれる**（ADR 0025 が明言 `0025:90-91`）。
     attention の f32 経路に dequant は無い。
  2. **QK は k = D = 128 しかない**。K タイル 16 → **8 回転**で、linear（k=2048 → 128 回転）の
     1/16 しか prologue/epilogue を償却できない。かつ出力 1 要素あたりの MAC が 128 個 =
     4 バイト書き出しあたり 32 MAC で、linear（512 MAC/B）の **1/16 の store 密度**。
     MAC を 4 倍速くすると store と prologue の相対比重が 4 倍になる。
  3. **PV は A タイル充填の `exp` が速くならない**。exp の評価回数は
     `M·N·(D/64)·B·H` = 1024px self 1 層あたり **536M**、28 層で **15.0G/step**【試算】。
     整数化してもこの ALU は 1 ミリも減らない（むしろ `round` + `pack` が増える）。
- **DRAM は制約にならない**（§1.4 の床 111ms に対し最良シナリオでも 402ms）。

## 9. キー語彙・ノブ・スコープ（Q6）

### 9.1 パイプラインキー

| 段 | 現行                                              | i8a8 変種（提案）                                               |
| -- | ------------------------------------------------- | --------------------------------------------------------------- |
| ①  | `attention_qk:v1:f32:reg64x64{v4}{:c16}`          | **`attention_qk:v2:i8a8:reg64x64{v4}:dp4a{Emu}`**               |
| ②  | `attention_stats:v1:f32:lastdim:safe:wg256{:c16}` | （§4.3 を採るなら）`attention_stats:v2:i8a8:lastdim:safe:wg256` |
| ③  | `attention_pv:v1:f32:reg64x64{v4}{:c16}`          | **`attention_pv:v2:i8a8:reg64x64{v4}:dp4a{Emu}`**               |

- `linear:v2:f32:…` → `linear:v3:i8a8:…:dp4a` の前例（`linear-i8a8.ts:100-101`）に厳密に倣う
  （**世代を上げ、dtype 欄を `i8a8` にし、内積変種を末尾に付ける**）。
- **既存 f32 / `:c16` キーは 1 文字も動かさない**（スナップショット 74 本が検出器）。
- q/k/Vᵀ の量子化は `QUANTIZE_ROWS_KEY` をそのまま使う → **診断上 linear の量子化と合算される**。
  診断の可読性のために別キーを立てると「同じ WGSL バイト列の別パイプライン」が生まれる。
  → **openQuestion ⑤**（推奨は「共有のまま・E2E の本数検査で内訳を担保」）。

### 9.2 ノブ

**`SessionOptions.attentionCompute?: "f32" | "f16" | "i8a8"`（同一 enum に 1 値追加）**。

- **linear の「i8 格納 × f16 計算 = 3 段 fail loudly」（ADR 0028 決定 4 /
  `gemm.ts:738-746` / `executor.ts:1327-1337`）と同じ扱いは不要**。理由は構造的:
  linear は **格納（weight）× 計算**の 2 軸の直積があるが、attention の q/k/v は
  **すべて活性**で格納軸を持たない。したがって `f16` と `i8a8` は**同一 enum の相互排他値**になり、
  「組めない組み合わせ」を表現すること自体ができない。**fail loudly の 3 段は不要**。
- **`i8a8` は `shaderF16` を要求しない**（`executor.ts:456-460` の f16 ゲートに `i8a8` を
  混ぜないこと）。
- **資産系列は増えない**。attention の a8 化は**活性のみ**なので、`--dit f16` でも `--dit i8` でも
  使える（**linear の i8a8 が「i8 常駐重み限定」だったのと違う**）。これは説明価値のある差分。
- デモは `--attention-compute {f32,f16,i8a8}`。**ノブは既に DiT の Session にだけ渡っている**
  （`examples/anima/main.ts:640-643` のコメントが明示）ので、VAE へ波及しない。

### 9.3 適用範囲（**要確認だった 3 点の回答**）

| 対象                                  | 融合 attention op を使うか                                                                                                                                   | a8 化の対象か                                                                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Anima DiT（transformer）**          | **使う**（`export_anima.py:364-368` の `TARGET_PRESERVED` で `PRESERVED_OP_PREFIXES_WITH_ATTENTION`）                                                        | **本命**（56 ノード/step）                                                                                                             |
| **Anima VAE decoder**                 | **使う**（同上）                                                                                                                                             | **対象外を推奨**。1024px で 112.34ms / 1,989.44ms = **5.65%**【実測】・D=384・N=16,384 で PV の k が最大・**画質に直結**。将来の別裁定 |
| Anima text_encoder / text_conditioner | **使わない**（既定 `PRESERVED_OP_PREFIXES` — mask 付きは `_h_attention` が fail loudly `convert.py:260-264`）                                                | 対象外                                                                                                                                 |
| **SBV2（front/flow/voice）**          | **使わない**（`export_sbv2.py` に preserved 指定なし = 既定）。そもそも softmax 出力が 2 回消費される構造で**融合不能**（ADR 0023 決定 5 / 設計 recon §1.3） | **構造的に対象外**                                                                                                                     |
| **DeBERTa（SBV2 text）**              | **使わない**（`export_deberta.py` に preserved 指定なし = 既定 → SDPA は分解される）                                                                         | **対象外**                                                                                                                             |

→ **ADR 0025 決定⑤の「他モデル検証は DeBERTa が受け皿」に相当する退避先が attention a8 には
無い**。検証は Anima DiT 1 本に閉じる。これは提案時に明示すべき制約
（「一般性の確認」は今回できない）。

## 10. openQuestions（メイン裁定に戻す論点・閉じた選択肢）

1. **PV を入れるか**（= 案 A か案 B か）。
   → **Q0 の P̃ 行 peak/rms 分布で機械的に決まる**。裁定してほしいのは
   「Q0 の門を §5.3 の値（中央値 ≤ 16・latent relRMS ≤ 1.5× vs w8a8）に置いてよいか」。
2. **stats の分母を量子化後総和にするか**（`attention_stats:v2:i8a8`）。
   (A) 入れる（行ごとの倍率バイアスが構造的に消える・コストは要素あたり `round` 1 個・
   stats は 7.3%）/ (B) 入れない（キー変種を増やさない）。**推奨 = Q0 で効果を測ってから (A)**。
3. **ノブ値の名前**。(A) `"i8a8"` 単一値にして、QK のみで着地した場合も ADR に段構成を書く /
   (B) `"i8a8qk"` と `"i8a8"` の 2 値を持つ。**推奨 = (A)**（直積を増やさない — ADR 0028 の規律）。
4. **VAE decoder へ広げるか**。**推奨 = 広げない**（利得 5.65%・画質直撃・D=384 は PV の k が
   16,384 で最大）。広げる場合はデモの VAE Session にもノブを渡す配線が要る。
5. **`quantize_rows` のキーを linear と共有するか**。共有（推奨）/ attention 専用キーを立てる
   （診断は読みやすくなるが同一バイト列の重複パイプライン）。
6. **PV の per-K-block scale（上位案）へ踏み込む条件**。Q0 で素の 1/127 格子が落ちた場合に、
   (A) PV を捨てる（案 A で着地）/ (B) per-K-block へ格上げ（barrier 追加・f32 累積復活・
   工数 M〜L）。**推奨 = (A)**。(B) は「PV だけで DiT GPU の 22% を握っている」ことを
   どれだけ重く見るかの判断。
7. **E2E の置き場**。(A) 新ファイル `tests/e2e_anima_attn_i8a8_test.ts`（w8a8 / f16compute と
   同じ型）/ (B) `e2e_anima_f16compute_test.ts` を「計算変種」として系列パラメタ化。
   **推奨 = (A)**（判別帯の実測値が変種ごとに違うため）。
8. **波 1（QK のみ）で一度リリース判定を挟むか**。挟むと ADR が 2 本になる可能性。
   **推奨 = 1 本の ADR に段構成を書く**（#28 が ADR 0024 への追補で済ませた前例）。

## 11. 隣接（本タスクのスコープ外・報告のみ）

1. **`docs/research/2026-08-03-shader-f16-recon.md:183-186` の「attention の内訳は記録されていない」は
   本 recon で解消**（§1.2）。恒久化のとき同 doc に 1 行の参照を足すと良い。
2. **`attention_stats` は f16 で 1.45〜1.58× 出ている唯一のカーネル**（ADR 0028 実測節）。
   attention 全体の 7.3% なので単独の価値は小さいが、**帯域律速のカーネルは f16 で素直に勝つ**
   という ADR 0028 の結論の再確認材料。`attentionCompute: "i8a8"` を入れるとき
   **stats だけ f16 にする**組み合わせは（S の格納形が揃わないので）作れない — 記録のみ。
3. **PV の A タイルは S を `D/64` 回読み直している**（D=128 で 2 回・D=384 で 6 回）。
   VAE（D=384）では **S を 6 回読む**ので、`exp` の再評価も 6 回。VAE の attention を
   触るなら a8 より先にここ（P の i8 実体化が VAE でだけ割に合う可能性）。
4. **dispatch 増（3 → 7/ノード）** は壁時計の固定費に効く（+28ms/step 級【試算】）。
   Vᵀ + 列量子化の 1 カーネル融合で 56 本戻せる。
5. **cross-attention の k/v は step 間で不変**（`encoder_hidden_states` が固定）。
   量子化結果を step 跨ぎでキャッシュできれば cross 側の量子化コストが 1/10 になるが、
   これはノード局所の設計を破る（ADR 0023 §7 の「cross-attention K/V の step 跨ぎ再計算」と
   同じ論点 = エクスポータ側のグラフ分割）。**別タスク**。
