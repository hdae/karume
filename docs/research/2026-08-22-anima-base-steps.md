# 素の Anima（LoRA 無し）の既定 step 数と CFG — 実測と視認裁定

> 性格: **時点スナップショット**（2026-08-22）。素の base 系列を新設した日の実測と、既定値を
> 決めた視認裁定の記録。恒久の規約ではないので、席や既定が動いたらこの文書ではなく
> [backlog](../backlog.md) と recipe のコメントが正本になる。

## 1. なぜ素版が要るか

出荷中の `anima-turbo` は Turbo LoRA を焼き込んだ蒸留版で、既定が **8 step / guidance 1**。
`guidanceScale === 1` では uncond 側の分岐を 1 度も計算しない（`needsUncond` —
`packages/models/src/anima/sampler.ts`）ので、**negative prompt が効かない**。効かせたい場合に
「渡したのに黙って無視される」ことがないよう、パイプラインは guidance 1 での
`negativePrompt` 指定を fail loudly で落とす設計になっている。

つまり negative を使う運用には **CFG を使う席**が要る。素の base はそれに当たる。

## 2. CFG の代償（実測・RTX 3080 Ti / 1024² / 既定席 `w8a8-s16`）

CFG は 1 step あたり forward 2 本（cond / uncond）なので、同じ step 数でも倍の計算になる。

| step | 所要（3 プロンプトの実測レンジ） |
| ---: | -------------------------------- |
|   20 | 41〜51s                          |
|   24 | 56〜62s                          |
|   28 | 69〜71s                          |
|   32 | 78〜80s                          |

turbo の既定（8 step / CFG 無し）は同条件で 6.6s。**6〜12 倍**が negative を効かせる代償で、
これは席の性格の違いであって劣化ではない。

## 3. step 数の視認裁定（2026-08-22・ユーザー）

3 プロンプト（人物 upper body / 風景 no humans / 全身 + 街）× 4 段（20 / 24 / 28 / 32）を
guidance 4 固定で焼き、1 枚の比較シートへ並べて裁定した。生成物は
`outputs/demo/step-check/`（git 追跡外）。

**重要（比較の読み方）**: step 数を変えると `sigmaSchedule(steps, shift)` が sigma 列ごと
組み直すので、**同じ絵が精細になるのではなく別の絵になる**。したがって「20 の絵と 32 の絵の
どちらが良いか」ではなく「**どこから破綻が減って安定するか**」で見る。i4 の採り直し
（[2026-08-21 の記録](2026-08-21-anima-i4-seat-speed.md) §9）で確認した性質と同じ。

**裁定**: 既定は **20 step**。差は題材によらず小さく、既定は「品質に問題の無い範囲で最速」を
採る方針に従った。上げたい利用者は `steps` を渡せばよい（受理は 2 以上の整数で上限なし）。

`guidanceScale` は **4**（出所ページの推奨値）。

## 4. サンプラーは Euler 固定（未着手として残す）

`FlowMatchEulerDiscreteScheduler` の static shift 経路の移植 1 本だけで、manifest が持てる
ノブは `scheduler: { shift, numTrainTimesteps }` の 2 つ。**サンプラー種別を選ぶ欄そのものが
無い**。多段サンプラー（DPM++ / Heun 等）を足すならサンプラー抽象 + golden の作り直しになる
別波で、2026-08-22 に「また今度試す」として保留にした。

## 5. 未検証（試していないこと — 「試してダメだった」ではない）

- **20 未満**（12 / 16）は焼いていない。裁定範囲は 20〜32 だけ。
- **guidance の振り**（3 / 5 / 7）は焼いていない。4 は出所ページの推奨をそのまま採った。
- **解像度の振り**は 1024² 固定。512² や非正方での step 依存は見ていない。
- **バリアント 2 種（WAI / CopyCat）での step 裁定**は行っていない。素の base で決めた既定を
  そのまま共有している（同じ base の fine-tune なので相場は同じ、という前提のまま）。
