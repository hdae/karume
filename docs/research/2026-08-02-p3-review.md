## 2. major 2 件の詳細

### L3-01（holds） — grid-stride 縮退テストに pad/flip/cumsum/strided書きが無い

`tests/gpu_gridstride_test.ts:7` は「grid-stride を謳う全カーネル族をここに載せる」を MUST
と宣言する一方、CASES（397-407 行）は elementwise/strided読み/gather/embedding/
masked_fill/conv1d/conv_transpose1d/reduce/softmax/layer_norm の 10 本のみで、波4・波5 で
新設した pad・flip・cumsum・strided書き（cat）が入っていなかった。敵対検証で
`PAD_WGSL` の grid-stride ループ（`while (i < params.n)`）を `if` に置換する変異を注入し、
毒値 -999 を敷いた出力へ実 GPU で打ったところ、縮退 dispatch（groups=2、必要数 4）では
864 要素中 352 が未書き込みのまま残り、必要数どおりの dispatch（groups=4）では未書き込み
0 で完全に緑になった。既存の実測形テスト（gpu_ops_test）は必要 workgroup 数がそのまま
割り当たるため縮退経路を一度も踏まず、gpu_full_write_test の毒値ケースも 1 workgroup
（6〜12 要素）で踏まない。

実害の前提も検証で確認された: flow/voice の相対位置注意 value 側 `functional.pad(p_attn,
[w,w])` は宣言上限 T=4096 で h=1 でも `ceil(4096·4104/256)=65,664 > 65,535`
（`maxComputeWorkgroupsPerDimension` 既定）で縮退が発動する一方、golden は最長 T=512
までしか無い（`2·512·520/256=2,080` で縮退しない）ため、長い発話（T≳2900 付近から）で
だけ波形の後半が沈黙誤値になる経路が門なしで残っていた。severity は「今バグは無い
（pad.wgsl 自体は正しい）が失敗様態が完全な沈黙・発火条件が実運用の主力経路・4 本とも
今後の改修が想定される」ことから major で確定。

波F（`e0b93a7`）で grid-stride 縮退ハーネスへ pad/flip/cumsum/strided書き族を追加
（pad は非対称幅 3/5 を採用）。while→if 変異 4 本の赤化を実測確認して根治した。cat は
実形（部分書き）が全域比較に載らないため、全域を覆う置換書きで等価に踏む形にしている
（縮退上限 n が stride 値に非依存であることを doc に明記）。

### L2-01（refuted） — 「対象軸は静的」規則が契約適合表の外にある

ADR 0014 の核心不変条件（slice/cat/flip の対象軸は宣言レベルで静的）が、TS では
`plan.ts:163-184` の `assertStaticLayoutAxis`（validateGraphContracts の独立パス）、
Python では `shapes.py:379-401` の `_static_axis`（compute_output_shape の内側）と
別レイヤに二重実装されており、共有正本の `op-contracts.json` の shapes 節はこの規則を
表現できない（TS は束縛解決後の数値 shape しか受け取らない）という構造の指摘は事実として
成立した。

一方、指摘の核心である実害主張——「`_static_axis` 呼び出しを 1 つ外せば TS/Python 両方の
適合表テストも exporter のテストも緑のまま通る」——は敵対検証で反証された。両側とも共有表の
外に専用の単体テストを持ち（Python: `test_shapes.py::TestLayoutAxisIsStatic`、TS:
`runtime_plan_test.ts:251-296`「slice/cat/flip の記号軸は Session 構築時に落ちる」）、
`_cat` の記号軸拒否だけを外す変異を実際に注入して pytest を回すと、適合表テストは緑の
ままだが `test_a_symbolic_cat_axis_is_rejected` が `DID NOT RAISE` で赤化した（1 failed,
664 passed）。片側だけの緩和は既に別経路で赤くなるため、severity は info へ降格。残る
真の残渣は「両側の受理集合が同じであることを機械的に固定する検査が無い」という保守上の
懸念のみで、コード変更ではなく波F（`681b98b`）で `op-contracts.json` の `_doc` に
担保範囲の限界 NOTE（宣言 shape 層の規則は両側の定義域が違い表に載らない旨）を追加する
対応に留めた。

## 4. 修正しない裁定（報告のみ 6 件）

- **L1-04**（clamp/leaky_relu の doc と実体の食い違い）— 実害は今のところ無く（式が単純で
  誤りようが少ない）、doc の一文訂正のみで済む低リスク事項のため、本波では手を付けず
  記録に残すに留めた。
- **L1-05**（spline パッチの区間外 logabsdet の finiteness 前提）— SBV2 の ConvFlow は
  reverse で logdet を返さないため export されるグラフでは当該ノードが DCE で消える
  死にコード。実害ゼロのため報告のみ。
- **L2-08**（相対位置表生成器が tests/ 配下止まり）— 意図的な暫定配置（doc に将来
  examples/ へ昇格する旨を明記済み）で、昇格時期は M1-P4 以降の判断事項のため今回は
  現状維持。
- **L2-09**（--verify が終了コードを持たない）— 現状は pytest 側の閾値判定で運用が
  成立しており（stdout パース方式）、CLI 単体をゲートとして使う経路は無いため実害なし。
- **L2-10**（weight_norm 検出述語の不一致）— 現行 style_bert_vits2 が旧 API
  （weight_g/weight_v）を使う前提が妥当な限り顕在化せず、壊れる場合も fail loudly で
  止まるため沈黙誤値ではない。
- **L3-04**（DEFAULT_TOLERANCE の根拠薄）— P1 からの既存繰延べ判断の維持。
  ACTIVE_DESIGN の「Decisions in flight」で置換を別タスクとして明示的に据え置いており、
  本差分固有の欠陥ではないため今回は手を付けない。
