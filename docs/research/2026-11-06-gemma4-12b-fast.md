> This document is a point-in-time snapshot (2026-11-06) of Gemma 4 12B decode speed on the maintainer's RTX 3080 Ti under
> Node + Dawn: the parallel-GEMV sweep behind its rows, the presets, long context and the decode run-ahead. It is not a
> design source of truth. Chrome was not run. The harness and the raw records are local and untracked
> (`outputs/diag/gemma4-12b-fast-2026-11-06/`).

# Gemma 4 12B: `i4-fast` and the decode run-ahead

## 1. Summary

- `i4-fast` decodes 12B about 2.9× faster than `i4` at P ≈ 1K, 3.3× at P ≈ 16K and 3.6× at P ≈ 32K, with identical
  tokens in every run here.
- With the MTP drafter `i4-fast` is slower than `i4`. The cause is not known (§3).
- `decodeAhead` works on 12B and its gain shrinks as the context grows: 12–17% of the decode wall per token at P ≈ 1K
  (depth 8), about 10% at P ≈ 16K and about 6% at P ≈ 32K (depth 4) (§4).
- Prefill does not change with the preset (§4).

## 2. The sweep behind the rows

Greedy, 64 tokens, the last warm chat, one process per arm, the GPU cooled to 60 °C between arms, two rounds. Median wall /
busy ms per token at P ≈ 1K (973 tokens). The token hash was the same in all arms.

| Arm | Round 1 | Round 2 |
| --- | ------- | ------- |
| `i4` | 64.9 / 63.2 | 64.9 / 63.1 |
| fused attention only | 44.3 / 42.8 | 44.4 / 42.9 |
| expanding 4, reducing 32 unstaged | 27.6 / 26.3 | 28.7 / 27.2 |
| expanding 4, reducing 32 staged | 23.9 / 22.5 | 24.2 / 22.6 |
| expanding 16, reducing 32 staged | 27.3 / 25.8 | 27.3 / 25.8 |
| expanding 32, reducing 32 staged | 27.7 / 26.1 | 27.6 / 26.1 |
| expanding 4, reducing 16 staged | 24.0 / 22.4 | 24.2 / 22.7 |
| as chosen + output head lanes 16 | 22.3 / 20.8 | 22.3 / 21.0 |
| as chosen + output head lanes 4 | 22.3 / 21.0 | 22.3 / 20.9 |

Output head lanes 32 did not build. The chosen row set is expanding 4, reducing 32 staged, output head lanes 16
(ADR [0098](../decisions/0098-linear-gemv-parallel.md) addendum of 2026-11-06).

## 3. The presets with the drafter

The bench harness under Node, interleaved in one process, 128 tokens: median ms per token. The text was the same
across presets. Acceptance is the drafter's on that prompt.

| Prompt (acceptance) | `i4` plain / speculative | `i4-gemvpar` plain / speculative | `i4-fast` plain / speculative |
| ------------------- | ------------------------ | -------------------------------- | ----------------------------- |
| `sky-en` (0.46) | 54.5 / 32.6 | 27.5 / 37.9 | 27.4 / 38.2 |
| `code-en` (0.93) | 55.0 / 19.1 | 28.5 / 25.1 | 26.1 / 25.9 |

Plain decode gains 1.9–2.1× here. Speculative decode loses on the same presets, and on `i4` the drafter cuts the time to ×0.60 and ×0.35, so the two speed-ups do not stack on 12B. On E2B and E4B both presets stay faster with the drafter (ADR
[0104](../decisions/0104-gemma-fast-quant.md)). Why 12B differs was not investigated (perf-ledger K-102).

## 4. Long context and the run-ahead

Masked selection, capacity 4096 / 16384 / 32768 for the three P, two rounds, 64 tokens, the last warm chat.
Depth 1 shows the median token and the decode wall per token; depths ≥ 2 only have the second, because their tokens arrive in
batches. The token hash was the same across the arms of each P.

| P | Arm | Depth 1 median | Depth 1 decode wall | Depth 4 decode wall | Depth 8 decode wall |
| - | --- | -------------- | ------------------- | ------------------- | ------------------- |
| 973 | `i4-fast` | 22.0 / 22.5 | 26.5 / 26.8 | 26.7 / 22.4 | 22.3 / 22.2 |
| 973 | `i4` | 62.8 / 64.6 | 74.5 / 76.5 | 67.2 / 71.3 | 65.3 / 66.9 |
| 15,994 | `i4-fast` | 36.2 / 35.7 | 45.0 / 41.0 | 38.9 / 38.9 | not run |
| 15,994 | `i4` | 121.1 / 122.4 | 142.0 / 143.8 | not run | not run |
| 31,978 | `i4-fast` | 50.5 / 49.6 | 58.5 / 62.1 | 57.1 / 56.6 | not run |
| 31,978 | `i4` | 181.4 / 180.3 | 209.4 / 196.9 | not run | not run |

The decode wall per token runs above the median at depth 1 because of a few slow tokens. It is the number to compare across
depths. One depth-4 round at P ≈ 1K (26.7) sits at the depth-1 level against 22.4 in the other; two rounds do not settle that
spread.

Prefill was about 2.5 s at P ≈ 1K, 51 s at P ≈ 16K and 111 s at P ≈ 32K, on every arm.

## 5. Not covered

Chrome and D3D12, the RTX 5070 Ti, sampling other than greedy, capacities above 32768 on 12B, and KL against upstream on the
new rows. The tokens matched `i4` on the prompts here, which says nothing about other prompts.
