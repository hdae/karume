**refuted 1 件 — 対応なし:**

- 「run の finally で popErrorScope が reject し flush-before-destroy が飛ぶ」— 実測で否定
  （popErrorScope は device 消失後も null で resolve。reject は空スタック時のみで、push/pop
  均衡により到達不能）。残る「pop の戻り値を捨てる」点は診断品質の話で既存パターンと同型。

修正後: 130 テスト緑（+9）、`deno task verify` 全緑。修正で可視の公開 API 変化は
①同一 Session の run が直列実行になる ②RunOutputs が null プロトタイプになる、の 2 点。

## 修正エージェントの隣接指摘（修正時に発見・未着手）

- **Session 間の errorScope 交錯は残る** — 直列化は Session 内のみ。同一 GpuContext 上の
  複数 Session の並行 run では同じ誤帰属が起きる。device 単位ロック or limitations 明文化の
  裁定要（M1 の SBV2 チェーンは逐次 await なら影響なし）。
- Session.create の catch 経路は weights.destroy() の throw で本体例外を上書きしうる
  （run 側と非対称のまま）。
- #readOutputs の staging が RunArena 所有外（ADR 0004「確保と破棄を 1 箇所へ」から外れる。
  現状は finally で確実破棄）。
- OOM スコープは重みアップロードのみ（run 本体 / readback の中間バッファ OOM は未捕捉）。
- flush() が計測コールバック（fire-and-forget）を待たないため、直後の stats 読みで
  measuredMs の最終チャンクが未反映になりうる（診断のみのレース）。
- 利用者が SymbolBindings / RunInputs をオブジェクトリテラルで組むと `__proto__:` キーは
  呼び出し側で own key にならず届かない（JS の記法の問題 — docs/limitations.md 候補）。
- レンズ notes より: amax/amin の identity が ±F32_MAX（全 -Infinity 行が -F32_MAX を返す。
  run は入力の非有限値を検査しないため到達可能 — M0 の対象外宣言の範囲内）。adapter.info は
  古い Chromium で undefined になりうる。

## レビューが「問題なし」と確認した点（再調査不要の記録）

- アリーナの read→write 追い越しは alloc 順序 + ノード境界解放で構造的に防止。エイリアス
  入力（add(x,x)）の延べ計数も一致。
- WGSL の barrier 一様性（reduce / matmul とも uniform 由来の制御フロー下）。grid-stride の
  全域被覆（上限クランプ後も欠落なし）。
- chunkSize 0 ハング / onSubmittedWorkDone 二重計上 / device 消失時の各種ハングは対策済み。
- `any` / `@ts-` / `enum` / `||` フォールバック 0 件。相対 import 全て `.ts` 付き。Web 標準
  API のみ。TypedArray `<ArrayBuffer>` 明示。禁止固有名の混入 0。
- gelu の CPU 参照（マクローリン級数）と WGSL（A&S 7.1.26）は独立実装で、tanh 近似への
  すり替えは atol=1e-5 が検出する（恒真でないことを数値で確認 — 当初疑義は撤回済み）。
