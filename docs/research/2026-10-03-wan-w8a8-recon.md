# Wan2.1 DiT に w8a8 の量子化席を足す — ADR 起草材料（recon）

読み取りだけの調査（HEAD `e2b14aa9`・GPU 不使用・リポのコード変更なし）。Wan2.1 T2V 1.3B の DiT に、anima の既定席
`f16+dit8-a8-attn8-s16` と同じ機構の席を足す ADR の材料を集めた。「事実」は file:line・コマンド出力・記録の数値を
根拠に持つ。「推測」は節の中で明示する。引用した行番号は全て HEAD `e2b14aa9` のもの（調査中に別の作業が
`wan/` の recipe・`packages/models/src/wan/`・exporter core などを編集していて、作業ツリーでは行がずれる）。

## 要約

- **runtime の追加は要らない見込み**。DiT の重みは linear 307 本だけで、attention 60 本（mask・GQA 無し・D = 128）と合わせ全部が
  既存の a8 / attn8 / s16 の適格条件を満たす。行ブロック × a8 / s16 にはビット一致の門が既にある。
- **i8 化で DiT の重みは 2.65 → 約 1.33 GiB**・配布の取得量は 3.14 → 約 1.72 GB（上流のヘッダからの計算）。
- **速度（推測）**: B570 で 1 パス 16.8 → 約 8 s（33 フレーム）・68.6 → 約 36 s（81 フレーム）。81 フレームは self-attention が 70%。
- **数値の門は 2 層**。`f16+dit8`（重みだけ i8）は参照層で ADR 0118 決定 8 の r 門がそのまま効く（逆量子化は CPU とビット一致）。
  a8 を含む席は実用層で、ADR 0110 決定 5 の自機 A/B 門（同じ i8 重みの `f16+dit8` と step 1 の latent で比べる）が既にある。
- **最大のリスクは attention a8 の長い行**（誤差は行の長さ N で増える — ADR 0030 決定 6）。anima の検収は N ≤ 4,096、Wan は
  14,040 / 32,760。既定席は f16 のまま始め、視認 A/B（seed 42〜45 × 固定プロンプト 3 本・f16 側は段 7 の 12 本）で決める。

## 0. 用語（本書の初出）

| 語              | 意味                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------- |
| `dit8`          | 席名の部品上書き。DiT（manifest の役割 `transformer`）の重みを i8 per-channel で格納する（ADR 0074 決定 4） |
| `a8`            | `linearCompute: "a8"`。linear の入力活性を per-token の i8 にして整数内積で計算する（ADR 0025）             |
| `attn8`         | `attentionCompute: "a8"`。attention の q / k / P̃ / V を i8 にして整数内積で計算する（ADR 0030）             |
| `s16`           | `attentionScoreStorage: "f16"`。attention のスコア S を f16 で格納する（ADR 0031）                          |
| 参照層 / 実用層 | runtime の省略値の経路 / quant 席の `session` が束ねた opt-in の経路（ADR 0110 決定 1）                     |
| 参照席          | 実用席と同じ重みで `session` が空の席。自機 A/B 門の比較相手（`referencePartnerOf`）                        |
| r               | ADR 0118 決定 8 の正規化比。GPU の f64 参照に対する誤差 ÷ CPU f32 参照の f64 参照に対する誤差               |
| 1 パス          | DiT の 1 forward。50 ステップ × CFG 2 で 1 本の生成は 100 パス                                              |

## 1. anima の席の機構の棚卸し

### 1.1 席の定義（recipe の quant 表）

`tools/export-recipes/anima/distribution.py:230-303` の `ANIMA_QUANTS` が席の正本。既定は 305 行の
`ANIMA_DEFAULT_QUANT = "f16+dit8-a8-attn8-s16"`。略称 `dit` → 役割 `transformer` は 220 行の
`ANIMA_QUANT_ABBREVIATIONS`。

| 席                      | `weights.transformer` | `session`                                                                        |
| ----------------------- | --------------------- | -------------------------------------------------------------------------------- |
| `f16`                   | `f16`                 | 空                                                                               |
| `f16+dit8`              | `i8`                  | 空                                                                               |
| `f16+dit8-a8`           | `i8`                  | `linearCompute: "a8"`                                                            |
| `f16+dit8-a8-attn8`     | `i8`                  | `linearCompute: "a8"`・`attentionCompute: "a8"`                                  |
| `f16+dit8-a8-attn8-s16` | `i8`                  | `linearCompute: "a8"`・`attentionCompute: "a8"`・`attentionScoreStorage: "f16"`  |
| `f16+dit4`              | `i4`                  | 空                                                                               |
| `f16+dit4-attn8-s16`    | `i4`                  | `attentionCompute: "a8"`・`attentionScoreStorage: "f16"`（a8 は品質で外した）    |
| `f16-c16`               | `f16`                 | `linearCompute: "f16"`・`attentionCompute: "f16"`・`gpuFeatures.shaderF16: true` |

- 配置: 格納ラベルごとに別の容器 `transformer/model.f16.krm` / `model.i8.krm` / `model.i4.krm`
  （`anima/distribution.py:205-214`）。重みの系列は `outputs/series/<model>-i8-dyn/`（同 `:574`）。
- 取り違えの門: `STORAGE_REQUIREMENTS`（`:385-392`）が「その格納を含む」を、`ANIMA_STORAGE_FORBIDDEN`
  （`:404-407`）が「その格納を含まない」を見る。i4 系列は i8 を含む混成なので、存在検査だけでは i4 を i8 席へ
  挿す取り違えが素通りする（`:394-403` の注記）。
- Wan 側の現状: 席は `f16` 1 つで `session` は空（HEAD の `wan/distribution.py:136-145`）。`WAN_STORAGE_FORBIDDEN` は
  全役割で `("bf16", "i8", "i4", "i2")`（`:120-122`）。出力 path は既に `transformer/model.f16.krm` の綴りで、
  「i8 / i4 の席を足した日に既存の path を動かさないため」と書いてある（`:98-100`）。

### 1.2 exporter 側で i8 重みを作る経路

- **fake-quant**: `karume.quantize.fake_quant_int8`（`tools/exporter/src/karume/quantize.py:173-223`）が、
  `QUANT_CHANNEL_AXES`（`:97-106` — Linear / Conv1d / Conv2d / Conv3d / ConvTranspose1d / Embedding）の `weight` だけを
  per-channel symmetric i8 の表現可能値へ丸め、scale 台帳を返す。bias と norm の weight は触らない。
- **呼ぶ順序**: anima は `_fake_quant`（`anima/export.py:925-956`）で `--dtype i8` のときこれを呼ぶ。参照の採取より前に
  当てる MUST（ADR 0006・ADR 0019）。
- **格納**: emit が scale を companion テンソル（F32・keepdim）として書く。codec は `int8-sym`（チャネル単位 —
  `tools/exporter/src/karume/container.py:308`・`packages/runtime/src/format/container/codecs.ts:95`）。
- **混成**: `_plan_weight_dtype`（`tools/exporter/src/karume/emit.py:594-616`）の `weight_dtype_overrides` が、
  テンソル 1 本単位で格納 dtype を上書きする。既定の格納は適格外を静かに f32 へ残し、明示の上書きは満たせなければ
  fail loudly。anima の i4 系列（既定 i8・適格な 1 本ずつを i4 へ）がこの口を使う。
- **IR の表現**: 量子化はグラフの意味論に入らない（ADR 0006）。IR の linear は f32 のままで、格納だけが i8 になる。
  a8 も IR の op ではなく実行時ノブ（ADR 0025 決定 1 — IR op 化の案 C は却下）。

### 1.3 hub の quant 名の解決

- 席名は hub にとって不透明なキー（`docs/glossary.md` の「quant 席」）。命名規則は ADR 0074 決定 1 の
  `<格納>[+<部品><ビット>]…[-<ノブ>]…`、表示欄 `label` / `description` は ADR 0075。
- manifest の `session` が受けるキーは `packages/hub/src/manifest.ts:175-184` の `SESSION_KEYS`
  （`linearCompute` / `attentionCompute` / `attentionScoreStorage` ほか）。家族ごとの絞り込みは hub ではなく
  models の受理表が持つ。
- `karume/5` では `weights.<役割>.<dtype ラベル>.container` が格納ラベルごとの容器を指す（ADR 0109・
  `docs/glossary.md` の manifest `karume/5`）。席の `weights` は役割 → ラベルの写像。

### 1.4 runtime の a8 の経路

- **linear の述語**: `packages/runtime/src/runtime/recipe-builders/linear.ts:209-215` —
  `linearCompute === "a8"` かつ重みが i8 / i4 常駐かつ `k > 0 && k % 4 === 0` のときだけ `buildLinearI8a8` へ行く。
  それ以外は f32 計算の経路へ静かに落ちる（検出は census — ADR 0025 決定 1）。f16 計算 × i8 常駐は fail loudly
  （`:220-226`）。
- **部品**: 活性の per-token 量子化 `quantize_rows`（`packages/runtime/src/kernels/quantize-rows.ts`）→ i8a8 GEMM
  （`packages/runtime/src/kernels/linear-i8a8.ts`・dp4a か同値のエミュ — ADR 0025 決定 3 / 5）。縮約は i32 の厳密整数加算で、
  GPU と TS 参照が atol = 0（契約クラス E — ADR 0110 決定 2・9）。k の上限は 2^17（Wan の最大 k は 8,960）。
- **attention**: `packages/runtime/src/runtime/recipe-builders/attention.ts:236-243` — ①QK は `D % 4 == 0`、
  ③PV は `N % 4 == 0` で段ごとに独立に適格。s16 は `D % 4 == 0 && N % 4 == 0`。加算 mask × a8 と GQA × a8 は
  fail loudly（`:252-279`）。量子化の一時は行ブロックのループの外で 1 回（`:305-313`）。
- **行ブロックとの組**: `packages/runtime/tests/gpu_attention_row_block_test.ts:1-24`・`:86-88` が、強制分割
  2 / 3 / 5 枚で s16 / a8 / a8 + s16 の出力を分割前と Uint32 一致で見ている。
- **キー**: anima の B570 の記録で `linear:v4:i8a8:tile128x64r8x8w8x16k16v4:dp4a`・
  `attention_qk:v3:i8a8:…:dp4a:s16`・`attention_pv:v3:i8a8:…:dp4a:s16`・`quantize_rows:v1:f32>i8:pertoken:wg256`
  （`docs/research/2026-09-27-k70-metal-per-op.md` §4.2）。

### 1.5 models 側の admission

- **Wan の受理表は全部 false**: `packages/models/src/wan/pipeline.ts:594-603` の `WAN_SESSION_POLICY`。
  anima は `linearCompute` / `attentionCompute` / `attentionScoreStorage` の 3 つを true にしている
  （`packages/models/src/anima/pipeline.ts:323-332`）。
- **合成**: `resolveSessionOptions(WAN_SESSION_POLICY, quant.session, {}, …)`（`wan/pipeline.ts:780-785`）。第 3 引数
  （利用者の明示指定）は空で、Wan の公開オプションは `quant` だけ（`:293-318`）。anima は明示指定も受ける。
  受けないキーの宣言は重みを取る前に素の `Error`（`packages/models/src/session/options.ts:196-198`）。
- **渡し先**: DiT の Session だけが `sessionOptions` を受ける（`wan/pipeline.ts:933`）。VAE の 2 Session は `{}`
  （`:1004-1005`）。anima と同じ形で、席のノブは DiT にしか効かない。
- **今の門**: `packages/models/tests/e2e_wan_pipeline_test.ts:335-347` は「`f16` 席が `linearCompute: "a8"` を宣言したら
  `session.linearComputeは未対応` で落ちる」を故障注入にしている。受理表を開けると、この注入は別の未受理キーへ
  差し替えが要る。`packages/models/tests/session_options_test.ts` と `packages/models/tests/helpers/census-table.ts:99` も
  `WAN_SESSION_POLICY` を参照する。
- **census 表**: `census-table.ts` は attention の席を表に書かない（`:40-42` — 行ブロックの枚数が device の上限で
  変わるため）。linear の席は本数ちょうどで書ける。ローカルミラーの非参照束に行が無いと GPU 不要の門が赤になる
  （`docs/glossary.md` の「束の census 表」）。

## 2. Wan の DiT グラフの中身

### 2.1 op の構成（配布中の容器から数えた事実）

`outputs/series/wan2.1-t2v-1.3b-f16-dyn/transformer/` の part 0 を `karume.dist.ir_graph` で読んだ集計
（scratchpad の `census.py`）:

| op           | 本数 | 中身                                                                    |
| ------------ | ---: | ----------------------------------------------------------------------- |
| `linear`     |  307 | 重みは 307 本とも initializer                                           |
| `attention`  |   60 | self 30 + cross 30。入力は全部 3 本（mask 無し）・attrs は `scale` だけ |
| `rms_norm`   |  120 | qk-norm（1 ブロック 4 本）                                              |
| `layer_norm` |   91 | 1 ブロック 3 本 + 出力 1 本                                             |
| `gelu_tanh`  |   31 | FFN 30 + テキスト射影 1                                                 |
| `sigmoid`    |    2 | SiLU（時刻 MLP）                                                        |
| その他       |      | reshape 362・add 303・slice 302・mul 243・permute 240・neg 60・cat 60   |

- **conv3d は DiT に無い**。patch 埋め込みの `Conv3d(16→1536, k = s = (1,2,2))` は recipe が `Linear(64→1536)` へ差し替えて
  いる（`tools/export-recipes/wan/dit_patch.py:189-222`）。重みは conv の重みの view なので、in-place の fake-quant は
  上流の conv にも届く（同 docstring `:192-195`）。i8 の `fake_quant_int8` も `weight.copy_` で書くので同じ性質を持つ。
- **RoPE** はホストが組んだ `rope_cos` / `rope_sin` をグラフ入力にし、グラフ内は neg / cat / mul / add だけ
  （`dit_patch.py:68-89`）。時刻埋め込みの sinusoidal はホスト、MLP（256→1536→1536→9216）はグラフ内の M = 1 の linear。
- 活性は全部 f32（ADR 0118 決定 3）。

### 2.2 linear の内訳（上流の safetensors ヘッダから）

上流 `Wan-AI/Wan2.1-T2V-1.3B-Diffusers`（revision `0fad780a…`）の `transformer/` 2 ファイルのヘッダを読んだ
（825 テンソル・全 F32・1,418,996,800 パラメータ — 実重みは読んでいない）。

| 重み                                                   | 形 `[out, in]`                  | 本数 | 行数 M | 備考                                   |
| ------------------------------------------------------ | ------------------------------- | ---: | ------ | -------------------------------------- |
| `blocks.N.attn1.to_q / to_k / to_v / to_out.0`         | `[1536, 1536]`                  |  120 | S      | self-attention                         |
| `blocks.N.attn2.to_q / to_out.0`                       | `[1536, 1536]`                  |   60 | S      | cross-attention の x 側                |
| `blocks.N.attn2.to_k / to_v`                           | `[1536, 1536]`                  |   60 | 512    | 文脈側（毎パス計算 — ADR 0118 決定 3） |
| `blocks.N.ffn.net.0.proj`                              | `[8960, 1536]`                  |   30 | S      | FFN 上り                               |
| `blocks.N.ffn.net.2`                                   | `[1536, 8960]`                  |   30 | S      | FFN 下り（k = 8,960）                  |
| `condition_embedder.text_embedder.linear_1 / linear_2` | `[1536, 4096]` / `[1536, 1536]` |    2 | 512    | テキスト射影                           |
| `condition_embedder.time_embedder.linear_1 / linear_2` | `[1536, 256]` / `[1536, 1536]`  |    2 | 1      | 時刻 MLP                               |
| `condition_embedder.time_proj`                         | `[9216, 1536]`                  |    1 | 1      | adaLN の 6 成分を作る共有 linear       |
| `patch_embedding`（Linear 化）                         | `[1536, 64]`                    |    1 | S      | 元は `[1536,16,1,2,2]` の Conv3d       |
| `proj_out`                                             | `[64, 1536]`                    |    1 | S      | 出力射影                               |

- 合計 307 本。k は 64 / 256 / 1,536 / 4,096 / 8,960 で、**全部が `k % 4 == 0`**（a8 の述語を満たす）。
- 重みスロットに載らない 1,256,512 パラメータ（bias 746,560・norm の weight 230,400・`scale_shift_table` 279,552）は
  f32 のまま残る。Wan の adaLN は「ブロックごとの linear」ではなく、共有の `time_proj` 1 本 + ブロックごとの加算表
  `scale_shift_table [1,6,1536]`（linear ではない）なので、anima の adaLN 168 本に当たる重みは `time_proj` 1 本だけ。
- **attention の適格**: D = 128・H = 12（KV も 12 で GQA 無し）。self は N = S、cross は N = 512。
  S = 1,560 × F'（F' は潜在のフレーム数 — 832×480 で 30 × 52 = 1,560）なので **S は常に 4 の倍数**。①QK・③PV・s16 の
  条件は全受理形で満たされる（推測ではなく式から従う）。

## 3. 期待できる効果と費用

### 3.1 B570 での a8 の実測（anima・512²・8 ステップ）

`docs/research/2026-09-27-k70-metal-per-op.md` §4.1 / §4.2 / §5.2 の B570 の列（Deno・raw tick を 52.08 ns で換算）:

| 段                    | `f16` 席                                              | 既定席 `f16+dit8-a8-attn8-s16`       |    比 |
| --------------------- | ----------------------------------------------------- | ------------------------------------ | ----: |
| linear（全 key の和） | 6,820.7 ms（大タイル 6,429.3 + 中 340.0 + GEMV 51.4） | 2,369.6 ms（`linear:v4:i8a8` 1 key） | 2.88× |
| 活性の量子化          | —                                                     | 176.1 ms（`quantize_rows` 3 key）    |     — |
| attention ①QK + ③PV   | 556.2 ms                                              | 249.6 ms                             | 2.23× |
| attention ② 行統計    | 191.1 ms                                              | 191.3 ms                             | 1.00× |
| 達成（linear）        | 約 4.1 TFLOPS                                         | f32 の 2.9 倍速                      |     — |

- 量子化込みの linear は 6,820.7 → 2,545.7 ms で **2.68×**。attention 3 段は 747.3 → 440.9 ms で **1.69×**。
- 前提の違い: anima は S = 1,024（512²）で、Wan の S は 14,040 / 32,760。ADR 0025 / 0030 / 0031 の倍率（linear 3.25×・
  attention 2.56×・s16 −2%）は RTX 3080 Ti の値で、B570 の値ではない（`docs/research/2026-08-21-anima-i4-seat-speed.md` §2・
  ADR 0025「実測効果」）。
- 重みだけ i8（`f16+dit8`）は f16 と同じ時間（anima の実測 — ADR 0076 Context・`2026-08-21-anima-i4-seat-speed.md` §4 の 1）。
  DiT は重み帯域律速ではない。
- **Metal では a8 の利得が消える**（M2 で i8a8 の linear が f32 と同じ時間 — K-70 §1・§5.2）。段 9（Chrome）の利用者の
  M2 では a8 席は速くならない。

### 3.2 Wan の 1 パスの内訳（推測）

Wan の GEMM と attention の時間の内訳は**記録が無い**。`outputs/verify/deno-intel-graphics-bmg-g21/2026-10-03_wan-dit/results.json`
はパス全体の GPU 時間（33 フレーム 16.73〜16.75 s・81 フレーム 68.07〜68.29 s）と submit 統計だけを持ち、op 別の時間
（`lastRunTiming` の key 別）は無い。ADR 0118 の検収欄も同じ。そこで計算量から割る（全て推測）。

| S                     |      linear |   self-attn | cross-attn | linear の割合 | self-attn の割合 |
| --------------------- | ----------: | ----------: | ---------: | ------------: | ---------------: |
| 14,040（33 フレーム） | 17.64 T MAC | 18.17 T MAC | 0.66 T MAC |         48.4% |            49.8% |
| 32,760（81 フレーム） | 41.05 T MAC | 98.91 T MAC | 1.55 T MAC |         29.0% |            69.9% |

- 式は ADR 0118 の見積り表（`docs/decisions/0118-wan21-video-generation.md:619`）と同じ。値は 33 フレームで一致する。
- linear に B570 の f32 の達成 4.1 TFLOPS を当てると、linear は 33 フレームで約 8.6 s・81 フレームで約 20.0 s。実測の
  パス時間から引いた残り（attention と elementwise ほか）は約 8.2 s / 約 48.1 s になる。残りの実効は 4.2〜4.6 TFLOPS で、
  linear と同程度。
- 81 フレームの S は 1 回触るだけで 30 層 × 12 head × 32,760² × 4 B = 1.55 TB/パス。①書き・②読み・③読みの 3 回を
  公称帯域 380 GB/s で割ると約 12 s で、attention の一部は帯域で縛られている可能性がある（推測 — 未計測）。

### 3.3 席ごとの短縮の上限（推測）

3.1 の倍率（linear 2.68×・attention 3 段 1.69×）を 3.2 の内訳に当てた上限。attention 側の倍率を「残り全体」に当てて
いるので、elementwise の分だけ楽観側に倒れている。

| 席                             | 33 フレームの 1 パス | 81 フレームの 1 パス | 50 ステップの DiT（33 / 81） |
| ------------------------------ | -------------------: | -------------------: | ---------------------------: |
| `f16`（実測）                  |               16.8 s |               68.6 s |       28 分 / 114 分（実測） |
| `f16+dit8`                     |            約 16.8 s |            約 68.6 s |                   変わらない |
| `f16+dit8-a8`                  |    約 11.4 s（−32%） |    約 55.6 s（−19%） |          約 19 分 / 約 93 分 |
| `f16+dit8-a8-attn8`（+ `s16`） |     約 8.0 s（−52%） |      約 36 s（−48%） |          約 13 分 / 約 60 分 |

- `s16` の時間の利得は anima で −2%（RTX 3080 Ti・ADR 0031）。81 フレームでは S の帯域が大きいので、②行統計の分
  （1.13〜1.39× — ADR 0031）がそれより効く可能性はあるが、③PV は命令律速で利得なし（同）。未計測。
- VAE 段（33 フレーム 128.9 s・81 フレーム 315 s）は席に依らず残る。
- ③PV の行の長さ N は anima の 4〜32 倍で、a8 の ③PV の倍率が S = 1,024 と同じとは限らない。**段で実測して置き換える**数値。

### 3.4 VRAM（推測）

| 量                            | 33 フレーム                       | 81 フレーム                       | 根拠                                                              |
| ----------------------------- | --------------------------------- | --------------------------------- | ----------------------------------------------------------------- |
| DiT 段の山（`f16`・実測）     | fdinfo 6.19 GiB / 診断の確保 5.15 | fdinfo 7.31 GiB / 診断の確保 6.17 | ADR 0118 段 6 / 段 8                                              |
| 重み（i8 化）                 | −1.32 GiB                         | −1.32 GiB                         | 2.3                                                               |
| linear の量子化の一時（最大） | +0.12 GiB                         | +0.27 GiB                         | FFN 下りの入力 `[S, 8960]` の i8                                  |
| attention の量子化の一時      | +0.14 GiB                         | +0.33 GiB                         | q / k / v の i8 + Vᵀ の f32（ループを跨いで生きる — 1.4）         |
| S の 1 ブロック（`s16`）      | 1.76 → 1.47 GiB（5 枚 → 3 枚）    | 2.00 → 2.00 GiB（24 枚 → 12 枚）  | `planRowBlocks`（`fusion-rules/row-block-attention.ts:73`）で計算 |

- 81 フレームでは S のブロックが束縛上限（2,147,483,644 B）ちょうどまで詰まるので、`s16` は VRAM の山を下げない。
  効くのはブロックの枚数（dispatch の本数）だけ。
- 差し引きで DiT 段の山は 33 フレームで約 1〜1.3 GiB・81 フレームで約 0.7〜1 GiB 下がる見込み（推測 — 一時バッファが山と
  重なるかで幅が出る）。Chrome（段 9）や
  VRAM の小さい機では、速度より取得量と VRAM の方が効く。

### 3.5 K-75 との関係（事実から従うこと）

ADR 0118 段 3 の帰属で、GPU の f32 GEMM の K 縮約は CPU f32 の 3〜14 倍の丸め誤差を持つ（perf-ledger K-75・現状維持）。
a8 の linear と attention は i32 の厳密整数加算なので、この縮約順の誤差は消える（ADR 0025 決定 4）。代わりに活性の
量子化誤差が入り、そちらが桁で大きい（anima の step 1 latent の relRMS 1.2〜1.4e-2 — ADR 0110 追記）。a8 席の数値の
門は K-75 の影響を受けない。

## 4. 品質の門の設計

### 4.1 前提: 席は参照層と実用層に分かれる

- **`f16+dit8`（`session` が空）は参照層**。GPU の i8 は読み出し時に要素ごとに逆量子化し、CPU の展開とビット一致する
  （ADR 0019 決定「scale の適用は要素ごと」）。参照は同じ i8 の fake-quant 重みで採る（ADR 0006）。したがって
  **ADR 0118 決定 8 の門（f64 参照 + 正規化比 r・帯 = 決定用 6 本の最悪 × 5）がそのまま使える**。依頼文の
  「量子化席では GPU の誤差が CPU f32 参照の誤差を桁で超える」は a8 を含む席には当てはまるが、`f16+dit8` には当てはまらない。
- **a8 を含む席は実用層**。カーネルの数値契約は既存の E クラス（GPU と TS 参照が atol = 0 — `gpu_i8a8_test.ts`・
  `gpu_attention_i8a8_test.ts`・`gpu_attention_pv_i8a8_test.ts`・`gpu_attention_s16_test.ts`）で、新しいカーネルを
  足さない限り追加の 4 点型は要らない（ADR 0110 決定 2・3）。モデル出口の torch との帯は恒真化するので使わない
  （ADR 0110 Context・ADR 0025 決定 6）。

## 6. リスク

1. **attention a8 の長い行（最大）**: ③PV は `qP = round(127·exp(S − m))` で、行の scale は 1/127 に構造的に固定される
   （ADR 0030 決定 3）。誤差は行の peak / rms で決まり、分布は N とともに右へ寄る（ADR 0030 決定 6・検出限界 1 —
   512px の門通過を 1024px へ外挿しなかった）。anima で検収した N は最大 4,096（1024²）で、Wan は 14,040 / 32,760。
   鋭い行では `exp(S − m) < 1/254` の要素が 0 に丸まり、質量が消える。**33 フレームの結果を 81 フレームへ外挿しない**。
2. **adaLN と条件の経路**: anima では adaLN を含む i4 の変種で、seed 42 単発の評「採用してもいい」が seed 43〜45 + 別
   プロンプトで覆った（`docs/research/2026-08-28-anima-adaln8-visual.md`・feedback「視認 A/B は seed 4 本以上」）。Wan の
   adaLN の重みは共有の `time_proj` 1 本で、a8 では M = 1 の入力ベクトルが行 1 本ぶんの scale で量子化され、誤差は全
   トークン・全ブロックの shift / scale / gate へ一様に乗る（推測）。上流 diffusers は低精度格納の層別キャストで
   `patch_embedding` / `condition_embedder` / `norm` を除外する（`transformer_wan.py:547` の
   `_skip_layerwise_casting_patterns`。理由は `modeling_utils.py:445-452`「precision-critical for quality」）。
   anima の既定席は adaLN を i8 + a8 にして視認を通っているが、モデル固有で一般化できない
   （feedback「棄却記録はモデル固有」）。
3. **時間方向の一貫性**: per-token の量子化誤差はフレームごとに別の値になる。静止部分のちらつきとして見える可能性が
   ある（推測 — 前例なし）。PNG の一覧図では見落としうる。
4. **テキスト文脈の外れ値**: `text_embedder` の入力は umT5 の出力 `[512, 4096]`。T5 系は活性の外れ値が大きいと言われ、
   per-token の i8 では外れ値の行で誤差が大きくなる（推測 — 実測なし）。パディングの 0 行は厳密に 0 のまま
   （ADR 0025 決定 2 の全ゼロ行）。
5. **行ブロックとの相互作用**: a8 / s16 × 行ブロックは Uint32 一致の門がある（1.4）。2.0 GiB の束縛上限は S のブロック
   1 枚で決まり、量子化の一時（最大 201 MB の Vᵀ）はその下に収まる。数値の新しいリスクは見つからなかった。census 表は
   attention の本数を書かない規約（1.5）。
6. **VRAM と B570 の解放遅れ**: 自機 A/B 門は 2 本の pipeline を順に張る。B570 では `destroy()` の解放が遅れ、段 8 で
   S = 14,040 の probe が S = 32,760 の照合の後に OOM になった（ADR 0118 段 8 の結果）。81 フレームの A/B は確保の
   大きい順・解放待ちの手順が要る可能性がある。
7. **Metal で速くならない**: 3.1 の最後。M2 の利用者には a8 席が品質だけを払う席になる。
8. **時間の門**: a8 席はカーネルが速くなる一方で dispatch が増える（anima で 3,087 → 3,311 / step — ADR 0030）。
   1 submit ≤ 1 s の門は席ごとに測り直す。

## 7. ADR で決めるべき軸

### 軸 1 — 足す席の数

- a. anima と同じ並び（`f16+dit8` / `-a8` / `-a8-attn8` / `-a8-attn8-s16`）。
- b. 参照席 `f16+dit8` と実用席 `f16+dit8-a8-attn8-s16` の 2 つ。
- c. 実用席だけ（参照席を manifest に置かない）。

**推奨 b**。参照席は自機 A/B 門の床の相手として manifest に要る（`referencePartnerOf` は 0 個で throw — glossary の
「参照席」）ので c は成り立たない。中間の席は視認・sha 行・カードの費用を席の数だけ増やす。Wan の視認は 1 本約 15〜30 分
なので効く。ノブ単位の切り分けは、テストの manifest 上書き（anima の故障注入と同じ `withManifestOverride`）で足りる。

### 軸 2 — i8 にする範囲

- a. 307 本すべて（anima の i8 系列と同じ・最も単純）。
- b. 条件の経路と端（`condition_embedder` の 5 本・`patch_embedding`・`proj_out`）を f16 に残す混成。増えるのは約
  25.8 MB（推測）で、時間はほぼ不変（M = 1 / 512 と k = 64 の小さい linear）。census は f32 経路の linear が 7 本残る。

**推奨 a で始め、段 3 のノブ単位の測定と段 6 の視認で問題が出たら b**。anima の既定席は adaLN を含めて i8 + a8 で通って
いる。b を最初から採る根拠は上流の層別キャストの除外表（6 の 2）だけで、Wan での実測は無い。b は
`weight_dtype_overrides` の既存の口で書ける（1.2）。

### 軸 3 — `f16+dit8` の数値の門の範囲

- a. 決定 8 をそのまま: S = 192・14,040・32,760 で帯を独立に導く（CPU 約 7.6 時間・ADR 0118 段 8 の 27 ケース 27,271 s が目安）。
- b. S = 192 の帯 + sha 参照行。実寸の誤差の伸びは `f16` 席の門に任せる。
- c. 数値の門を持たない（anima の前例 — A/B の相手としてだけ）。

**推奨 b**。i8 に固有の誤り（scale の軸・束縛・逆量子化）は S に依らず S = 192 で掴める。S による誤差の伸び（K-75 の
縮約順）は `f16` 席と同じカーネルの性質で、席に固有ではない。ただし決定 8 の「帯は系列ごとに独立に導く」から外れる
ので、ADR にその理由を書く。保守側なら a から 81 フレームだけを外す（S = 14,040 まで — 約 1.5 時間）。

### 軸 4 — 実用席の門の置き場

- a. 自機 A/B 門を 33 フレームだけ。
- b. 33 と 81 フレームの両方。

**推奨 b**。リスク 1 のとおり attention a8 の誤差は N に依り、ADR 0030 は 1024px を直接測り直した。81 フレームの A/B は
1 回約 5 分（推測）。sha 行は既定レーンの 2 ステップ × 33 フレームだけで足り、81 フレームは 50 ステップの opt-in に置く
（ADR 0118 段 8 と同じ配置）。案 ② / ③ は採らない（4.3）。

### 軸 5 — 実装前の品質の測り方

- a. torch CPU のシム（ADR 0025 / 0030 の Q0 — `anima/measure_quant.py` を Wan へ移す）。
- b. GPU で席どうし（同じ i8 重み・ノブを 1 つずつ足す）の step 1 relRMS と層ごとの差を測る。
- c. 測らずに視認へ進む。

**推奨 b**。a は anima でカーネルを書く前の門だった。今はカーネルが E クラスで揃っていて、GPU の値が TS 参照と
atol = 0 で一致する。b はそのまま本物を測れて、1 回数分で済む（推測）。a は S = 14,040 で P を head ごとに実体化
するシムが要り、CPU で数時間級（推測）。

### 軸 6 — 既定席

- a. `f16` のまま（この ADR では席を足すだけ）。
- b. 視認 A/B が通れば実用席を既定にする（anima の形）。

**推奨: ADR は a で着地し、段 6 の視認の結果で b を別に裁定する**。ADR 0110 決定 8 は既定にするときだけ品質裁定を
要求する。Metal（M2）では速くならず品質だけを払う（3.1）ので、ブラウザ優先の方針の下で既定を変えるかは段 9 の結果も
見て決める。

### 軸 7 — 公開 API

- a. 席の選択（既存の `quant`）だけ。
- b. anima と同じく `linearCompute` などの明示指定も受ける。

**推奨 a**。テストのノブの切り分けは manifest の上書きで足りる。b は要求が出てから足せる（受理表は同じ 1 本）。

### 軸 8 — i8 系列の bias / norm の値

- a. 上流の f32 のまま（anima の i8 系列の前例 — `_fake_quant` の i8 分岐は `fake_quant_int8` だけ）。
- b. f16 系列と同じく f16 で表現できる値へ丸める（今の Wan の `round_to_f16` は全パラメータを丸める — `export_dit.py:273-298`）。

**推奨 a**（推測の範囲 — どちらでも計算と格納の形は同じで、値だけが違う）。b にすると「i8 の席は f16 の丸めも
含む」になり、NOTICE の文面が増える。決めて書くことが要点。

### 軸 9 — VAE

VAE は席の対象外（f16 のまま）を推奨。VAE の conv3d は i8 でも実行できる（ADR 0118 追記 2026-10-02）が、VAE の
attention は ADR 0030 決定 7 で対象外にした前例があり、VAE 段は 81 フレームの通しの 4%（315 s / 7,173 s）。
