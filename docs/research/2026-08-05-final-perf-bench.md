# 最終 perf ベンチ（1024×1024・turbo 8 step・方式×フェーズ）

> NOTE: 時点スナップショット。文中のパス・コマンド・コミットハッシュは記録当時のリポジトリ構成に基づく。

2026-08-05・ユーザー指示の予約実測（タスク #22）。perf 本線（ADR 0021〜0035）の締めの記録。

## 測定条件

- 1024×1024・turbo・**8 step**・cfg 1・seed 42・`examples/anima/main.ts`（1 構成 1 run）
- **ベンチ規約を全適用**: 毎 run 前にクールダウン（当日アイドル実測 45°C + 5°C = 50°C 以下
  へ待機・待機実績 0〜140s）・**GPU 時間計測 off**（素の時間 — ADR 0032）・run 前の
  SM クロックはアイドル 210MHz を確認
- VRAM は `nvidia-smi --query-gpu=timestamp,memory.used`（500ms ポーリング）をコンソール行の
  epoch タイムスタンプと突合してフェーズ窓へ帰属（プロセス外の常駐 33MiB 込み）
- 生ログ・JSON はセッション scratchpad（b22/）— 揮発。本表が恒久記録

## 読み取り

1. **運用形（i8+w8a8+attn a8+s16）が時間の最適点**: 44.7 → **19.2s（2.33×）**。内訳は
   w8a8 が DiT −49%・attention a8 がさらに −29%・s16 は時間微増分の回収 + transient 半減。
2. **VAE 段の VRAM がチェーン最大を決めている**（非 tiling 行は全て 5,72x MiB）。
   **tiling 行だけ VAE 段 1,633MiB（−4.1GB）** となり、チェーン最大が DiT 段の 3,906MiB へ
   移る — 「tiling はメモリの手」の最終形。代償は VAE 実行 1.5 → 3.4s（+1.9s・全体 +9%）。
3. i8（格納のみ）は f32 計算のままなので**時間は f16 と同じ**（4,209 vs 4,231ms/step）。
   効くのはロード（6.46→3.38s）と DiT 常駐（3,733→1,875MiB）。
4. f16 行の DiT 実行段 9,429MiB は f32 計算の S 中間（w8a8 系は quantize で縮む）による。
   s16 行は DiT 実行段でも最小（3,425MiB — S 半減の効き）。
5. 非 GPU は ADR 0032 適用後の姿（例: 運用形 DiT 12.0s = GPU 内訳実測 ~11.2s + α）。
   本表は「素の時間」— GPU 内訳が要る場合は `--gpu-timing` の別 run（規約）。

## 経緯メモ

perf 本線の始点（2026-08-03 GEMM 置換前）の 1024px turbo は **約 340s** だった
（i8・置換前 GPU 3.65×・examples/anima/README.md の当時実測から換算）。本日の運用形
19.2s で **約 18 倍**。フェーズ別の主な手: GEMM レジスタブロッキング（ADR 0022）→ 融合
attention（0023）→ conv2d igemm（0024）→ w8a8（0025）→ attention a8（0030）→ S f16 格納
（0031）→ 非直列化 + 計測 opt-in（0032）→ VAE tiling（0033）→ 軸 reduce（0035）。
