# attention の行ブロックの予算の実測（ADR 0124 の段 4b と層 1 の u32 A/B）

> 時点スナップショット（2026-10-11 10:04〜10:37 UTC）— 開発機（RTX 3080 Ti・Deno）1 台での実測。Chrome と 10 GB 級の機は測っていない。

## 条件

| 項目             | 値                                                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| 機               | RTX 3080 Ti（12,288 MiB）・Linux x86_64・環境キー `deno-nvidia-geforce-rtx-3080-ti`                              |
| runtime          | Deno 2.9.6（V8 15.0.245.2-rusty）                                                                                |
| checkout         | `fd8c0cb8`（段 4b の計測の `results.json` の記録・dirty なし）                                                   |
| device の上限    | `maxStorageBufferBindingSize` 2,147,483,644 B・`maxBufferSize` 1 TiB                                             |
| 幾何プロファイル | `default`（全ての予算で同じ）                                                                                    |
| 走行前           | GPU 全体の VRAM 263 MiB・70 ℃（段 4b の計測の直前に nvidia-smi で採った値）                                      |
| 対象             | Wan2.2 TI2V-5B の DiT の 1 forward（pipeline の 50 ステップではない）。入力の文脈は S = 192 の golden から借りる |

## 測り方

テストは全て `packages/models/tests/e2e_wan_ti2v_dit_test.ts` にある。3 本を別々のプロセスで順に回した。

| 走行                            | 起動の条件                                 | 形                         | 席             | 予算                             |
| ------------------------------- | ------------------------------------------ | -------------------------- | -------------- | -------------------------------- |
| 層 1 の u32 A/B（17 フレーム）  | 既定のレーン（`test:models:wan-ti2v`）     | 1280×704×17（S = 4,400）   | 参照席・実用席 | なし / 512 MiB / 256 MiB         |
| 層 1 の u32 A/B（121 フレーム） | opt-in `KARUME_WAN_TI2V_121F=1`            | 1280×704×121（S = 27,280） | 参照席・実用席 | なし / 512 MiB / 256 MiB         |
| 段 4b の計測                    | opt-in `KARUME_WAN_TI2V_ROW_BLOCK_PROBE=1` | 1280×704×121（S = 27,280） | 実用席         | なし / 1 GiB / 512 MiB / 256 MiB |

席の名前: 参照席 = `f16+dit8`（スコア S は f32）、実用席 = `f16+dit8-a8-attn8-s16`（a8 の attention・S は f16 で格納）。

- 予算ごとに Session を張り、同じ入力で 2 本回して畳む。1 本目はパイプラインの生成と裏付け前のチャンクを含む。2 本目は生成の
  各ステップに近い形で、backing は 2 本目の値（slot backing = 中間の領域 + 入力）。diag は 2 本の最大。
- ①QK の枚数は、直近の run の `attention_qk` の dispatch 本数から数えた（行窓 `:rwa` つき = 2 枚以上の attention・無し = 1 枚の
  attention）。30 層ぶんなので、30 で割ると 1 層の枚数になる。
- 段 4b の通常モード（計測なし — 製品の経路）は ABBA の順（予算なし → 1 GiB → 512 → 256 → 256 → 512 → 1 GiB → 予算なし）で回した。
  熱制限の偏りを前後で相殺するためである。VRAM の山は nvidia-smi の GPU 全体の値（`-lms` の標本 — 画面などの他の確保を含む・
  ADR 0121 の 11,361 MiB と同じ測り方）。fdinfo のこの process の山は、この走行では記録が空だった。
- 段 4b の計測モード（`gpuTiming` — timestamp-query）は別の device で、予算なし → 1 GiB → 512 → 256 の順に 1 回ずつ回した。段別の
  GPU 時間と合計は 2 本目（1 forward）の値。計測モードは 1 dispatch = 1 pass で encode するので、合計は通常モードの壁時計と同じ量では
  ない。submit と dispatch の本数は Session の 2 forward の累計。
- 生のログ（ANSI 色つき）と全体の記録の JSON は git 追跡外。段 4b の計測の結果は
  `outputs/verify/deno-nvidia-geforce-rtx-3080-ti/2026-10-11_wan-ti2v-dit/results.json` にもある（同じ日付の層 1 の走行の分は、後の走行が
  同じファイルを上書きしたので残っていない）。

再現（例・GPU を占有する）:

```sh
KARUME_WAN_TI2V_ROW_BLOCK_PROBE=1 deno test -A --v8-flags=--expose-gc packages/models/tests/e2e_wan_ti2v_dit_test.ts --filter 行ブロックの予算の計測
```

## 結果

### 層 1 の u32 A/B（ビット同一の門）

全ての組で、予算 512 MiB / 256 MiB の出力が予算なしと Uint32 で一致した。①QK の枚数は、runtime と独立に導いた期待（self / cross 別・
席の格納幅つき）と全て一致し、予算なしとも違った。

- 17 フレームの A/B 1 本（2 席）の所要は 1m26s。既定のレーンにこの時間が足される。

- 壁時計の 4 回は、ABBA の前半の 1 本目 / 2 本目、後半の 1 本目 / 2 本目の順。
- 同じ予算の 2 度目の backing は 1 度目と同じだった（テストの門）。diag − backing は全ての予算で約 4.69 GiB（予算に依らずほぼ一定・差は数 KB）で、backing −

  熱制限を含む。

## 読み

- **VRAM の山は backing の差とほぼ同じだけ下がった**。GPU 全体の山の差（−1,004 / −1,497 / −1,686 MiB）と backing の差（−1,001.5 /
  −1,494.8 / −1,684.6 MiB）の食い違いは 3 MiB 以内だった。
- **1 GiB → 512 MiB → 256 MiB で単調に下がった**。ただし 512 MiB から 256 MiB への上積みは backing −0.19 GiB・山 −189 MiB と小さく、
  計測モードの GPU 時間は +28%（36.30 → 46.57 s）になった。
- **設計の推測との比較**: 予算 512 MiB の backing の減り幅は推測の幅 0.95〜1.46 GiB の上端（Deno の点）と一致した（実測 −1.46 GiB）。山は
  9,811 MiB（2 回の平均）で、推測の幅 9,866〜10,389 MiB（ADR 0121 の DiT の段の山 11,361 MiB から推測の減り幅を引いた値）の下端より
  約 55 MiB 低い。基準が違う: 推測の基準は pipeline の DiT の段の山（11,361 MiB）で、この計測の予算なしの山は DiT だけを回した 11,308 MiB
  である。自分の基準からの差は −1,497 MiB で、backing の差と合う。
- **見積りの単調でない形は実寸では出なかった**。融合 attention の一時を数える見積り（[research 2026-10-11](2026-10-11-fused-attention-estimate-before-after.md)
  の Wan2.2 の表・実用席・121 フレーム）では 256 MiB（4,252,639,232 B）が 512 MiB（4,116,457,472 B）より大きかったが、実寸の backing は
  256 MiB の方が小さかった。その research の「実寸も同じ形になる見込み（推測）」は外れた。見積りと実寸の差は予算なし / 1 GiB / 256 MiB で
  約 0.37 GiB、512 MiB で約 0.68 GiB だった。差の内訳は調べていない。
- **速さの主な材料は計測モードの GPU 時間にした**。通常モードの壁時計は全ての走行で 93〜94 ℃・sw_thermal_slowdown を含み、同じ予算
  の 4 回でも揺れた（予算なしで 28.4〜40.5 s）。計測モードでは、`attention_qk` と `attention_stats` は予算に依らずほぼ同じで（7.09〜7.34 s・
  4.50〜4.82 s）、予算で動いたのは `attention_pv` だった（10.89 / 9.91 / 12.79 / 20.89 s）。
- **1 GiB と 512 MiB の GPU 時間の差は揺れの内と読む**（推測）。attention 以外の部分はカーネルが同じなのに 11.92〜14.27 s と 2.35 s
  揺れており、合計の −3.9% / −2.6% はこの幅より小さい。256 MiB の +24.9%（+9.3 s）はこの幅を超え、ほぼ全てが `attention_pv` の
  +10.0 s である。
- 壁時計も 256 MiB だけが 4 回とも遅かった（46.2〜49.4 s。他の予算は 42.9 s 以下）。1 GiB と 512 MiB は予算なしと揺れの幅が重なる。

## 未測

- **Chrome の点は測っていない**。ADR 0121 の Chrome（RTX 5070 Ti）の backing は予算なしで 4.80 GiB で、Deno の 5.97 GiB と 1.17 GiB
  違う。Chrome での減り幅（ADR 0124 の推測の下端 0.95 GiB・1 GiB でも 512 MiB と同じだけ減るという推測）は確かめていない。
- 10 GB 級の機（61 フレーム以上が入るか）は測っていない。
- pipeline の 50 ステップの通しは回していない（pipeline に予算の口が無い）。測ったのは DiT の 1 forward だけ。
