# umT5 と sbv2 の a8（int8 活性の整数内積）の計測 — 速度と品質

利用者の指示（2026-10-17）「umt5 の受理表を開き `i8-a8` を候補に品質と速度を測る・sbv2 の `i8-a8` を再計測する」の記録。
product コードは触っていない: umT5 は中間成果物の容器を runtime の Session で直接 f32 / a8 の 2 通りに張り、Wan は umT5 の出力を
`text_embeds` 資産に書いて一時 manifest で差し替えた（`textEncoder: "precomputed"` の経路）。script は追跡外
（`outputs/diag/a8-2026-10-18/scripts/diag_a8_{umt5,wan,sbv2}_test.ts` — 回すときは `packages/e2e/tests/` に置いて
`vp test --project models:<family> <file>`）、実物は `outputs/diag/a8-2026-10-18/`（追跡外）。

## 要約

- **umT5 の速度**: a8 は L（トークン数）≥ 118 で f32 の 2.1〜2.7 倍速い（4 回の計測で L 163 は 2.0〜2.1 倍・L 488 は 2.6〜2.7 倍・
  Wan の negative prompt〈126〉は 2.3〜2.5 倍）。L 28〜50 は 1.0〜2.7 倍で計測ごとに揺れ（§1.5 の遅い run の影響）、L 22 は同等、
  L 8 は 0.4〜0.5 倍（a8 の linear は 128 行のタイルの GEMM 1 形で、短い行数では床 65 ms が効く）。ただし Wan の text 段は 5.3 GiB の
  Session 構築（9 s）が支配的で、a8 で縮むのは 1 生成あたり 0.1〜0.2 s。
- **umT5 の品質（埋め込み）**: a8 の追加誤差は i8 の丸め自体の 4〜8 倍（量子化なし CPU f32 に対する相対フロベニウス 1.8e-1〜3.4e-1・
  i8 だけなら 2.3e-2〜7.7e-2）。行（トークン）ごとに見ると中央値のコサインは 0.99 で、2〜5 行だけがコサイン 0.05〜0.5 まで崩れる
  （ノルムは中央値並み — 小さい行の数値不安定ではない）。計画で合意した線「i8 の丸めと同じ桁（1e-1 未満）」を超える。
- **Wan の step 1 の潜在**: umT5 の a8 の効き（relRMS 4.5e-2〜6.6e-2）は、DiT 自身の a8 プリセットの効き（1.0e-1・既存の自機 A/B の上限
  2.2e-1）より小さい。a8 の 2 回はビット一致。
- **視認の対（seed 42〜45 × 2 プロンプト）**: §3（利用者の裁定待ち）。
- **sbv2**: a8 が効くのは front 2 本・voice 4 本の linear だけで、GPU 時間は voice の conv 族が支配（a8 の linear は voice の上位 5 キーに
  入らない）。壁時間 0.7〜0.9 s のうち GPU は 0.1〜0.2 s（残りはホスト側）で、a8 で速くも遅くもならない。表の `i8-a8` の voice が
  大きい行は §1.5 の遅い run（conv1d）が重なったもの（§4.1）。2026-08 の結論（ADR 0039 §5）を再確認。

## 5. 読み（裁定の材料 — 決定は backlog / ADR へ）

- umT5 の `i8-a8` を**プリセットとして足すか**: 速度は合意の線（L 488 で ×1.3 以上）を満たす（×2.7）が、品質は合意の線（追加誤差が
  i8 の丸めと同じ桁）を超える（4〜8 倍・数行が崩れる）。Wan の出口では DiT の a8 より小さい動きで、視認（§3）が正。
  利得が出るのは「Umt5Encoder を単体で張って何度も encode する使い方」で、Wan の 1 生成では text 段 10 s のうち 0.1〜0.2 s。
- 崩れる行を直す手（設計の候補・未検証）: ① 外れ値のある linear の入力だけ f32 に残す（層 / 位置の切り分けが要る）② export 側で
  活性の外れ値を重みへ移す（SmoothQuant 系の per-channel の等価変換 — exporter の新しい方式）③ 行の scale を外れ値に合わせず
  クリップする（数値契約の変更）。どれも計測の範囲外。
- sbv2 の `i8-a8`: 速度の意味は無い（再確認 — a8 の linear は voice の GPU 時間の上位に出ず、壁時間はホスト側が支配）。プリセットは
  「選択肢として置く」の位置づけのまま（ADR 0039 §5）。
- 環境の隣接問題（この計測の範囲外・報告のみ）: この機の GPU カーネルが数秒〜十数秒だけ 5〜45 倍遅くなる現象（§1.5）。クロックでは
  説明できず、表示を兼ねる GPU の時分割が疑わしい。timing を根拠にする計測はこの機では最小値を併記する。
