# anima cold ロードの DL タイムライン — 律速の特定（2026-09-02）

> **性格**: 時点スナップショット（2026-09-02・Linux / Deno 2.9.6・疑似 HF サーバ + 帯域制限・遅延注入・
> 各条件 1 回、②のみ再走で再現性 0.1%）。backlog「anima-web の cold ロード DL スロット改善（提案
> b+a）」の前提を実測で確かめる計測。台本は scratchpad（セッションで消える）— 方法と数値をここに残す。

## §1 方法

- 対象: `models/karume-anima`（anima-turbo-v1.1・既定 quant `f16+dit8-a8-attn8-s16`）: グラフ shard 4 本
  1.15 MiB / 重み 16 本 3,315.0 MiB（1 本 48.3〜246.2 MiB）/ extras 3 本 4.46 MiB（tokenizer ×2 + rope 表）。
- 疑似 HF サーバ（`examples/shared/local-dist-server.ts` を台本側で書き直し）: 帯域は**リンク 1 本の共有**
  （グローバルなトークンバケツ — 接続ごとに配ると「同時本数を増やすほど総帯域が増える」偽の効果が出る）、
  遅延はヘッダ返却前の固定待ち。サーバ + ループバックの天井は 1,400 MB/s。
- 取得: `AnimaPipeline.fromPretrained(source, { onProgress })` を永続キャッシュを冷やして実走。全進捗
  イベントに時刻を付けて相ごとに集計。同時本数の反実仮想は `prefetchAssets` を G 群に割って同時に呼ぶ
  （実効同時数 4×G・hub のコードは不変）。

## §3 所見

1. **律速は帯域そのもの**。②は床 +1.85 s（+2.7%）、③は床 +2.56 s（+1.5%）で、構造的な損失は合計 1〜3 秒。
   共有リンクが遊ぶ時間はゼロ。
2. **extras は直列ではない** — `fetchAssets` が 3 本同時に発行している（バイト予算 1.5 GiB ≫ 4.5 MiB）。
   「末尾」なのは重み 16 本の完了を待つ点だけで、重み prefetch と同じ回に載せても削減は ≤0.3%（②0.09 s・
   ③0.25 s）。起票の案 a の利得はこれで閉じる。
3. **グラフ相 → 重みの空白は 0.17〜0.20 s**（requestAdapter ≈0.10 + prepareModel 4 本 + admission ≈0.09）。
   起票の案 b（admission の前倒し）の利得上限は ≤0.3%。起票時（0.7.0）のグラフ相 2.4 GiB は shard 仕様
   v2/v3 で 1.15 MiB になっており、前提が消えている。
4. **同時本数 4 と末尾 drain は同一現象**。削減量は「4 × 1 接続の実効速度 ÷ リンク帯域」だけで決まり、
   1 本でリンクを埋められる回線では 0 に近い。1 本が埋め切れない回線（接続ごとの上限がある CDN で
   起きる形）では、埋め切れない比率がそのまま損失になる（接続上限 12.5 MB/s なら −15%）。今回の 3 条件は
   前者なので **CONCURRENCY = 4 は無料**。実回線（HF の CDN）に接続ごとの上限があるかは未測。
5. 末尾 drain の中身: 16 本 ÷ 4 枠 = 4 波で、最後の発行から 10.7 s は 3 → 2 → 1 本。shard を細かくすると
   埋まる（シミュレーション: 接続上限 12.5 / 4 本で 256 MiB 75.8 s → 128 MiB 73.8 s → 64 MiB 72.2 s —
   **推定**・実測ではない）。
6. 重み 1 バイト目までに直列 4 往復（revision API → karume.json → グラフ shard → 重み）: ③0.87 s・②0.38 s。
   pin 済み revision なら 1 往復減る。
7. 無制限条件の 183 MB/s は取得側の天井で、サーバ 1,400 MB/s・SHA-256 4 本並行 1,641 MB/s との差は
   永続キャッシュ書込み（Deno の Cache API）にある。1.5 Gbps 超の回線では hub 自身が律速に回る計算
   （ブラウザの CacheStorage は別実装で未測）。

## §4 判定

- 起票「anima-web DL スロット改善（b+a）」は**前提が消滅・利得 ≤0.3% で kill**（復活条件: グラフ相が再び
  GB 級になる配布形 = 無い）。c 案（コンポーネント単位の門）も同時に閉じる。
- 残る唯一のレバーは**同時本数 vs 接続ごとの上限**で、実回線の測定が要る（HF の CDN から 4 本 / 8 本で同じ
  資産を落として比べる）。接続上限が確認されたら同時本数の引き上げ（定数 1 つ）か、末尾向けの shard 細分化を
  再起票する。
