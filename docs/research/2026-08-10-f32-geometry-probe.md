# f32/f16 GEMM 骨格のタイル幾何プローブと横展開実測

> NOTE: 時点スナップショット（2026-08-10・RTX 3080 Ti / Linux / Vulkan (wgpu) /
> Deno 2.9.4・main `25ed0e1` 起点）。比（ABBA 対計測）のみが有効で、絶対秒を別日の測定と
> 比較しないこと。計測規約は
> [2026-08-10-kernel-variant-sweep.md](2026-08-10-kernel-variant-sweep.md) §5 に同じ
> （GPU 45℃ 以下まで冷却待ち・回文順・代表値 min）。

## 問い

[ADR 0022](../decisions/0022-gemm-register-blocking.md) 決定 3 は「f32/f16 の K 縮約順は
数値契約」とし、[変種スイープ](2026-08-10-kernel-variant-sweep.md) §7-1 は「タイル幾何は
担当割りだけを決めるので f32 でもビット同一のはず — ただし backend の fma 縮約判断の留保が
あり PNG 門で確認が先」と申し送った。本プローブはこの読みを実測で検定した。

## 方法

gemm.ts の骨格に幾何変種を注入し（出力タイル 64×64・K タイル 16・共有 8KB・dispatch は
全変種で不変 — スレッドへの担当割りだけが変わる）、各変種で
①ビット門 = PNG sha256 門 4 本（`e2e_anima_test`）+ WAV 門（`e2e_sbv2_wav_test`）
②性能 = f16-1024 / w8a8-s16-1024 の E2E を ABBA 回文で対計測した。

- **v0**: 幾何パラメタ化のみ（r4×4 / wg16×16 = 現行と同一幾何）。副産物として全 op の
  accumulator が `acc{行}_{列quad}` の静的展開になる — 幾何と展開の交絡を分離する対照群
- **v1**: + r8×8 / wg8×8（64 スレッド）
- **v2**: + r8×4 / wg16×8（128 スレッド）

## 結果

### ビット同一性 — 全変種・全門で成立

v0 / v1 / v2 ×（PNG 門 4 本 + WAV 門）で **sha256 不一致 0 件**（各門 3 実走）。
1 スレッドの出力数（16 → 64 → 32）も workgroup 形（256 / 64 / 128 スレッド）も変えて
1 ビットも動かず、**fma 縮約の兆候なし**。積和の字面は `acc = acc + sa[…] * bv` のまま。
決定 3 の留保（fma で最終ビットが動きうる）は、少なくともこの環境では実測で外れた。

### 性能 — 主は静的展開、従が幾何

| 変種                  | f16-1024 (min) | 比 vs main | w8a8-s16-1024 | 比         |
| --------------------- | -------------- | ---------- | ------------- | ---------- |
| main                  | 30.5s          | —          | 11.8s         | —          |
| v0（展開のみ）        | 26.5s          | ×1.151     | 10.8s         | ×1.093     |
| v1（r8×8/wg8×8）      | 24.9s          | ×1.225     | 10.9s         | ×1.083     |
| **v2（r8×4/wg16×8）** | **23.7s**      | **×1.287** | **10.7s**     | **×1.103** |

- **静的 acc 展開の全 op 横展開だけで ×1.151**（v0 — 幾何不変の対照群が交絡を分離）。
  ADR 0022 追記の予言（動的添字はローカルメモリ退避で律速）が f32 側でも成立し、C3 で
  linear だけに入れた展開を matmul / bmm / attention QK・PV / conv2d が受け取った形。
- 幾何の上積みは ×1.064〜1.118。**r8×4/wg16×8（128 スレッド）が r8×8/wg8×8（64 スレッド）に
  勝つ** — i8a8 掃引の「レジスタブロック第一」は同じだが、f32/f16 では 64 スレッド
  （wg あたり 2 warp）まで落とすと占有率が足りない。
- w8a8 も ×1.10 動いた = VAE conv2d（GPU の 19.1% — 統計波）と attention f32 経路が
  gemm.ts 骨格を共有するため。**「VAE conv2d への横展開」はこの時点で成立**。
- 冷却規約なしの対計測は 29.4〜40.4s に散り（±15%）判別不能だった。規約下の再現性は
  ±0.4%（v2 は 2 回とも 23.7s）。E2E でも規約が必須。

## 本実装（幾何パラメタ化 + 既定 r8×4/wg16×8）の検収 A/B

プローブ後、恒久実装（`src/kernels/gemm-geometry.ts` + gemm.ts の幾何パラメタ化・
キーへの幾何判別子・全 op 静的展開）を書き下ろし、検収の回文（main → 実装 → 実装 → main・
全走で PNG 門 4 本緑）で確定:

| 系列          | main         | 実装         | 比（min/min） |
| ------------- | ------------ | ------------ | ------------- |
| f16-1024      | 30.5 / 30.4s | 23.7 / 23.7s | **×1.28**     |
| w8a8-s16-1024 | 11.8 / 11.7s | 10.7 / 10.7s | **×1.09**     |

`deno task verify` 742 passed / 0 failed（PNG 門 4 本 + WAV 門込み）。

## タイル軸掃引（tileM/N=128・同日後刻）

タイル辺を幾何へ吸収する純リファクタ（`b9e579f` — fixture バイト同一で機械検証）の上で、
既定 1 行差し替えの 2 変種を同一規約の ABBA 回文
（base → M128N64 → M128N128 → M128N128 → M128N64 → base）で対計測した。

| 変種                      | f16-1024        | 比 vs base | w8a8-s16-1024 | 比     |
| ------------------------- | --------------- | ---------- | ------------- | ------ |
| base（64×64 r8×4 wg16×8） | 23.7 / 23.7     | —          | 10.8 / 10.7   | —      |
| M128N64 r8×8 wg8×16       | 22.7 / 22.8     | ×1.044     | 11.2 / 10.9   | ×0.982 |
| **M128N128 r8×8 wg16×16** | **20.2 / 20.2** | **×1.173** | 10.9 / 10.6   | ×1.009 |

- ビット門: 回文全 6 走の PNG 門 4 本 + 変種別の WAV 門で sha256 不一致 0。
- **M128N128 を新既定として採用**（`d0afc22` — fixture 再エミット・着地後 verify 742/0 =
  門再実測込み）。f16-1024 は朝の 30.5s から累計 **×1.51**。
- 最良タイル形は i8a8（linear/QK は M128N64）と**一致しない** — 幾何の答えは経路ごとの
  実測でしか出ない。w8a8 が中立なのは DiT linear が i8a8 経路でこの幾何を踏まないため
  （動くのは VAE conv2d と attention の f32 部分のみ）。
- M128N128 の共有メモリは f32 で 16,384 B・threads 256 — どちらも WebGPU 既定上限
  **ちょうど**（f16 計算変種は共有半分）。conv2d は m タイル 64/32 のヒューリスティックを
  維持し n タイルだけ 128 に追随（キーは `igemm{64|32}x128`）。

## Apple M2 での追試（同日・ユーザー実測）

Apple M2 / macOS / Deno 2.9.4・各 1 走（冷却規約なし — 比は参考値。sha は温度に依らない）。
main `53ba66f`（M128N128）vs `881d41d`（旧既定 64×64 r8×4 wg16×8・v0.2.2）:

| M2・単走      | main（M128N128） | 881d41d（64×64） | 比     |
| ------------- | ---------------- | ---------------- | ------ |
| f16-1024      | 461.2s           | 489.2s           | ×1.061 |
| w8a8-s16-1024 | 397.3s           | 414.6s           | ×1.044 |

- **spill 懸念（acc 64 本/スレッド）は M2 で否定** — 退行なし、むしろ改善。環境別の既定
  分岐は不要と確定（ユーザー裁定: NVIDIA 第一・分岐は明確な退行の実証が出た時だけ検討）。
- **幾何 2 種の出力 sha256 が全 4 系列で互いに完全一致**（w8a8-1024 `703e1eb5…`・f16-1024
  `771dabd2…`・512 系 `7f1b459d…`）— 「幾何は担当割りだけを変えるのでビット同一」の実測
  命題に **Metal のデータ点が加わった**（Vulkan / Metal の 2 環境で成立）。さらに quant 512 と
  fromPretrained-512 の独立 2 セッションが同一 sha = デバイス内決定性の実証。
- 参照 sha（RTX/Vulkan 焼き）とは全系列不一致・絵は正常 = クロスデバイスの数値差
  （想定内 — 規約は [limitations.md](../limitations.md) に明文化）。
- キャンペーン累計（M2 w8a8-1024）: 625.2s（08-08 記録）→ 397.3s = **×1.57 — M2 にも
  移転している**。SBV2 は M2 で f16 4.6s < w8a8 5.0s（Anima は逆 — 量子化の利得は
  GEMM 規模依存で、小形状では quantize のオーバーヘッドが勝る）。
- NOTE: 旧セッション記録の「M2 基準線 463.4s」は出所コミット不明のため破棄（本表が正）。

## 帰結・次への申し送り

1. **f32/f16 の幾何変更はビット同一「という実測」であって理論保証ではない**（i8a8 の
   整数縮約と違う）。幾何の既定変更は門の再実測とセット。**実行時に幾何が変わる形
   （オートチューン）は f32/f16 では取らない**。実測データ点は Vulkan（RTX 3080 Ti）と
   Metal（Apple M2）の 2 環境。
2. ~~未計測の本命が残る: **tileM/N=128 軸**~~ → 実測済み（§タイル軸掃引 — M128N128 を
   既定として着地）。
3. ~~Metal（Apple M2）は未実測~~ → 追試済み（§Apple M2 — 退行なし・ビット同一成立）。
   AMD / Intel は未実測のまま。別バックエンドの検証は**自己 A/B**（同一入力・幾何 2 種の
   出力 sha が互いに一致するか + 新旧の壁時計比）で行える — 参照 sha との一致は求めない。
